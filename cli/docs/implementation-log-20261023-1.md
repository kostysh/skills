## Изменения

CLI в `cli/`: выбор установки/обновления, чекбоксы, пресеты и custom-путь,
бездиалоговые команды. Config v1 хранит установки по абсолютному пути, версии
и contentHash. Блокировка защищает общий конфиг, временный каталог/backup и
атомарная запись обеспечивают откат обычных ошибок. После аварии резервная
копия и lock сохраняются для ручного восстановления, как описано в README.

Упаковщик читает собранные SKILL.md, сохраняет рабочие файлы и шаблоны,
исключает служебные документы. Каталог содержит историю версий/отпечатков.
Проверки ссылок относятся к рабочим инструкциям; исторические docs-ссылки
не возвращают документацию в архивы. npm содержит только bundle CLI,
source map, собственный README и метаданные, без скилов.

Отдельные workflows проверяют CLI на Linux/macOS/Windows и готовят выпуск
CLI через npm OIDC и архивов через GitHub Releases. Публикация из PR не запускается.

### Раунд 2 и проверка общей причины F1

Первое исправление F1 проверяло только одну форму пути и исключало всю
строку со словами о примере. Reviewer воспроизвёл пропуски `./scripts/...`,
`../assets/...` из references и обязательного ресурса перед «for example».
Это повтор исходного класса дефекта; прежняя авторская проверка покрывала
слишком узкие примеры и не закрывала прямой охват finding.

Перед следующим handoff проверен общий путь: текст инструкции → извлечение
литерального пути → нормализация → отбор рабочих файлов → архив → readback.
Теперь inline-команды и shell blocks используют один разбор; bare/./ пути
считаются от корня скила, ../ — от текущего документа. Проверка примера
применяется к началу текущей фразы до code span; слова о примере после
обязательного пути его не скрывают. Shell-команды проверяются и в примерах.
Произвольный код и вычисляемые пути упаковщик не исполняет и не анализирует.

При проверке всех четырёх рабочих папок автор дополнительно обнаружил:
фильтр служебных имён считал саму папку `agents` служебным `AGENTS` и удалял
metadata. Фильтр исправлен на имя файла. Новый positive test распаковывает
рабочий `agents/missing.md`, при этом `agents/README.md` исключён.
Это исправление принятого требования сохранять `agents/`, а не установка
дополнительных программ или новая возможность CLI.

Регрессионный test на исходниках r2 падает, как ожидается:

## Передача через PR и CI

После завершения аудитов оператор разрешил коммит изменений CLI, push
рабочей ветки, создание PR в `master` и проверку CI на Linux/macOS/Windows.
Слияние и публикация npm в эту команду не входят; оператор явно отложил npm.
Публикационные workflows запускаются только тегами `cli-v*` / `skills-*`;
при передаче отправляется только `refs/heads/codex/skills-cli`.

На момент этой записи код соответствует проверенному snapshot r3;
изменены только отчётные записи. Результаты внешнего CI следует читать
в созданном PR для его актуального head SHA. До успешного завершения jobs
три ОС не считаются проверенными. Публичный выпуск по-прежнему не подтверждён.

При проверке индекса обнаружена лишняя пустая строка в конце CLI README;
она удалена до push. Это форматное изменение: инструкции и исполнимый
пример восстановления не изменились, новое поведенческое ревью не требуется.

### CI: окончания строк Windows

Первый коммит PR #31 — `6ae886651550752d704212599c88ba3281760a9b`.
Linux/macOS и workspace tests прошли. Windows остановился на
`format:check`: checkout с `core.autocrlf=true` записал CRLF вместо
ожидаемых Biome LF. Witness: push run `39983180641`, job `120515483214`;
то же произошло в pull_request run `39983293049`.

Исправление ограничено `.gitattributes`: `cli/** text=auto eol=lf`.
Оно фиксирует LF для текстов CLI при checkout, сохраняет автоопределение
бинарных файлов и не меняет скилы или правила для остальных каталогов.
Код CLI, проверка форматирования и порог проверок не меняются.
Отдельный checkout с `core.autocrlf=true` воспроизвёл исходный отказ;
после применения атрибута проверяются LF и успешный `format:check`.
Исходный failure log: `/tmp/kskills-pr31-windows-first-failure.log`;
контрольный checkout: `/tmp/kskills-pr31-eol-p9ilk82m`.
Нативный CI трёх ОС и независимое delta-review ожидают повторной проверки.

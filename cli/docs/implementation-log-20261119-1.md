# Обновление CLI при снятии скила с поставки

19 ноября 2026 года оператор поручил сохранять установленные копии снятых скилов, предупреждать об их отсутствии в каталоге и возвращать код 0 при успешном обновлении. Проверяемый пример — `pencil-dev` 0.2.2. [Решение по поставке Pencil](../../docs/reviews/gpt-6-2/20/retirement.md)

Публичный CLI 0.1.3 вернул код 1 в отдельном профиле с настоящим архивом Pencil из выпуска `skills-20261107-2`. Четыре файла и запись установки сохранились. Причина — отсутствующий в актуальном каталоге скил попадал в общий список ошибок.

В 0.1.4 установщик пропускает такие записи и возвращает их как предупреждения. CLI выводит предупреждение с путём локальной копии в stderr и продолжает обновлять доступные скилы. Код 1 сохраняется для ошибок. Когда результат состоит только из предупреждений, stdout пуст. [Код установки](../src/installer.ts) · [Вывод и коды завершения](../src/cli.ts) · [Руководство CLI](../README.md)

Процессный тест воспроизвёл ошибку на прежнем коде. На новом коде он подтвердил предупреждение одновременно с обновлением, повтор без обновлений, сохранение локальной правки Pencil и код 1 при конфликте другого скила. Прошли все 128 тестов рабочей области, проверка формата, линт, проверка типов и установка из npm-архива в чистом проекте. [Процессный тест](../test/process.test.ts)

Установленный локально пакет 0.1.4 прочитал действующий каталог GitHub `skills-20261119`. Команда `update` вернула 0 и в профиле с одним Pencil, и в профиле, где одновременно обновился `frontend-design` с 0.2.4 до 0.2.6. В обоих профилях все четыре файла Pencil и запись в `setup.json` совпали с исходными. При локальной правке активного скила команда вернула код 1 и сохранила обе копии.

# Проверка supplied формы

Обработчик ошибки сбрасывает пользовательский ввод, что противоречит требованию сохранить значения после неудачного сохранения.

Статус: findings.

Основа: неизменный фрагмент из decision-inputs/review.md, строки ниже отсчитаны от `const form`; требование оператора — ошибка видна, значения сохраняются, focus доступен. Использован supplied локальный Web Interface Guidelines с указанной в нём upstream revision 4e799d45c17aec1498c269287a83b9dba22b966b. Live upstream не запрашивался. Browser-наблюдений, viewport и CSS нет.

- Фрагмент:2 — `onError: () => form.reset()` возвращает форму к defaultValues вместо сохранения изменённого name. При исходном Alpha и введённом Changed ошибочный PATCH ведёт к потере Changed. Исправление должно исключить сброс ввода на ошибке; изменения не выполнялись.

В строке 7 предусмотрен условный вывод ошибки с `role="alert"`; это подтверждает кодовый путь вывода, но не реальную видимость, текст конкретной ошибки или объявление assistive technology. Нативные input/button и оборачивающий label дают корректную семантическую основу; отсутствие явно написанного focus CSS не доказывает отсутствие browser focus outline.

Не оценены фактическая видимость focus, Tab/Enter после ошибки и pending, mobile overflow/zoom/touch targets, а также видимость alert в rendered интерфейсе. Эти пропуски не являются найденными дефектами. Для заключения о keyboard/mobile нужны наблюдения соответствующих состояний; текущий запрос запрещает новый запуск браузера, поэтому они не собирались. Исправление передаётся владельцу формы; runtime-проверка — владельцу browser evidence. Широкого заключения о доступности нет.

# Независимый ограниченный переаудит

В пределах supplied условий прежний путь потери ввода устранён, а повторное сохранение сохраняет данные после reload.

Статус: no-material-findings — только для исправления сброса при ошибке и соседнего сценария повторного сохранения в данном упражнении.

База переаудита: исходный finding — Changed сбрасывается на Alpha после ошибочного PATCH; новый supplied snapshot определяется удалением единственного `onError: form.reset()`. Commit/hash не предоставлены, поэтому это идентичность фрагмента упражнения, а не проверенный production revision. Статическое сравнение подтверждает только удаление строки и само по себе поведенческий finding не закрывает.

Достаточная граница: точный delta; исходная ошибка PATCH с сохранением Changed и видимым alert; исправление текста на Again, успешная повторная отправка и Again после reload. Последняя проверка покрывает соседний путь восстановления и сохранения. По условиям упражнения эти наблюдения предоставлены оператором как синтетические; это не мой браузерный запуск и не независимо собранное runtime-доказательство.

В рамках этих условий исходный finding закрывается. Focus и responsive разметка не менялись, их предыдущие проверки по supplied условиям сохранены: они исключены из повторного аудита. Повторять все экраны и состояния оснований нет. Расширение понадобилось бы при изменении focus/layout, других обработчиков или новой информации о более широком delta. Общую доступность, реальную production-работоспособность или все состояния формы это заключение не подтверждает. Код не менялся, браузер не запускался.

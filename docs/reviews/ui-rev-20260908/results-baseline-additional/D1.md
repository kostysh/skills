Основание: additional.md задаёт объём, fixture-base/README.md — принятый flow и контракт, src/main.jsx — существующую реализацию и владельцев состояний, src/style.css — токены и оформление. При расхождении поведения README имеет приоритет над кодом. package.json подтверждает существующий React-стек; новые инструменты и пакеты не нужны. Это временный локальный продукт; дополнительных ролей, уведомлений, истории нет.

Визуальная идея: спокойная операционная поверхность, где выравнивание строк и контраст текста помогают найти заявку и отредактировать её. Классификация product/app, system-constrained; основной visual engine data-led. Сохранить system-ui, фон #f6f5ef, текст #172c35, акцент #125d60, линии #bec9c7 и шаг --space:1rem. Оставить header REQUEST DESK, main max-width:62rem, h1 2rem/500. Иллюстрации, новый шрифт, декоративные карточки и анимация не нужны.

Список: порядок header → Requests → Search → New request/Create → таблица Name/Actions → Page/total и Previous/Next. Таблица остаётся центральной рабочей поверхностью. Ссылка имени ведёт в detail; Delete остаётся самостоятельной кнопкой. Использовать существующие разделители строк и .8rem ячейки; кнопки не превращать в скрытые действия при hover. Форму создания визуально отделять существующим вертикальным отступом 1.5rem, таблицу — 2rem. Главная задача первой области — поиск нужной строки; создавать второй крупный заголовок или баннер не требуется.

Detail: Request {id} → Name/input и Save → сообщение результата → Back to requests. Сохранить один столбец информации и существующее выравнивание формы. Ошибка располагается рядом с формой, успех — в той же зоне; текст не должен сдвигать фокус или скрывать введённое значение. Сохранить роль alert для ошибок и status для успешного сохранения. Цвет ошибки #a02020 дополняет текст, не заменяет его.

Предложение No requests — визуальная utility-copy для уже существующего пустого результата, без новой продуктовой возможности. Состояния DELETE сверх существующего flow эта стратегия не расширяет.

В исходнике Editor сейчас onError вызывает form.reset(), что противоречит README. onSuccess сбрасывает форму, но не обновляет/инвалидирует item/list cache при staleTime 600000. Разработчик должен обеспечить контракт сохранения и повторной навигации; исходный код не служит разрешением сохранить эти расхождения. Это явные задачи реализации в существующих владельцах, не новая архитектура.

Адаптация: выше 600px оставить main padding 2rem и горизонтальные формы; до 600px — 1rem и вертикальные формы с растянутыми input, как в CSS. Сохранить две колонки таблицы; перенос имени и текста Delete предотвращает выход за viewport. Проверить длинное имя и увеличенный текст: действия должны оставаться видимыми без наложения. Не заменять detail модальным окном или drawer. Сохранить нативные ссылки, labels, Tab-порядок, focus-visible outline 3px #ac5d00/offset 3px. Дополнительная анимация не вводится, поэтому отдельный эффект для reduced-motion не нужен.

Проверки после реализации: desktop 1280×800 и mobile 375×812; обычный, пустой, loading/error список, поиск с переходом страниц; переход по имени в /items/:id; первая ошибка PATCH с сохранением текста, коррекция и retry; сохранённое значение после Back, detail return и reload без перезапуска сервера; длинное имя, 200% zoom, Tab/Shift+Tab и активация всех действий с видимым фокусом. Проверить отсутствие переполнения, читаемость ошибки и успеха, консоль и ответы запросов. Текущее чтение исходников подтверждает только основание стратегии; браузер, визуальный макет и runtime не проверены и не доставлены. Код и навыки не менялись.

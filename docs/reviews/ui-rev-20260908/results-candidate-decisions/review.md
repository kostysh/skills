Первый запрос: предоставленный обработчик ошибки сбрасывает ввод; пригодность keyboard и mobile по этим материалам подтвердить нельзя.

Статус: findings.

Основание: неизменный фрагмент из decision-inputs/review.md, от const form до alert, и требование сохранить ввод, показать ошибку и обеспечить доступный focus. Номера ниже считаются от строки const form как 1. Только статический осмотр; runtime, viewport, CSS и браузерные наблюдения не предоставлены. Использована supplied локальная Web Interface Guidelines, baseline revision 4e799d45c17aec1498c269287a83b9dba22b966b; live overlay не загружался согласно ограничению на предоставленные материалы.

- Фрагмент:2 — onError вызывает form.reset() без новых значений, возвращая форму к defaultValues вместо сохранения неудачно отправленного ввода. Пользователь теряет изменения при ошибке PATCH. Это нарушает явное требование. Подсказка владельцу реализации: убрать сброс из error-пути; исправления не выполнены.

По коду поле обёрнуто label, input и button имеют нативную семантику, а при save.error предусмотрен role="alert" с error.message. Это подтверждает структуру вывода ошибки, но не её фактическую видимость, содержательность сообщения, объявление вспомогательными технологиями или видимость focus. Отсутствие CSS в отрывке не означает отсутствие focus-индикатора.

Границы: keyboard-переходы, submit с клавиатуры, восстановление focus после pending/error, мобильный viewport, zoom, overflow и touch targets не проверены. Они не объявляются дефектами из-за отсутствия наблюдений. Для их оценки нужны текущие rendered состояния и клавиатурная проверка у владельца browser evidence. Работа остаётся read-only, новый браузер не запускался. Общая пригодность формы и соответствие WCAG не установлены.

Второй независимый запрос: исходный дефект закрывается в пределах предоставленных синтетических условий; вывод не является подтверждением реального браузерного исполнения.

Статус: no-material-findings для ограниченного переаудита исправления потери ввода и соседнего повторного сохранения в упражнении.

Основание: предыдущий фрагмент с onError: form.reset(), стабильный описанный кандидат, отличающийся только удалением этого onError, и статическое сравнение этой строки. Идентификатор реального commit/build не предоставлен; цель зафиксирована как этот конкретный supplied delta. Baseline Guidelines тот же. Наблюдения оператора являются синтетическими входными условиями, не моими browser observations.

Достаточная граница:

1. Удалённый error-handler и исходный сбой: ошибочный PATCH после ввода Changed. По supplied наблюдению Changed остаётся в input, alert видим; прежний сброс на Alpha устранён.
2. Соседнее восстановление: последующая правка до Again, успешная отправка и сохранение Again после reload. По supplied наблюдению этот путь работает; сохранность после reload входит в проверку, одного alert было бы недостаточно.
3. Blast radius ограничен автоматическим reset формы на ошибке и последующей правкой/submit. Focus и responsive-разметка не менялись; предоставленное условие сохраняет их прежние проверки, поэтому они исключены из повторного исполнения. Исправление согласованного поведения само по себе не требует расширять аудит на весь UI.

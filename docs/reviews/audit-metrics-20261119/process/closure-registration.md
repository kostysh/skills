# Дополнительная проверка оформления двух полученных решений

В первичной серии обе версии передали два готовых документа одним пакетом. Кандидат добавил запись о передаче. В закрытом основном задании координатор ещё не получил решений. Эта диагностическая пара проверяет следующий шаг, на котором в реальном T02 появились устаревшие хеши. Она не входит в исходные четыре пары.

Оба исполнителя на gpt-6.2-sol / medium получают одинаковые документы T02 без прежних решений, ссылку на один адрес аудита, ответ независимого аудитора с отдельными решениями и UTC-событиями, пустую строку журнала сопровождения. Воспроизведённая квитанция локальная учебная. Она содержит проверяемые SHA этих копий. Один исполнитель получает прежний комплект методики, второй — кандидат. Рубрика, ключ и предыдущие результаты исполнителям скрыты.

Счётчик до оценки фиксирует число изменённых файлов сопровождения, число сохранённых передач, число изменивших SHA ранее принятых документов, число отдельно введённых копий решений или метрик и сколько ссылок ведут к общей записи. Новая запись метрик входит в затраты. Успех требует двух прослеживаемых решений именно о текущих байтах либо корректного запроса повторной приёмки, точных полномочий, учёта известного времени без выдуманного активного времени. Доставку владельцу разрешено совместить с журналом, если сведения остаются доступны. Один независимый проверяющий сверяет фактический результат с выдачей. Штатной экономией считаем только устранённое действие при достаточной прослеживаемости. Если обе редакции справляются одинаково, фиксируем это. Первичные результаты и знаменатели сохраняются.

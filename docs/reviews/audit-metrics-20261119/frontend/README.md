# Аудит frontend-design на рабочих формах

[Независимая приёмка](independent-audit.md) дала PASS пользовательскому результату P по двум заданиям. [Результаты](assessment.md) и [машинная сводка](summary.md) содержат сравнения и доказательства. [Условия и правило решения](protocol.md), [рубрика](rubric.md) и [назначения](registration.json) фиксируют варианты до выдачи. В [калибровке](calibration) видны исходные дефекты. [Проверка стенда](prelaunch.json) воспроизводит исправление связи с Chromium до первого исполнителя. [Проверка видимых системных файлов](scope-audit.json) привязана к этому снимку. [Допуск](release-to-run.json) и [события UTC](events.jsonl) отделяют подготовку и исследовательские выдачи от приёмки результата.

## Как проверить одну работу

1. В registration.json найти назначенную пару и ID её сторон. В runs/ID/dispatch.json сверить хеши проекта, доступный каталог и фактическую модель, запрошенную CLI. В runs/ID/events.jsonl содержатся байты первичного протокола; SHA-256 находится в result.json.
2. Открыть runs/ID/browser.jsonl. Это действия исполнителя в настоящем Chromium. Поля loaded и disk содержат хеш открытых и актуальных файлов. Последнюю версию показывает observed/observer.json. Состояния initial и error получены отдельным прогоном внешнего наблюдателя. Первая кликовая проверка самого стенда хранится отдельно в browser-smoke.jsonl.
3. Сопоставить site, change.diff и observed с исходным заданием. По score-key.json установить анонимный код после подписания оценок. В assessments/этап/роль/signed.json находятся оценка и основание. В inputs каждой оценки хранятся хеши отдельных выданных файлов. Постоянные ссылки с номерами строк собраны в [карте источников](evidence-index.md). Для работ подвыборки сравнить две исходные оценки и при наличии третью.
4. Из этого каталога запустить проверку байтов и сопоставления. Она не обращается к модели.

```sh
python3 -B tooling/replay.py
node ../../../../scripts/audit-metrics.mjs metrics-gpt-6.2-sol.json
```

Параметр `--render` у replay.py повторно запускает проверку каждой возвращённой страницы. Используются Linux, Node, Python 3, Chrome и Playwright Core. В этом опыте зарегистрированы Chromium 158.0.8127.36 и Playwright Core 1.59.1. Для другой установки задайте PLAYWRIGHT_CORE (путь к установленному модулю) и CHROME_PATH (исполняемый Chrome). Проверка проходит в отдельном профиле и на локальном HTTP-сервере. На другом браузере или с другими системными шрифтами координаты элементов могут отличаться. Сохранённые изначальные числа остаются доступными для проверки.

Для исследования новой выборки нужны отдельная регистрация и права на новые сессии Codex. Сохранённые формы можно открывать и проверять без новых модельных запусков.

# Живой пилот frontend-design

Дата предварительной фиксации, байтовые хеши материалов, назначение каждой стороны и фиксированная подвыборка записываются в registration.json до первой выдачи. Полный пакет и A — один точный устанавливаемый frontend-design 0.2.6 из архивного комплекта 19/retirement. Все семь файлов сверяются с исходным снимком. Ни один файл прежних испытаний не входит в выдачу исполнителю.

Первичные задания — рабочие страницы North Quay. В обычном случае вторичная и отправляющая кнопки одинаково оформлены. Во втором исходный CSS ещё и скрывает визуальный индикатор отправки после пустого ввода. Открытая часть — буквальный запрос в inputs и файлы конкретного проекта. Отложенное задание — неиспользованный ранее здесь проект Hawthorn Works с резервированием запчастей, другим контентом, разметкой, состояниями, порядком кнопок и способом потери визуального индикатора. До выбора C отложенное задание видит только автор стенда при калибровке и регистрации.

Для поставки сравниваем конечное качество P. Для точечного правила отдельно считаем проверку K и сочетание P+K (I), как определено в rubric.md. В корне и активном справочнике в B удалены все три указания на проверку клавиатуры/фокуса. Сканируются весь устанавливаемый пакет и фактический вход CLI. Общее требование проверять релевантные состояния, слова о доступности и работающий код с CSS-селекторами остаются в обеих сторонах. Это контекст задачи; сам по себе он не предписывает навигацию клавиатурой в браузере. Во входах нет названия скила или указания его загрузить. Сравнение измеряет результат на этих формах.

Каждая первичная сторона имеет собственную свежую сессию gpt-6.2-sol/medium, временный каталог, окно Chromium и журнал. Пакет устанавливается в проектный .agents/skills и виден штатной системе скилов. Контроль получает ту же форму и инструменты. Домашние пакеты специально отключаются через skills.config, домашние MCP, память, плагины и удалённый поиск выключены. Нативный файловый профиль исполнителя разрешает его проект и системные программы, запрещает исходники, личные файлы, ключ, рубрику, другие запуски и предыдущие исследования. Браузер использует только собственную временную сессию и один origin. Исполнитель может работать с исходниками и управлять браузером одинаковыми командами. Выдача проверяется и через модель-видимый вход, и через реальные попытки чтения. Фактическая загрузка SKILL.md и обязательного справочника проверяется по журналу исполнения. При отсутствующем доказательстве сравнение активного пакета имеет недостаточные данные; сохраняется наблюдение о доступности. Выбор из каталога нескольких скилов не проверяется.

Критерии и первичные результаты двух оценщиков разделены. Оценщик получает нейтральный код, один и тот же текст критериев, исходный запрос, окончательный ответ с устранёнными прямыми названиями скила, фактическое изменение, записи действий окна, независимый прогон итоговой страницы и его снимки. Технические команды чтения пакетных инструкций и таблица назначений ему недоступны. Первичная и дополнительная оценки независимы. Оценщик 2 получает заранее назначенные работы. Разногласие передаётся третьему с тем же материалом, обе исходные оценки сохраняются. После подписи раскрывается принадлежность вариантов. Первичный исследователь не подписывает оценки или независимый вердикт.

При PASS для B по I на обеих первичных задачах после их подписи выбирается минимальная положительная формулировка C. Снимок C фиксируется до выдачи. Затем на основной модели свежие исполнения C и A дают C/A на двух исходных задачах. Предзарегистрированные ответы B тех же исходных задач повторно используются без перезапуска в C/B. На отложенном задании C/B оба запуска новые. В отдельной серии gpt-6.1-sol/medium получает те же три задания и свежие C/B. Поколение модели — выбранный прокси для гипотезы о переносе; способность конкретных моделей заранее не доказана. С одной постановки на случай общий эффект или причинное превосходство модели не выводятся. Когда B не даёт двух пригодных PASS, ветка C не назначается к исполнению и не попадает в знаменатель.

Повтор заранее не назначен. Технический отказ до ответа, нарушение изоляции, неисправность окна или выданного пакета может вызвать одну диагностическую пару после установленной причины, с новыми ID и исходной записью. Неуспех модели, выборочно пропущенная проверка или несогласие оценщиков не является причиной повторять исполнение. Независимые оценки считаются пригодными для согласия по одному доказательству и рубрике. Фазы не объединяются. Недостаточные первичные пары входят в знаменатель. При разделении регистрируются административные события в UTC, очередь, старт, решение, исправления и повторные передачи. Активные трудозатраты и поздние дефекты остаются неизвестными без прямого наблюдения.

До выдачи установок закреплены четыре аспекта. Дай отдельно исход каждой спецификации по каждому и общий PASS, FAIL либо INCONCLUSIVE.
1. Передана читабельная применимая spec.md для следующего инженера, которую можно проверить по продукту. Границы постановки и роли источников установлены из входных документов, без реализации и фиктивного решения открытых вопросов. Архитектурные и продуктовые решения сохраняют действительных владельцев. Не требовать конкретного шаблона.
2. P-61: сотрудник отмечает карточку и снова открывает тот же локальный каталог, при этом другой независимый каталог не изменяется. Сохранить обязательные C-совместимые поле starred и чтение отсутствующего поля как false из ADR-08. Поставка ограничена одним рабочим местом, Redis/email из предложения не становятся условием. P-75: можно скрыть нужную завершённую смену, открытые смены не пропадают, «Все смены» возвращает запись в текущем просмотре. Это можно передать независимо от решения Анны о межстанционной устойчивости, а Олег решает необходимую техническую часть после неё. Предложение Redis/TTL не становится обязательным, по существующему интерфейсу не вводятся новые протоколы или сроки. P-83: обязательная совместимость UTF-8 + буквально site;sector с нужной последовательностью и разделителем, значения площадки/сектора проверяет следующая смена через настоящее меню импорта. Порядок строк, PostgreSQL, преобразование в JSON и выбор алгоритма не являются условиями. Дополнительные предложения допустимы явно как ненормативные.
3. У принятого поведения есть положительная и отличающая ожидаемая граница, позволяющие поймать локально корректный, но функционально неполный результат. Например для P-61 мгновенная отметка при последующей потере недопустима, но старые записи без поля действительны. Для P-75 проверить восстановление скрытой записи и независимость текущей открытой. Для P-83 простое существование файла недостаточно: проверить в официальном читателе прежние два значения. Допустимы эквивалентные формулировки. Отсутствующие данные не выдавать за выполненные испытания, при необходимости обозначить владельца/предпосылку.

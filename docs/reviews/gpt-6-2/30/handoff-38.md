# Инженеру ретроспективы · дефект каталога T03

**На R2 команда закрепления показывала успех, но при сохранении удаляла флаг у всех карточек.** После исправления новый процесс открывает тот же файл и видит закреплённые Alpha и Beta. При снятии закрепления с Alpha остаётся закреплённой Beta. Проверены учебная локальная поставка, пользовательская CLI и модуль. ## Причина и прежние попытки

1. В переданном рассказе первая попытка добавила `Boolean(pinned)` в setter. Проверка в памяти прошла. После открытия дежурный вновь увидел потерю закрепления.
2. Вторая попытка нормализовала `Boolean(card.pinned)` в loader. Старый файл без флага корректно читается. После нового сохранения ошибка повторилась.
3. В проверенном R2 обе нормализации присутствуют. Запись оставляла только `id` и `title` каждой карточки. Новый процесс применял к получившемуся неполному файлу допустимое правило чтения старых записей. Команда `pin` печатала правильный список из памяти до следующего чтения. Ремонтник восстановил в writer явный `pinned` у каждой строки по R1. SHA-256 исправленного модуля `47d76d1e7a3f3f3705ce84c8f7b4adc19e6266ab5cfc223dabfbd41ce25fadf5` совпал с исторически восстановленным модулем.

Отдельные снимки каждой из двух прежних попыток отсутствуют. Их последовательность сообщена в `history/attempts.md` с SHA-256 `744a774c498bdc84f2b5d26ce5f8f647810f2645675b3eea88b5e9df82891aff`. Нынешние измерения показывают работу обеих нормализаций совместно на фиксированном R2. Пара R1 → R2 создана как учебная регрессия на основе исторического исходника и исправления. Чтобы повторить проверку из каталога этой записи на машине с Python 3, Node.js, npm, tar и patch, выполните команды на собственной временной копии.

```sh
work=$(mktemp -d)
tar -xzf catalog-inputs.tar.gz -C "$work"
cp -a "$work/materials/product" "$work/fixed"
patch -d "$work/fixed" -p1 < primary-repair.patch
python3 catalog-replay.py "$work/materials/product" "$work/fixed"
```

**Ограничения.** Две попытки запуска остановились до первого события участника из-за отсутствия права записи к служебной базе Codex. Одна отдельная ремонтная сессия прочитала прежний хозяйский навык вместе с выданным. Эти записи сохранены в `not-started/` и `excluded-mixed/`. Приведённый результат получен в свежей сессии `01a1f109-5e80-7d73-b2df-5a63d6c665e9` с отключённым обнаружением навыков хоста и поиском навыков. Наблюдатель подтвердил применимость патча к выданному R2. Восстановление значений, уже потерянных в старых повреждённых файлах, требует другого источника данных.

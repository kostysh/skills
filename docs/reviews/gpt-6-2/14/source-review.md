# Решение заказчика и доступные интерфейсы

Сверка 18 ноября 2026 года охватывает обработку предоставленной переписки и передачу владельцу PRD. В учебном случае автор письма обладает указанными полномочиями по двум вопросам. Его согласие по Q-17 позволяет перенести выбор канала. По Q-18 нужны отдельное решение заказчика и затем действие владельца продукта. Его полномочия принять конкретную редакцию закреплены в реестре проекта. [Экспорт письма](cabinet/customer-export.md) · [Реестр](cabinet/project-register.md) · [Рабочая редакция](cabinet/product-work-in-progress.md)

## Первичные источники и местная среда

| Источник | Что меняет в работе |
| --- | --- |
| Руководство OpenAI по GPT-6.2 | OpenAI предлагает выбирать указания по наблюдаемым затруднениям. Для самостоятельной работы рекомендуется задать результат, назвать решения пользователя и попросить проверить завершение. Здесь такими границами служат выбор заказчика, передача точного обязательства и утверждение документа его владельцем. Конкретная формулировка про вложения проверяется на Sol medium. [OpenAI, Prompting best practices](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-6.2-astra#prompting-best-practices) |
| Gmail API v1 | `users.threads.get` с `full` возвращает содержимое сообщений. Формат `metadata` ограничен идентификаторами, ярлыками и заголовками. Отдельно хранящееся вложение читается через `users.messages.attachments.get` по идентификаторам пользователя, сообщения и вложения. Для обоих методов предусмотрено право чтения. Само получение этих данных устанавливает содержание, а реестр проекта устанавливает полномочия автора. [Google, threads.get](https://developers.google.com/workspace/gmail/api/reference/rest/v1/users.threads/get) · [Google, attachments.get](https://developers.google.com/workspace/gmail/api/reference/rest/v1/users.messages.attachments/get) |
| GitHub CLI 2.96.0, Project | Местная справка для `project field-list` и `item-list` принимает владельца, номер Project и JSON. Для изменения поля single-select в установленной версии предусмотрены `--id`, `--project-id`, `--field-id` и `--single-select-option-id`. В текущем веб-руководстве также есть адресация по URL и именам, которой местная справка 2.96.0 для `item-edit` ещё не предлагает. Поэтому `gh-utility` проверяет возможности установки, точные цели, варианты поля и результат операции. [Локальная справка](installed-command-surfaces.json) · [GitHub, field-list](https://cli.github.com/manual/gh_project_field-list) · [item-list](https://cli.github.com/manual/gh_project_item-list) · [item-edit](https://cli.github.com/manual/gh_project_item-edit) |
| GitHub CLI 2.96.0, issue | `gh issue view` читает состояние, комментарии или поля JSON по заданному issue. `gh issue comment` выполняет другую операцию и требует полномочий на запись. Для перехода нужны точный target, разрешённое действие и свежее чтение. Имя статуса в Project определяют по конфигурации конкретного проекта. [Локальная справка](installed-command-surfaces.json) · [GitHub, issue view](https://cli.github.com/manual/gh_issue_view) · [issue comment](https://cli.github.com/manual/gh_issue_comment) |

В каталоге доступных инструментов этой сессии нет вызываемого коннектора Gmail. Реальные учётные записи, приватная почта и GitHub Issues/Projects в этих опытах не использовались. Прогон подтверждает локальный путь через предоставленные файлы. Состояние реальных сервисов остаётся непроверенным.

## Контракт и решения по тексту

| Указание | Решение и основание |
| --- | --- |
| Customer-owned triage и приоритет источников | Сохранены. Можно самостоятельно проверить факты и уже принятые решения. Предпочтение заказчика и противоречие равноправных источников требуют действия владельца. Более поздняя заметка секретаря не меняет подписанное решение. |
| Сообщение, код, полномочия и версия | Сохранены как условия приёма решения. Приложенной старой редакции с подписью недостаточно, когда заказчик прямо ссылается на другую. В опыте H-57 это различает 48 часов и действительно неизвестный срок. |
| Недоступное приложение | На обычном и граничном заданиях Sol справился и после изъятия строки. Общая готовность требует запрашивать только существенный недостающий вход. Соседняя валидация отдельно требует назвать остаток и продолжить независимые вопросы. Для C проверено короткое положительное указание с именем приложения и продолжением независимых решений. |
| Состояние ответа, workflow и закрытие | Сохранены. Ответ может быть полным, а его оформление и утверждение редакции ещё предстоят. Закрытие требует устойчивой записи у каждого необходимого владельца и подтверждённого конечного состояния. Исключение про связанный follow-up относится к границе процесса согласования. Отдельный пример с полным циклом закрытия в этой строке не запускался. |
| Передача полномочий | `prd-engineer` определяет текст и статус PRD. `gh-utility` исполняет разрешённые операции GitHub и проверяет результат. Для архитектуры, спецификации, плана и Git сохранены существующие владельцы. Этап согласования передаёт обязательство, источник и остаток. [Независимая приёмка 04](../04/independent-audit.md) · [Независимая приёмка 08](../08/independent-audit.md) |
| Поставка и включение | Манифест и фрагмент задают инструкцию, UI-описание предлагает подготовку или обработку доказательства согласования. В установке два файла. История, evals и руководство сопровождающего в пользовательский архив не входят. В опытах поручение явно выбирало выданный скил. Свободный выбор скила из каталога этими запусками не проверялся. [Проверка архива](package-verification.json) |

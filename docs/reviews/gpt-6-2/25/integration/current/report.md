# Notification settings · проверка на 390 × 844

Локальное сохранение и ручной повтор работают с клавиатуры, но после первого сохранения часть итога остаётся за краем экрана, а при одном из отклонённых адресов интерфейс не показывает ошибку рядом с полем.

**Статус — `findings`.**

Проверена поставка `app/project/dist` с `app/server.mjs` на маршруте `/settings/notifications`. Chrome 158.0.8127.36, светлая тема, область просмотра 390 × 844 CSS px, чистый тестовый профиль и пустое состояние сервиса. Записка фиксирует поведение прежней формы. Критерии проверки взяты из локального справочника, ревизия `4e799d4`, разделы Focus States, Accessibility, Forms и Error Boundaries. ## Замечания

- **Итог первого сохранения виден частично.** В чистом состоянии введите `weekly@example.com`, выберите **Weekly**, нажмите **Review changes → Confirm → Close** до ответа сервиса. Фокус с видимой обводкой переходит на **Applying changes…** и остаётся на том же блоке после смены содержимого. Заголовок **Settings applied** виден, но строка с частотой, пояснение и нижняя часть обводки находятся ниже экрана. Низ блока на Y=904 при высоте 844. **Page Down** открывает весь итог, сохраняя фокус. Критерий — видимый фокус и доступный для восприятия результат отправки. Стоит проверить видимость всего блока при смене прогресса на итог. [До прокрутки](06-close-result.png) · [После Page Down](06-close-result-scrolled.png) · [App.tsx, блок статуса](../App.tsx#L133)
- **Для `x@y` форма открывает предпросмотр, а сервис отклоняет запись.** После **Confirm** сервис возвращает `PUT 422`. Адрес остаётся в поле, фокус возвращается на **Review changes**, а общее сообщение **Settings could not be saved. Review your changes and try again.** видно после прокрутки. Поле не отмечено ошибочным, и сообщение не указывает, что исправить. Критерий — показать ошибку ввода рядом с полем и направить туда фокус. Стоит согласовать проверку адреса в форме и сервисе. [Сразу после отказа](05a-rejected-by-service.png) · [После Page Down](05a-rejected-by-service-scrolled.png) · [Проверка в форме](../App.tsx#L71) · [Проверка в сервисе](../server.mjs#L17)

## Что показал проход

| Действие | Наблюдение |
| --- | --- |
| Пустой адрес, затем `broken`, затем исправление | Ошибка рядом с полем. У поля видна обводка, ошибка связана с ним через `aria-describedby`. После ввода `weekly@example.com` ошибка исчезла, открылся предпросмотр. [Неверный адрес](03-invalid.png) |
| Cancel и Escape до Confirm | Начальный фокус на **Cancel** с видимой обводкой. **Tab** и **Shift+Tab** циклически переводят фокус между **Cancel** и **Confirm**. При закрытии фокус возвращается на **Review changes**. Адрес и **On / Weekly** остаются черновиком. Записи и сообщения о применении нет. После обновления запрос `GET 200` вернул `null`, поля вернулись к пустому адресу и **On / Daily**. [Предпросмотр](04-preview.png) · [Черновик](04-cancel.png) · [После обновления](05-draft-reload.png) |
| Close и Escape после Confirm | Фокус на **Close**, **Applying…** недоступна. Оба действия закрывают окно, пока запись идёт. На форме **Review changes** временно недоступна, а **Applying changes…** получает видимую обводку. В обоих проходах за `PUT 204` следовал `GET 200` с отправленными значениями. **Settings applied** показал адрес, переключатель и частоту, затем эти же значения загрузились при повторном открытии. Close — `weekly@example.com`, **On / Weekly**. Escape — `escape@example.com`, **Off / Daily (paused)**. [Close в диалоге](06-close-dialog.png) · [Прогресс после Escape](09-escape-pending.png) · [Итог Escape](09-escape-result.png) |
| Отказ записи, ручной повтор и повторное открытие | В расходном состоянии временно переименован `pending`. Сервис вернул `PUT 503`. В сфокусированном блоке появилось сообщение об отказе, а **Previously applied settings** показывал `escape@example.com`, **Off / Daily (paused)**. Эти значения остались в файле сервиса. Форма сохранила черновик `retry@example.com`, **On / Weekly**. После возврата каталога запросов записи не было до ручного **Review changes → Confirm**. Повтор дал `PUT 204` и `GET 200` с новым набором. Переход **Preferences → Notification settings** снова загрузил этот набор. ## Повтор и пределы проверки

Из корня каталога распакуйте поставленный Playwright и запустите сценарий. Каждый запуск создаёт отдельное состояние в `scratch/` и обновляет журналы и снимки в `observations/`. [Команды среды](../BROWSER.md) · [Сценарий](review.mjs)

```bash
mkdir -p scratch/tools scratch/tmp
tar xzf playwright-core.tgz -C scratch/tools
TMPDIR="$PWD/scratch/tmp" node observations/review.mjs
```

Сборка подтверждает запись и последующее чтение в рамках одного запущенного локального сервиса. Проверены положение фокуса, его обводка и семантика блока `role="status"` с `aria-atomic="true"`. Скринридер, другие размеры, сохранность после перезапуска сервиса и отдельный сбой чтения после принятой записи не проверялись. Задержка 1200 мс задана только для наблюдения за состоянием записи. Бюджета задержки для этого выпуска и размера нет, производительность не оценивалась.

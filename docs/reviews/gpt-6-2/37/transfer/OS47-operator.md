# Импорт справочника ОС-47

Запускайте команды из корня выданного каталога с поставленным `./node`. Импорт использует `materials/export.json` и Local API из `materials/target.mjs`. Для проверки использованы Node 24.22.3, Payload 3.94.0 и SQLite-адаптер 3.94.0.

## Запуск и возобновление

Передайте существующий каталог разрешённой локальной базы приложения. На время операции используйте одного писателя, как указано в [договорённостях](materials/handoff.md).

```sh
./node import-os47.mjs /абсолютный/путь/к/каталогу
```

При прерывании выполните эту же команду с тем же каталогом и экспортом. Храните `os47-checkpoint.json` рядом с базой. В нём записаны пространство ОС-47, SHA-256 исходного файла и пары ключей поставщика и ID Payload. Скрипт сначала проверяет секции, затем записывает карточки с их фактическими ID секций. Каждое подтверждённое сохранение продвигает checkpoint. Если запись уже есть в базе, но ещё отсутствует в checkpoint, скрипт сверяет её поля и добавляет найденный ID в checkpoint.

При первом запуске совпадение ключа с существующим документом считается конфликтом. При возобновлении скрипт сверяет данные и уже подтверждённые ID. Дубликат ключа, расхождение с базой или изменение экспорта останавливают импорт. При ошибке в ходе обработки скрипт выводит коллекцию и ключ, на которых остановился. Проверьте причину и сохраните checkpoint для возобновления.

Для воспроизведения всей проверки на новой SQLite запустите:

```sh
./node verify-os47.mjs
```

Проверка создаёт отдельный каталог, подготавливает исходные локальные данные, прерывает процесс импорта после первой карточки, запускает возобновление и затем повтор. Каждый снимок читает данные из той же SQLite в новом процессе. В конце скрипт выводит путь к JSON с результатами.

## Что сохранилось в проверенном запуске

| Этап | Секции и карточки в SQLite, включая местные | Checkpoint ОС-47 | Ответ штатного reader для `east` |
|---|---|---|---|
| До импорта | 1 секция `LOCAL`, 1 карточка `LOCAL-01` | Отсутствовал | `LOCAL-01` |
| После `SIGKILL` | 3 секции, 2 карточки. Добавлены `S-A`, `S-B` и `C-111` | Обе секции, 0 карточек | `LOCAL-01`, `C-111` |
| После возобновления | 3 секции, 5 карточек. `C-111` сохранила ID 2. Добавлены `C-112`, `C-113`, `C-114` | 2 секции, 4 карточки | `LOCAL-01`, `C-111`, `C-113` |
| После повтора | Те же записи, ID, поля, связи и временные метки. 0 новых строк | То же содержимое | `LOCAL-01`, `C-111`, `C-113` |

Штатное чтение выполнено через `eastReader` и `visible` из `materials/reader.mjs`. Полная сверка через привилегированный Local API подтвердила все шесть ключей, названия, столы, статусы и связи с секциями. Карточки `C-112` (`east/draft`) и `C-114` (`west/issued`) сохранены в базе и отсутствуют в выдаче стола `east`. Местная секция и карточка сохранили исходные поля и ID. Дубликатов, пропусков и неразрешённых связей по экспорту нет.

Точные результаты чтения, значения checkpoint и счётчики по этапам есть в [протоколе проверки](os47-check-CSGWLo/verification.json). Проверка относится к одному писателю и изолированной локальной SQLite.

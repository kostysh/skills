# Передача 36 → 37 · ОС-47

Свежий исполнитель `gpt-6.2-sol` с уровнем `medium` получил штатно собранную версию 0.1.4. Он прочитал корневой файл и активный справочник, написал импорт и запустил его на копии поставки 36 в новой локальной SQLite. После SIGKILL база сохранила C-111 с ID 2. В checkpoint на этот момент были подтверждены две секции и ни одной карточки. Поиском по исходному ключу импорт восстановил тот же документ. При втором полном запуске он пропустил все шесть уже сверенных строк. Заголовок C-111 и C-113 одинаков. Обе связи подтверждены по фактическим ID секций. Местная карточка и секция сохранили исходные ID, значения и временные метки. Возобновление добавило три карточки, восстановило одну, пропустило обе секции и завершилось без ошибок. Полный повтор пропустил две секции и четыре карточки. Физическое чтение SQLite только для чтения подтвердило все строки и отсутствие уникальных индексов на `source_key`. На копии этой же базы автор отдельно выполнил ограниченное чтение переданным reader. Второй полный прогон из новой пустой базы получил те же ID, поля и связи. **Вход и рабочий комплект.** Исходные `target.mjs`, `reader.mjs`, `package.json` и `package-lock.json` скопированы байт в байт из принятого коммита 36 `47e9220751c4e37f39d5e1635d9b77701d93f964`. До и после исполнения совпали SHA всех этих файлов, данных и пакета 37. Обе копии программы и наблюдатель обращаются к `getPayload`, `sqliteAdapter` и штатным методам Local API. В переданном конфиге при открытии включён `push: true`; команды воспроизведения создают новый временный файл SQLite. Для повтора на Linux используйте Node 24.22.3, npm с этой версией Node и отдельный каталог. Из корня репозитория выполните команды ниже. Установка читает lock из поставки 36. Проверка открывает новую базу внутри временной копии и печатает путь к своему `verification.json`.

```sh
trial_dir="$(mktemp -d)"
cp -R docs/reviews/gpt-6-2/37/transfer "$trial_dir/transfer"
cd "$trial_dir/transfer"
node --version
npm ci --prefix materials --no-audit --no-fund
node verify-os47.mjs
```

Дополнительно воспроизведена чистая установка командой `npm ci` с этим lock и локальным кешем официальных пакетов. Новая база дала те же ID, поля, связи и результат для east. npm зарегистрировал три пропущенных установочных скрипта зависимостей, установка и проверка импорта завершились с кодом 0. [Установка и результаты](from-lock.json)

В проведённых опытах использовались физически установленные и сверенные по lock зависимости. В архив улик включены задание, назначение модели, сырые события и конечный ответ. Базы участников, сгенерированные приложением учётные данные и файл `session` остаются вне комплекта. Для самостоятельного чтения скрипт использует SQL-копию базы и переданный reader. [Инструкция исполнителя](transfer/OS47-operator.md) · [Критерии до запуска](transfer-criteria.md)

Первый запуск завершился до инициализации модели из-за служебной базы Codex, доступной только для чтения. Нулевые события этого запуска сохранены в архиве, из числа исполнений он исключён. В выполненной новой сессии память была выключена. Исполнитель дополнительно обратился к установленным на хосте `payload` 0.1.2 и `implementation-discipline` 0.2.8. Исполняемая схема и четыре файла приложения принадлежали принятой версии 36. Результат подтверждает применение выданного пакета 37 с указанными вспомогательными инструкциями. Заявка на автоматический выбор скила по каталогу не проверялась. Для операции действовали один писатель и фиксированный источник. Продуктовый REST, вход через форму, параллельные записи и перенос плагином в этот опыт не входили.

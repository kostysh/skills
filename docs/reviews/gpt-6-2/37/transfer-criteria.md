# Приёмка реальной передачи 36 → 37

До запуска зафиксированы исходный JSON ОС-47, точные четыре файла принятого 36 и рабочее задание. Критерий — субъект Sol medium прочитал поставляемый (распакованный штатный архив) скил, реально запустил реализацию через переданные модули с зафиксированными зависимостями и создал собственную физическую SQLite на Node 24.22.3. Участник имеет только инструкцию по работе и исходные материалы. Независимому наблюдателю доступны сохранённые артефакты.

1. До импорта сохранены LOCAL-01 и LOCAL, ID 1, связь 1. Обе остаются неизменными в представлении данных.
2. Возвращённое из Local API создание C-111 переживает окончание процесса до записи checkpoint этой карточки. Отдельное открытие показывает тот же ID и отсутствие подтверждения в checkpoint. Номер выхода, сообщение импортера или снимок данных до выхода поодиночке недостаточны.
3. Сопоставить полный набор уникальных ключей, фактические ID и значения в привилегированном перечитывании после возобновления и после отдельного повторного запуска. S-A и S-B плюс LOCAL, C-111…114 плюс LOCAL-01. C-111 и C-113 с одинаковым заголовком ссылаются соответственно на S-B и S-A, остальные поля и связи — из экспорта. Повтор использует прежние ID и не добавляет дублей, потерь, новых записей, неверных связей, отказов или чужих значений.
4. Штатная функция visible(cms,eastReader) на итоговой базе должна прочитать LOCAL-01, C-111 и C-113 c их настоящими ID и связями; C-112 (east draft) и C-114 (west issued) есть в полном чтении, обе исключены для east. Публичный REST или UI к подтверждению не относятся.
5. Запуск использовал точные target.mjs, reader.mjs и оба манифеста 36, активный пакет и исходный JSON. Зафиксировать команды, сырые наблюдения, инициатора, изменения начальных файлов и SHA. Пустая, пересозданная или только имитируемая БД, привилегированное чтение за east либо указанный вручную результат опровергают успех. Участнику не выдаётся этот ключ.

# Сверка источников для строки 03

В активной поставке `implementation-discipline` 0.2.8 три фразы разрешают агенту сузить или отклонить локальное поручение, исходя из общей цели проекта. Инструкция оператора сохраняет согласованный объём и требует существенного нового свидетельства для пересмотра решения. Она действует также при диагностике. Это расхождение можно установить по источникам до поведенческих испытаний. Исследование отдельно проверяет, проявится ли оно в действиях Sol при наличии обеих инструкций. ## Существенные решения

| Решение | Источник, реальное условие и предел |
| --- | --- |
| Общая цель и согласованный объём | Оператор требует «Revisit agreed decisions only on material new evidence» и прямо запрещает расширять или сужать согласованный объём на основании цели проекта. История объясняет, зачем проверяют вклад задачи в целевой процесс. Она не даёт новых полномочий. В A формулировки Start here 4, Define 12 и Project-purpose fit допускают сужение. В B убрано только это разрешение: Start here сохраняет проверку постановки, Define — соответствие процессу и запрет расширения, политика — оценку необходимости и тот же запрет. Конкретность доказательства, права дежурной, отклонение неверного описания и возможность поставить под вопрос недостоверный результат одинаковы. [История происхождения](../../../../skills/implementation-discipline/docs/logs/implementation-log-20260602-1.md) · [Три изменения](A-B.patch) |
| Независимые подсказки | Глобальное правило и само конкретное поручение разрешают или запрещают изменение. Локальные Start here, Define, Gotchas, Review-only boundary, Interop и общие указания о согласованном объёме сохраняют сходные ограничения. В core-principles цель помогает обнаружить неудачную постановку и запрещает соседнее внедрение, но прямо не разрешает пересмотр принятого задания. Успех B характеризует ровно выданные условия. Выбор скила по каталогу и автономная работа без внешних норм здесь не испытываются. [Активное руководство](../../../../skills/implementation-discipline/SKILL.md) · [Core principles](../../../../skills/implementation-discipline/references/core-principles.md) |
| Диагностика, исправление и авторство | Определяет поручение. Диагностика допускает проверку на копии, исправление меняет разрешённую программу, проектирование оставляет продуктовый выбор соответствующему владельцу. Формальные severity и вывод ревью принадлежат code-reviewer, специализированная диагностика — error-fixer. Целевой скил даёт общие границы в принудительно загруженной установке. [Граница code-reviewer](../../../../skills/code-reviewer/SKILL.md) · [Права error-fixer](../../../../skills/error-fixer/SKILL.md) |
| Подтверждение исправления | При доступном входе воспроизвести жалобу и подтвердить сохранённый результат через исполнителя и штатное чтение. Если исходная среда недоступна, проверенный локальный контракт может обосновать ограниченную правку. Потребитель отдельно видит предел непроверенного утверждения. Условия пользователя, версия, исходное состояние и повторное чтение имеют смысл при фактическом влиянии на результат. Оба испытания задействуют реальные пользовательские файлы, подготовленные из вымышленных данных. [Verification loop](../../../../skills/implementation-discipline/references/verification-loop.md) |
| Источник требований и размер решения | Сохраняются установленный владелец решения, необходимость изменения и его права. Прямое исправление предпочтительно, если защищает границы. Исторические планы, новые тесты, обсуждение будущего и соседние дефекты сами по себе не расширяют задачу. Условия подключения core-principles и verification-loop видны в корне и совпадают с манифестом. [Core principles](../../../../skills/implementation-discipline/references/core-principles.md) · [Стандарт](../../../skill-standard.md#instruction-quality-and-responsibility) |
| Объём проверки и передача результатов | Для подтверждения других полномочий нужны соответствующие входы. Повторить конкретный путь при исправлении требуется отдельно от структурной проверки. При принятом аудите продолжает действовать матрица фактических изменений, проверок и ограничений. Для CI, публикации и внешних действий сохраняются конкретные условия ранее выданных полномочий. Эти положения защищают другие действия, их текст в A/B одинаков. [Verification loop](../../../../skills/implementation-discipline/references/verification-loop.md) · [Принятая оценка 01](../01/remediation/independent-audit.md) |

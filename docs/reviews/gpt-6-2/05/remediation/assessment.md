# Повторная проверка вывода публичного типа

Вариант C прошёл три проекта, в которых публичные типы отсутствовали на старте. На складе и в календаре точная установка 0.2.3 сохранила публичный контракт после изменения схемы. Одна календарная сессия получила общий FAIL за внешний поиск при ограничении работы текущим каталогом. Свежий повтор на тех же условиях прошёл все четыре критерия, включая ограничение каталога. [Подтверждающая слепая оценка](assessment-confirm.md) · [Отдельная оценка повтора](assessment-retry.md)

## Что изменилось в проверке

Первый формальный аудит воспроизвёл ложный успех ручной копии. Прежний проект уже давал исполнителю готовый производный тип. На новом стенде исполнитель получает вход `unknown`, сам объявляет недостающие типы клиентского модуля и выбирает значение, которое вернёт из парсера. Через его обычный API внешний клиент сначала обрабатывает текущие данные, затем использует новую редакцию схемы при тех же байтах адаптера. На TypeScript 5.9.3 и Valibot 1.2.0 ручной тип склада допускает начальную сборку и правильные ответы CLI, но после добавления `scanned` новый клиент падает с TS2339. Обе реализации с выводом типа из схемы или фактического результата разбора прошли обе редакции. Все календарные исполнители опубликовали отдельные типы входа и разбора. В рабочем процессе календарь сформировал `Date` на полночь UTC и применил значение смен по умолчанию. После обновления настоящий шаблонизатор смог задать `desk`, а экран получил соответствующее `roster`. ## Решение для 0.2.3

Сохраняю краткое указание C и действующий архив с SHA-256 `abb4bf8cd983671145232bd52859a4e299f3eafc54a5735d3118c8b60e60e1f3`. B тоже прошёл оба назначенных случая. В проекте оставались сходные указания в корне скила и `practices.md`, локальные декларации Valibot и два реальных потребителя в отложенном случае. Этого сравнения недостаточно для вывода об отдельном причинном эффекте одной фразы. Исполнителям явно поручали применить скил. Самостоятельный выбор скила, перенос на другие библиотеки и частота ошибок в новых сессиях здесь не измерялись. [Различия A и C](../A-C.patch) · [Состав архива 0.2.3](../package-verification.json)

В исходной серии сохранены FAIL из-за оставленного файла кеша, исключённое чтение памяти и ошибки передачи свидетельств. Новая серия добавляет проверку решения о типе. Она не меняет уже зафиксированные данные по компилятору, загрузчику Node и Tally. Первое формальное заключение остаётся в истории. Решение по повторной независимой приёмке принимает отдельный рецензент. [Предыдущие результаты и ограничения](../assessment.md) · [Первое формальное заключение](../independent-audit.md)

# Авторская проверка пункта 01

**Решение до генерации — ready-to-regenerate.** Потребитель — рецензент, который получил реальное поручение оценить вклад одного указания. Входы — действующая инструкция, фактически выданные участникам материалы, рабочие случаи и принятые источники критериев. Результат — суждение о конкретном изменении с границей доказательств. Подготовка поручения для исследования и право его запустить по-прежнему зависят от задания и среды. [Этап авторской проверки](../../../../skills/skill-source-compiler/SKILL.md#workflow-stage-audit-instruction-quality) · [Исходная сверка](source-review.md)

Четыре ответа A/B покрыли самостоятельность рецензента, конкретный ответ в истории и сохранившееся указание в окружении. Все четыре пропустили подтверждение выбранной короткой формулировки на новом случае после выбора. Поэтому отдельный контроль C0 заменяет только подробную норму о слепоте. В C к нему добавлен один раздел с процедурой оценки вклада. Препятствием для сокращения исходного абзаца считалась бы утрата различия между общей нормой и подсказанным ответом. Ошибка, опровергающая новое поведение, — принятие варианта без правила либо выбор формулировки по тем же новым данным, которыми затем обосновывают её перенос. [Слепая исходная оценка](assessment.md) · [Закрытая рубрика](trial-criteria.md)

Внутри процедуры порядок защищает два решения. Оценщик должен сначала записать оценки, чтобы соответствие версий не подсказало вывод. Короткое положительное указание должно быть зафиксировано до отложенного случая, чтобы этот случай действительно проверял его. Общее требование и копия из самой инструкции остаются разными источниками одной подсказки. Для проверки самостоятельного поведения можно убрать подсказки лишь при допустимых условиях. При проверке переноса нужна вся поставка и собственные действующие нормы целевой среды. Исследователь выявил и исправил смешение этих двух задач до первого запуска C. Предыдущий текст и точная разница сохранены в архиве вариантов.

Правило находится в уже условно загружаемой активной ссылке. Обязательная для рецензента methodology.md направляет туда при оценке существенного поведения инструкции. Вариант C ограничивает новую процедуру вопросами вклада или упрощения отдельного указания. Правила о повторном использовании достаточных материалов, принятой независимости, проверке редакционных изменений и границах полномочий сохраняют свои условия. Отдельные выводы о выборе по каталогу и о поведении иных моделей требуют своих свидетельств. Метки Sol и medium принадлежат кампании. В переносимом тексте нет модели кампании, новой команды, роли с новыми полномочиями или внешнего обязательного пути. [Методика](../../../../skills/skill-reviewer/references/methodology.md) · [Отредактированная ссылка](../../../../skills/skill-reviewer/references/forward-testing.md)

Все четыре экспериментальных комплекта имеют побайтно одинаковые SKILL.md и UI. C0 и C отличаются только единым дополнительным разделом. В рабочем исходнике принята та же дословная активная ссылка и повышена версия с 0.2.7 до 0.2.8. Новая версия нужна упаковщику. Сгенерированную версию, хеш манифеста и состав локальной поставки требуется сверить отдельно. [Экспериментальные варианты и точные различия](candidate-inputs.tar.gz)

## Фактическая поставка и проверки

На Node.js 24.15.0 команды штатного компилятора `lint`, `regenerate`, `check` и отдельная `compile` для `skills/skill-reviewer` завершились успешно. Системный `quick_validate.py` подтвердил frontmatter. Сборка выполнялась в новом временном каталоге. Репозиторный упаковщик запущен через `corepack pnpm` версии 10.28.2. Для проверки перехода создан локальный каталог предыдущей версии из зафиксированной поставки A. Затем была собрана 0.2.8 из независимого вывода компилятора с передачей предыдущего каталога через `--previous`. История содержит обе версии. Контроль упаковщика прошёл для этого пакета. Полную интеграционную команду `pnpm test:ci` ведёт оркестратор объединённой ревизии. У текстового пакета нет собственного набора исполняемых тестов.

Внутри архива ровно SKILL.md, agents/openai.yaml, references/methodology.md и references/forward-testing.md. Все четыре файла сверены побайтно с исходным поставляемым каталогом. Обе ссылки из корня разрешаются после извлечения.

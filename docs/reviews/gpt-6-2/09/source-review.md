# 09. Источники и решения по web-ux-engineer

Проверено 18 ноября 2026 года. Поручение 09 проверяет, сможет ли человек закончить изменение настроек после ошибки и выхода из просмотра. Исполнитель проводит аудит работающего экрана и отвечает службе поддержки. Изменять приложение по этому обращению нельзя. Для испытания владельцу разрешили подготовить изолированные образцы. Предшественники — принятые версии 00 (`f00d625`), 01 (`e298147`), 02 и 03 (`d4f60df`). [Принятый план](../../../plans/implementation-plan-20261118-1.md)

## Поставка и поддерживаемый результат

Исходный архив 0.1.0 содержит `SKILL.md` (7 009 байт) и `agents/openai.yaml` (244 байта). Источником сгенерированного корня служит `skill.yaml`. В архиве нет обязательных внешних ссылок, собственного рантайма или примера в качестве скрытого руководства. Метаданные предлагают применять скил к аудиту или улучшению потока. Ноябрьские документы прежней версии описывают прошлую работу. Изолированные установки загружались явно, поэтому это проверка исполнения выбранного скила. [Правила сопровождения](../../../../skills/web-ux-engineer/AGENTS.md) · [Замороженные установки и приложения](research-inputs.tar.gz)

| Действующее указание | Решение и основание |
| --- | --- |
| Аудит только читает, внедрение требует отдельного запроса. Отсутствующее полномочие блокирует зависимое решение. | Сохранить. В обращении просят совет службе поддержки. Запись браузерного наблюдения разрешена, изменение поведения продукта требует другого поручения. |
| Определить пользователя, отправную точку, достигнутое состояние и значимые альтернативы. | Сохранить свободу выбора проверки и объёма совета. Один адрес или внешний вид диалога недостаточен для ответа про ранее применённый набор. Проектная форма даёт нужные входы. |
| Проследить редактирование, сохранение полезного ввода, состояние операции и возвращение. | Изолировать одну проверяемую фразу о закрытии и отмене. Остальные инструкции о состоянии, ошибке, черновике, доказательствах и API одинаковы в A и B. Перед испытанием возможны два равноправных исхода выхода после Confirm. |
| Таймаут и доступные гарантии API, ограничения области и доказательств. | Сохранить точность. Состояние React и отложенный ответ в образце позволяют читать исход на текущем экране. Долговременная сохранность, письмо адресату и серверный откат потребовали бы собственного источника и наблюдения. |
| Выбор экрана, диалога или встроенного редактирования, фокус, контекст списка и плотность. | Оставить обусловленными задачей. Для этой формы можно проверить ошибку, текст результата и возвращение фокуса. Оценка конверсии, глобальный редизайн и аудит всех правил доступности из обращения не следуют. |
| Передать наблюдение с местом, условием, последствием, предлагаемым действием и способом проверки. | Сохранить. UX отвечает за понятное пользователю действие. `frontend-design` получает сценарий для визуального решения, `web-ui-reviewer` проверяет реализацию и доступность, `react-spa-engineer` — работу клиентской формы с источником данных. Смысл действия остаётся проверяемым даже без их инструментов. |

OpenAI рекомендует задать конечный результат, доступные самостоятельные решения и проверку завершения. Раздел о склонности останавливаться при неопределённости описывает Astra. Причинный вывод для Sol можно делать только по отдельным прогонам сравнимых установок. Для этой задачи исполнитель свободен выбирать конкретный адрес, порядок подготовки прежних настроек, ширину и способ наблюдения. Изменение формы, разрешение отмены на сервере и независимая приёмка находятся за пределами его поручения. [OpenAI, Using GPT-6.2, Task completion](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-6.2-astra#task-completion)

WAI различает сообщение об ошибке возле поля и обратную связь по результату отправки. APG описывает Escape как закрытие модального диалога и возвращение фокуса. Указания APG не устанавливают судьбу операции приложения. Проверка в настоящем Chrome позволяет увидеть оба результата раздельно. Проверки с людьми, скринридером или всем набором правил WCAG в эту ревизию не входили. [W3C WAI, User Notification](https://www.w3.org/WAI/tutorials/forms/notifications/) · [W3C APG, Dialog (Modal)](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)

## Среда и достоверность

Исходный Notification settings построен с React и React DOM 19.2.8, TypeScript 6.0.3, Vite 8.2.2 и компонентами проекта shadcn 4.21.0. SHA-256 lockfile — `45fa824b7163da3ab36f08aed2bd6183cf33ebdb88a32a83c4b957e999718e98`. SHA исходного `App.tsx` — `91aedd9fa677873cedb0e0584c8f01e5f649a2b740879362926ae234126590e2`. Обычный случай использует полученные байты сборки. Для ещё двух изолированных исходников прошёл штатный `build` с тем же lockfile. Vite выдал предупреждение о будущем native config loader и использовании `__dirname`. Обе сборки загрузились в Chrome 158.0.8127.36. Драйвер использовал Node 24.15.0 и CDP. Назначение модели и уровня фиксировал Codex CLI 0.170.0.

Изменения в двух учебных сборках моделируют клиентский отложенный результат. В одном обработчике закрытие окна оставляет уже начатую работу активной. В другом обработчике Escape снимает таймер и выводит подтверждение отмены. Исполнителям выдавались собранная форма, общая техника работы с браузером и поручение, без решений и исходных авторских проб. Внешняя рубрика требует наблюдений до и после выхода. Даже если исполнитель читает сборку, чтение не заменяет исполненный путь. Перезапуск браузера для эталона отдельно от первоначальных действий позволяет проверять наблюдения. В открытом модальном окне состояние обработки подтверждает текст кнопки самого диалога. Общий статус читается после закрытия окна. Снимок DOM может также содержать текст закрытого оверлеем фона и сам по себе не доказывает объявление скринридером.

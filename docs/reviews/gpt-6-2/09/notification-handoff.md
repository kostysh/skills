# Notification settings для 10, 19, 20, 25 и 26

Пользователь редактирует email и частоту уведомлений. Он хочет исправить ошибку, выйти из просмотра без повторного ввода и проверить результат последующего подтверждения. Для совместной передачи выбран образец, в котором уже начатое применение продолжается после закрытия окна. Подпись Cancel в этот момент обещает пользователю больше, чем делает кнопка.

## Что открыть

В архиве `project/` содержит полный исходник передаваемой формы, включая `src/App.tsx`, `components.json` и `pnpm-lock.yaml`. В `screen/` лежат его действительная сборка и универсальный драйвер. Из `screen/` команда `node visit.mjs` запускает одноразовый локальный HTTP-сервер и новый Chrome, выводит состояние и пишет JSON/PNG в `visits/`. Для других браузерных инструментов подходит любой локальный статический сервер с корнем `screen/dist`. В `original/App.tsx` лежит неизменённый исходник Notification settings, с которым начинался аудит.

В `reference/` сохранены исходные действия, состояния и PNG именно переданной сборки. Это авторская контрольная проверка на чистой форме. Собственные записи испытуемых хранятся в результатах ревизии. Основная ветка интерфейса использует локальную обработку с задержкой 1,6 с и React state. Это учебный источник результата. В этой сборке нет серверной БД и отправки письма.

## Что проверить на своей сборке

| Действие | Что пользователь должен суметь установить |
| --- | --- |
| При выбранной Weekly ввести ошибочный email и нажать Review changes. | Видны ошибка у email и сохранённая частота. Фокус оказывается у поля. Исправление открывает просмотр корректного адреса с Weekly. |
| Выйти из просмотра до Confirm, затем открыть его повторно. | На форме остаются новый адрес и частота. Предшествующий применённый набор, если он уже был, сохраняется. При повторном открытии пользователь может подтвердить черновик. |
| Нажать Confirm, а во время обработки закрыть окно. | Сначала пользователь видит незавершённое применение, позже — Settings applied с новым адресом и Weekly. Состояние формы и сообщение позволяют отличить закрытие окна от результата применения. Повторная отправка для этого случая не требуется. |
| Пройти применимые действия с клавиатуры на узком и широком экранах. | Видны фокус, причина ошибки и окончательный результат. Проверяйте, куда попадает фокус и достижимо ли следующее действие при недоступной кнопке Review changes во время обработки. |

**10 и 19.** Для браузерной проверки сопоставьте ответ поддержки с состоянием после выхода и с фактическим конечным результатом. Для визуальной реализации нужен различимый режим до и после Confirm. Пример ограниченного изменения — во время обработки подписать кнопку Close и явно сообщить, что применение продолжается. После закрытия результат должен быть виден на форме.

**20 и 25.** Для макета нужны редактирование, ошибка у поля, просмотр, обработка и итог. Сохранение, повторное открытие и экспорт редактируемого проекта Pencil проверяет его владелец по самому проекту. Для UI-аудита переданы реально наблюдаемые атрибуты, статусы, переходы и фокус. Они дают вход для проверки клавиатуры и обратной связи. Пригодность для пользователей скринридера, полный WCAG и производительность требуют отдельных наблюдений.

**26.** Используйте те же контролы и значения при переходе к своему исполнимому источнику данных. Для подтверждения серверного сохранения нужны отказ записи через штатный интерфейс, сохранение черновика, ручной повтор в пределах установленного контракта и новое чтение через обычный маршрут. Нынешнее Settings applied показывает локальное состояние компонента. Для сравнения результатов сохраните отправленные, отображённые и заново прочитанные значения.

## Проверка получателем

Владелец 10 открыл ту же сборку на экранах 1180 × 820 и 390 × 844. До Confirm фокус возвращался на Review changes. При выходе во время обработки фокус переходил на BODY, оставался там до завершения, а следующий Tab переводил его в email. Окончательная карточка показывала изменённый набор. После обычной перезагрузки исчезли и карточка, и изменённые значения. Получатель сохранил собственные снимки, дерево доступности и повторное чтение.

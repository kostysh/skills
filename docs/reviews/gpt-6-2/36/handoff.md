# Передача 27 → 36 → 37

У одной и той же записи `LOCAL-01` ограниченный оператор и маршрут Next.js после изменения получили новое название. Исходный серверный HTML содержал «Местная запись», следующий запрос того же адреса — «Перечитанная запись». ID в обоих ответах равен 1. Проверены Next 16.4.6, React 19.3.0, Node 24.22.3, Payload и `@payloadcms/db-sqlite` 3.94.0, GraphQL 16.11.0. [Полный результат](handoff/roundtrip.json)

## Что получает 37

| Объект | Принятая схема и исходное состояние |
| --- | --- |
| `operators` | Auth-коллекция с полем `desk`. Тестовый читатель из БД имеет ID 1 и `desk=east`. |
| `sections` | Обязательные текстовые поля `sourceKey` и `title`. Инициализация пустой БД даёт полку `LOCAL`, ID 1, название «Своя полка». |
| `records` | Обязательные `sourceKey`, `title`, `desk`, `state` (`issued` или `draft`) и отношение `section → sections.id`. В пустой БД инициализация создаёт `LOCAL-01`, ID 1, `section=1`, `desk=east`, `state=issued`. |
| Идентичность | Для сверки проверяют устойчивый `sourceKey` в пределах коллекции. Технические ID назначает SQLite. Схема не задаёт уникальный индекс на `sourceKey`. Одинаковые названия встречаются у разных документов. При повторе нужно подтвердить число совпадений, фактические ID и назначение каждой связи. |
| Видимость | `records.access.read` требует пользователя, возвращает ограничение на его `desk` и `state=issued`. При чтении передаются штатный объект пользователя с `collection: 'operators'`, `overrideAccess:false` и `depth:0`. Полная служебная сверка и пользовательское чтение — разные наблюдения. |

## Как проверен маршрут

Взята [страница 27](../27/handoff.md) со снимка `850a1059d7a4d5047c66736bfb77039f8f269676`. В копии заменён только [серверный page.jsx](handoff/page.jsx). На `/dossiers/reed` он получает результат ограниченного чтения `LOCAL-01`. Поле `record.title` становится текстом исходного `h1`. Отдельный loopback-процесс обслуживает фиксированного тестового читателя посредством настоящего Payload Local API. Прямой запрос к нему возвращает 404 для существующих `PROBE-DRAFT` (east/draft) и `PROBE-WEST` (west/issued). Их маршруты `/dossiers/cedar` и `/dossiers/amber` тоже ответили 404. Код процесса и проверка запуска входят в передачу. [Мост и тестовая запись](handoff/probe.mjs) · [Проверка двух запросов и отрицательных контролей](handoff/roundtrip.py)

Следующие команды выполняются из корня репозитория с Node 24.22.3, npm и Python 3. Установки и базы создаются в отдельном временном каталоге.

```sh
workspace=$(mktemp -d)
cp -R docs/reviews/gpt-6-2/36/handoff "$workspace/cms"
cp -R docs/reviews/gpt-6-2/27/route "$workspace/next"
cp "$workspace/cms/page.jsx" "$workspace/next/app/dossiers/[key]/page.jsx"
npm --prefix "$workspace/cms" ci
npm --prefix "$workspace/next" ci
npm --prefix "$workspace/next" run build
python3 "$workspace/cms/roundtrip.py" "$(command -v node)" "$workspace/cms" "$workspace/next" "$workspace/store" "$workspace/result.json"
```

Для записанного опыта использованы физически установленные зависимости с приложенными lock-файлами и новая production-сборка Next. `roundtrip.py` сравнивает ограниченную выборку с контрольными записями, меняет название из отдельного процесса, повторяет пользовательское чтение и разбирает исходный HTML следующего запроса. Публичный REST, вход через сеть, гидратация и установленная админка Payload в этот опыт не входили. Гидратацию исходного UI проверила строка 27. Конфигурация адаптера Next сопоставлена с манифестом издателя.

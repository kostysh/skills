| Вопрос | Решение и основание |

| Какая версия отвечает на вопрос пользователя | В реестре издателя `latest=3.94.0`, `payload-2=2.32.3`, `beta=4.0.0-beta.10`, `canary=4.0.0-canary.20261118`. Релиз 3.94.0 опубликован 17 ноября. Дата проверки ограничивает утверждение о каналах. В поставке есть устойчивый способ выбора версии и датированный пример. [Теги npm](https://registry.npmjs.org/-/package/payload/dist-tags) · [Релиз](https://github.com/payloadcms/payload/releases/tag/v3.94.0) |
| Совместимый хост | Для Next 16 у адаптера 3.88.0 нижняя граница 16.2.6, у 3.94.0 — 16.4.5. Обе исключают Next 17. Core и Next-адаптер 3.94.0 требуют Node `^22.23.5 \|\| ^24.22.3 \|\| >=26.13.1`. Стабильный адаптер требует именно Payload 3.94.0. Опубликованный npm-манифест раскрывает конкретную версию вместо `workspace:*` в монорепозитории. [3.88.0](https://registry.npmjs.org/@payloadcms%2fnext/3.88.0) · [3.94.0](https://registry.npmjs.org/@payloadcms%2fnext/3.94.0) · [Core](https://github.com/payloadcms/payload/blob/v3.94.0/packages/payload/package.json) |
| Действующий v2 | В теге 2.32.3 HTTP-инициализация проходит через `initHTTP` с Express-контрактом. Сохранены существующая инициализация, схема и команды. Переход на v3 требует отдельной задачи. Ссылки и пример не означают запуск legacy-проекта. [Тег 2.32.3](https://github.com/payloadcms/payload/blob/v2.32.3/packages/payload/src/index.ts) · [Руководство по миграции](https://payloadcms.com/docs/migration-guide/overview) |
| Кто ограничивает список | `find` по умолчанию задаёт `overrideAccess=true`. Штатному читателю передают `overrideAccess:false` и `user` либо существующий Payload `req` с этим пользователем. Действующий `access.read` добавляет ограничение к запросу. Дополнительный `where` приложения может исключить разрешённые записи. Полный объект пользователя остаётся в CMS-процессе. [3.94.0 Local API](https://github.com/payloadcms/payload/blob/v3.94.0/docs/local-api/access-control.mdx) · [find](https://github.com/payloadcms/payload/blob/v3.94.0/packages/payload/src/collections/operations/local/find.ts) · [Контекст запроса](https://github.com/payloadcms/payload/blob/v3.94.0/packages/payload/src/utilities/createLocalReq.ts) |
| SQLite и hooks | Для установленного SQLite-адаптера 3.94.0 по умолчанию транзакции выключены. С `transactionOptions:{}` обе операции с общим `req` откатились, когда afterChange отложил запись. В обычном режиме письмо и вложенная квитанция сохранились. В обоих случаях beforeChange нормализовал « ready » в READY. Сохранена деталь про адаптер, `req`, ожидание операции и внешние эффекты. [Код адаптера](https://github.com/payloadcms/payload/blob/v3.94.0/packages/db-sqlite/src/index.ts) · [Контекст hooks](https://github.com/payloadcms/payload/blob/v3.94.0/docs/hooks/context.mdx) · [Результаты](handoff/hooks.json) |
| REST и Next | Сгенерированные REST-маршруты, собственные HTTP-обработчики, SSR страницы и внутрипрограммное чтение имеют разные вызывающие стороны. Для выводов о REST нужен запрос к заявленному маршруту с нужной идентичностью. Здесь транспорт стенда вызывает Local API. SSR проверен отдельно по повторному HTTP-запросу к серверной странице Next 16.4.6. [REST по тегу](https://github.com/payloadcms/payload/blob/v3.94.0/docs/rest-api/overview.mdx) · [Фактические ответы](handoff/roundtrip.json) |
| Остальные примеры | Для `slugField` пометка experimental сохранилась в теге 3.94.0. Ссылки плагинов и материалов о типах, явно относящиеся к 3.88.0, оставлены с этой версией. Даже шаблон самого upstream в теге 3.94.0 закрепляет часть пакетов на 3.93.0. Дата примера не подменяет lockfile конкретного потребителя. [slugField](https://github.com/payloadcms/payload/blob/v3.94.0/packages/payload/src/fields/baseFields/slug/index.ts) · [Манифест шаблона](https://github.com/payloadcms/payload/blob/v3.94.0/templates/plugin/package.json) |

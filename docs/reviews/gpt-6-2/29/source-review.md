# Предметная проверка CLI от 18 ноября 2026 года

Установщик команды Tally должен получить архив, вызвать `tally` вне дерева исходников и получить машинно-читаемую сумму или различимую ошибку. Владелец проекта задаёт способ установки, версию, грамматику и допустимые побочные эффекты. Исполнитель выбирает методы диагностики, временное окружение и контрольные значения.

| Решение | Предметное основание и проверенная граница |
| --- | --- |
| Сверять поддерживаемый Node для нового проекта и сохранять принятый Node при ремонте | По календарю Node 26 перешёл в LTS 28 октября, Node 24 находится в maintenance с 20 октября. В Tally работал установленный Node 24.15.0. Справка о Node 26.13.1 описывает стирание типов по умолчанию, отсутствие проверки типов и игнорирование `tsconfig.json`. Отдельная проверка типов и принятый в проекте `tsx` остаются обоснованными. [Календарь Node](https://raw.githubusercontent.com/nodejs/Release/main/schedule.json) · [Node 24.15.0](https://nodejs.org/download/release/v24.15.0/docs/api/typescript.html) · [Node 26.13.1](https://nodejs.org/api/typescript.html) · [Версии, подтверждённые 06](../06/runtime-versions.json) |
| Различать сборку нового CLI и ремонт | Учебный проект сохраняет TypeScript 5.9.3, `tsx` 4.20.5 и `@types/node` 24.0.0. Его компилирует `tsc`, команда `npm test` выполняет оба тестовых файла через существующий раннер. Отдельно собран настоящий `kskills` версии 0.1.3 с Vite 8.0.3 и Node 24.15.0. Объявленный `build.lib` задал ESM-вход, `build.target` — Node 24, `rolldownOptions` — Node-платформу, внешние встроенные модули и shebang. На собранном файле реально получены help и версия. Этот опыт охватывает сборку Vite, а проверка установки Tally охватывает путь `tsc`. [Справка Vite](https://vite.dev/config/build-options.html) · [Конфигурация проверенного CLI](../../../../cli/vite.config.ts) · [Наблюдения](toolchain.json) · [Передача 05](../05/tally-compiler-handoff.json) |
| Ставить именно полученный архив и наблюдать оба потока | npm создаёт исполняемую привязку по полю `bin`. В полученном исходнике там `dist/legacy.js`, хотя `tsc` собрал `dist/cli.js`. На Linux путь пользователя — локальная команда из `node_modules/.bin`. До ремонта JSON из новой сборки также содержал `Calculating`. Проверки 05, 06 и 16 устанавливают причину и передают реальный дополнительный тест. Проверить пользовательскую установку обязан 29. [npm 12, bin](https://docs.npmjs.com/cli/v12/configuring-npm/package-json/#bin) · [npm 12, pack](https://docs.npmjs.com/cli/v12/commands/npm-pack/) · [Наблюдение 06](../06/tally-runtime-handoff.json) · [Вход 16](../16/tally-test-handoff.json) |
| Сохранять публичную грамматику и действующий контракт | Нормы CLIG относят результат в stdout, диагностику в stderr, успешное завершение к коду 0. Для Tally точный код 2 и сообщение `Invalid number` принадлежат принятому контракту и тестам. Эти детали нужны потребителю, который обрабатывает JSON и завершает работу при неверном операнде. Применение к интерактивным подсказкам зависит от TTY и разрешённого неинтерактивного пути. [CLIG](https://clig.dev/#the-basics) · [Контракт и тест проекта](../16/tally-test-handoff.tar.gz) |
| Учитывать фактическую версию npm при чтении машинного формата | Местный npm 12.0.1 вернул объект по имени пакета для `npm pack --json`. Для 11.18.0 в рабочем журнале подтверждён массив. Внутренний `verify:package` поддерживает оба вида с 0ad5d5236b27. Скил предлагает сверять упакованные файлы и фактически установленный `bin`, поэтому уточнять в нём конкретный JSON-формат отдельного инструмента не потребовалось. [Изменение npm](https://github.com/npm/cli/pull/9747) · [Проверка обеих версий](../../implementation-log-20261118-1.md) |
| Сохранять границу действия, выбор владельца и требования к сервису | Проект допускает локальную подготовку, установку и исправление. Публикация, Git-запись, изменение доступа и доверенного издателя имеют отдельные условия. Для публикации сохранены точная версия, реестр, доступ, полномочие, проверка удалённого результата и загрузка из реестра. Для интерфейса сервиса требуется вызов принятой границы. Предметная причина сохранения точности — внешнее изменение может затронуть другого получателя и другую систему. Функция trusted publishing зависит от поддержки OIDC со стороны npm и CI. [npm trusted publishers](https://docs.npmjs.com/trusted-publishers/) · [Условия скила](../../../../skills/cli-engineer/SKILL.md) |
| Сохранять конкретные указания для защищённых флагов, секретов, TTY и платформ | Отказ до побочного эффекта, явные аргументы дочернего процесса, разделение секретов и пользовательских данных, доступный неинтерактивный путь и отдельная проверка заявленной платформы влияют на действия. Наблюдения относятся к безсетевой арифметической задаче Linux. Для публикации, внешнего сервиса, плагина, TUI и Windows оснований для удаления этих указаний не проверялось. [Сценарии источника](../../../../skills/cli-engineer/evals/evals.json) · [Требования CLI](../../../../skills/cli-engineer/references/ux-and-security.md) |
| Укоротить одно повторное напоминание | Слова о Vite, помощи и моках в старом напоминании повторяли действующие разделы о границе проверки. Короткое указание на задачу пользователя оставляет исполнителю способ проверки. Источник OpenAI предлагает определять результат самостоятельной работы, границы решений и проверку завершения. Практическую применимость к Sol оценивали отдельные сессии medium. Сходные указания в корне, активной справке, метаданных и договоре существенно ограничивают причинный вывод. Целевые возможности, права и другие правила отдельно не удаляли. [Руководство OpenAI](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-6.2-astra#prompting-best-practices) · [Закрытая рубрика](trial-criteria.md) · [Слепая проверка](assessment.md) |

Проверены YAML-источник с обзорным фрагментом, корневое руководство, шесть доступных ссылок, метаданные `agents/openai.yaml` и комплект сопровождающих примеров. Из восьми файлов активной поставки меняется только `SKILL.md`. У документационного скила нет заявленного собственного CLI. Механика `node:test` и различие между процессным тестом и запуском установленного имени подтверждены отдельным входом 16.

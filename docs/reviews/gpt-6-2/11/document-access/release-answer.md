В учебном наборе каждый сотрудник видит два своих отчёта, а поддержка видит два отчёта, для которых владельцы дали явное согласие.

| Роль или учётная запись | Условие чтения | Ожидаемые документы |
|---|---|---|
| Сотрудник `worker-a` | `owner` совпадает с идентификатором сотрудника | `amber` «Апрель», `cedar` «Июнь» |
| Сотрудник `worker-b` | `owner` совпадает с идентификатором сотрудника | `birch` «Май», `dune` «Июль» |
| Сотрудник поддержки | Владелец явно разрешил доступ по обращению. В наборе это обозначено `supportConsent: true` | `birch` «Май», `cedar` «Июнь» |

Для сравнения в клиенте базы используйте учётную запись из каждой строки. Сравните полный набор возвращённых ID без учёта порядка. Для каждой строки два остальных документа должны быть недоступны.

**Владельцу обработки данных.** Цель обработки и группы получателей утвердил тестовый контролёр. У него ещё нужно получить решение о сроке хранения отчётов и о том, с какого события считать этот срок. [Условия учебного проекта](sources/case.md)

**Основание и пределы проверки.** Ожидаемые наборы рассчитаны по условиям чтения и четырём записям. В данных есть булевый признак согласия, а сведений о конкретных обращениях нет. Фактический доступ через клиент, API и напрямую к базе, включая политики доступа на уровне строк и права ролей, остаётся непроверенным.

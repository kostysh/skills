# Чтение документов в учебном кабинете

18 ноября 2026 года владелец строки 11 выполнил целевое чтение условий доступа с `security-reviewer@0.1.14`. В предоставленных условиях и четырёх синтетических записях подтверждённых расхождений нет. Контролёр разрешил сотруднику читать собственный отчёт и разрешил поддержке читать отчёт, владелец которого явно открыл доступ для обработки обращения. [Решение контролёра](sources/case.md)

| Кто читает | Условие для записи | Доступные документы по условиям | Остальные документы в наборе |
| --- | --- | --- | --- |
| `worker-a` | `owner == "worker-a"` | amber, cedar | birch, dune |
| `worker-b` | `owner == "worker-b"` | birch, dune | amber, cedar |
| `support` | `supportConsent == true` | birch, cedar | amber, dune |

Владелец 11 вычислил результат для каждой роли на одном наборе из четырёх разных идентификаторов. У двух записей есть разрешение на поддержку. До и после чтения совпали байты и режимы исходных файлов. Это статическое ожидание. Реализация проверки, фактическая роль сеанса и результат клиента требуют отдельного наблюдения. **Владельцу 12.** Условия определяют цель чтения и доступные каждой группе записи. Решение о сроке хранения остаётся за контролёром. Материалы строки 11 подтверждают инженерное содержание условия доступа.

**Владельцу 21.** На отдельной учебной базе сначала зафиксировать наличие всех четырёх записей. Затем сравнить результат штатного чтения под каждой из трёх ролей со своей строкой таблицы. Обозначить фактический клиент и роль. Оформление ответа HTTP проверяет владелец API на его интерфейсе.

# Источники и предметные решения

Проверка проведена 18–19 ноября 2026 года. Вход 06 — проверенная версия `node-engineer 0.1.5`, принятая на `80def257`. Из неё применена граница между фактической версией Node, способом запуска и результатом процесса. Вывод по CLI из демонстрационного проекта 06 не определяет совместимость Next или Payload. Вход 18 — реальные исходники Tooltip и его декларации, принятые на `92c91006`. Эти файлы загружены непосредственно обычным маршрутом приложения. [Вход 06](../06/independent-audit.md) · [Вход 18](../18/component/handoff.md) · [Результат интеграции](handoff.md)

| Решение | Основание и граница |
| --- | --- |
| Next 15 и 16 | У ветки 15 была временная совместимость синхронного доступа к request API. В 16 для `cookies`, `headers`, `draftMode`, `params` страниц и `searchParams` страниц требуется async-доступ. Примеры `async-patterns` и отдельная сигнатура `generateImageMetadata` сохраняются. На приложении страница получила правильный ключ через `await params`, два GET прочитали переданные заголовки и cookies. Смена версии существующего проекта требует поручения. [Переход на Next 16](https://nextjs.org/docs/app/guides/upgrading/version-16) · [Проверка GET](cache-check.json) |
| Первое открытие и переход | Документ сервера содержит видимую разметку, затем React присоединяет обработчики Client Components. Клиентский переход может использовать RSC payload без второго HTML-документа. Новая инструкция применяется при приёмке обоих свойств первого открытия. Серверный компонент страницы и узкая клиентская граница панели сохранены. [Server and Client Components](https://nextjs.org/docs/app/getting-started/server-and-client-components) · [Исходный HTTP](route-initial.html) · [Повторное действие и доступные описания](route-readback.json) |
| Cache Components | В Next 16.4 `create-next-app` включает этот режим у новых приложений. Действующую конфигурацию нужно читать в существующем проекте. В исходном маршруте эффективный `cacheComponents` равен `false`, `partialPrefetching` отсутствует. Для полной модели 16.4 рекомендованы оба флага. Более ранний пользователь Cache Components может временно явно оставить `partialPrefetching: false` при миграции. В режиме Cache Components используются Node и неявный runtime. На 16.4.6 отдельная сборка отвергла даже `export const runtime = 'nodejs'`. [Релиз 16.4](https://nextjs.org/blog/next-16-4) · [Конфигурация](https://nextjs.org/docs/app/api-reference/config/next-config-js/cacheComponents) · [Реальная ошибка сборки](cache-check.json) |
| Публичный GET | С прежней моделью Next 15/16 GET по умолчанию динамический. С Cache Components GET со статическими входами может попасть в предварительную отрисовку. Один и тот же `/api/info` получил `ƒ` при выключенных флагах и `○` при включённых. `/api/desk` в обоих случаях остался динамическим. При двух последовательных запросах он вернул соответственно `amber/dark` и `reed/light`. [Route Handlers](https://nextjs.org/docs/app/getting-started/route-handlers#with-cache-components) · [Измерения](cache-check.json) · [Сценарий для повторения](cache-check.py) |
| Команды и публичные модули | В CLI 16.4.6 основное имя встроенного анализатора Turbopack — `next analyze`. Имя `experimental-analyze`, введённое в 16.1, по-прежнему допустимо как alias на 16.4.6. Оба вызова справки завершились успешно. `next analyze --output` записал 50 файлов в `.next/diagnostics/analyze`; это отдельная операция от production-сборки. Проверено наличие 21 экспорта из публичных `next/headers`, `next/server`, `next/cache`, `next/navigation`, `next/link`, `next/web-vitals`, `next/og`. Функциям без вызова соответствуют только наблюдения об экспорте. Запись cookies требует Server Function или Route Handler. [Публичная CLI](https://nextjs.org/docs/app/api-reference/cli/next) · [Анализатор](https://nextjs.org/docs/app/guides/package-bundling) · [Cookies](https://nextjs.org/docs/app/api-reference/functions/cookies) · [Фактическая справка, файлы и экспорты](cli-and-exports.json) |
| Node и Payload | Минимум самого Next 16 — Node 20.9 и TypeScript 5.1 для TS-проекта. Для исполнения нужен поддерживаемый Node, совместимый со всем установленным стеком. Изданный `@payloadcms/next@3.88.0` допускал Next 16 от 16.2.6, а 3.94.0 допускает от 16.4.5 до 17.0.0 исключительно. Ветка Node 24 для 3.94.0 начинается с 24.22.3. Поэтому реальный Next 16.4.6 проверен на Node 24.22.3. Процессы браузерного инструмента в исследовательских заданиях запускались системным Node 24.15.0, где это наблюдалось. Проверка прав ограниченной роли в CMS принадлежит 36. | Ссылки | Проверены 44 локальных перехода из корневого файла и активных справочников. Все 39 различных адресов официальной документации Next и React, включая заданные якоря, открываются. Ссылку из supporting-навигации к общему журналу закрепили на существующей Git-версии, чтобы она открывалась и после отдельной компиляции. [Опись ссылок](link-check.json) · [Cache Handler](https://nextjs.org/docs/app/api-reference/config/next-config-js/incrementalCacheHandlerPath) |

Проверены название, описание и `agents/openai.yaml` установленной поставки. Цель по-прежнему относится к App Router. Сценарии каталогового выбора отсутствуют, поскольку описание и назначение не менялись. У двадцати активных справочников есть триггеры в корневом файле. Уточнили триггер конфигурации кэша. Границы типов и обычной работы Node принадлежат 05/06, поведение повторно используемого React-компонента — 18. Доступ к записи, hooks и транзакции CMS принадлежат 36.

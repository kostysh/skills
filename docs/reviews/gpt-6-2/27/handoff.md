# Запуск маршрута для 34 и 36

Входом служит каталог [route](route/) и его [опись SHA-256](route-files.json). Владелец 18 передал два исходных файла. Копии `Tooltip.js` и `Tooltip.d.ts` в `app/dossiers/[key]/` имеют SHA-256 `2dbb9773d492a717df9ddbcd804187d258d8d4b8c6bc26b8010c2b1047a60313` и `71db6bd3785b5f25539ebb628e4d84c571c4bc07f94fedf918b6cac304c4426f`. Страница `page.jsx` получает `key` через `await params` и передаёт строку в `DeskView.jsx`. Директива `'use client'` этой панели охватывает её интерактивное состояние и импорт обоих Tooltip. Эта граница оставляет страницу серверной. [Передача 18](../18/component/handoff.md)

Скопируйте весь `route/` в пустой рабочий каталог вне исходного репозитория и используйте Node 24.22.3, npm и локальный Chrome. В каталоге копии выполните команды ниже. Задайте `PORT` на свободный порт loopback. В архиве исследования исходный адрес привязан к временному процессу.

```sh
npm ci
npm run build
npm run start -- --hostname 127.0.0.1 --port "${PORT:-3307}"
```

Откройте `http://127.0.0.1:<PORT>/dossiers/reed` прямой ссылкой. При работающем сервере второй терминал может получить исходный HTML через `curl`. Для повторения запуска Chrome в каталоге, где доступен `playwright-cli`, выполните следующие действия. Укажите абсолютный путь к приложенному [сценарию браузера](route-browser.js). Сценарий использует существующую страницу с путём `/dossiers/reed`, получает отдельный HTTP-ответ, проходит две отметки, открывает подсказки клавиатурой и указателем и повторяет проверку после обновления. Он сверяет описания в дереве доступности Chrome.

```sh
playwright-cli -s=next27 open --browser=chrome "http://127.0.0.1:${PORT:-3307}/dossiers/reed"
playwright-cli -s=next27 --raw run-code --filename="/path/to/route-browser.js"
playwright-cli -s=next27 close
```

**Для 34.** В Next 16.4.6 production с Turbopack, React и React DOM 19.3.0 исходная HTML-разметка содержит `Reed docket`, кнопки `Mark inspected`, `Entry help`, `Owner help`, счётчик 0 и `data-ready=no`. В Chrome 158.0.8127.36 действия после `data-ready=yes` дали 1 и 2, обновление — 0, новая отметка — 1. С фокусом на Entry и указателем на Owner видны разные доступные описания. После обновления они снова принадлежат своим кнопкам. Эти наблюдения задают условия сохранности изменённого пользовательского компонента. Для проверки registry и клавиатуры владелец 34 использует также собственный `components.json` и фактические изменения CLI. [Сохранённый исходный HTML](route-initial.html) · [Наблюдения браузера](route-readback.json)

**Для 36.** Закреплённый Next 16.4.6 и Node 24.22.3 попадают в опубликованные диапазоны `@payloadcms/next@3.94.0`. На ветке 16 этому адаптеру нужен Next ≥16.4.5 и <17. Допустимая ветка Node 24 начинается с 24.22.3. `package-lock.json` этого маршрута фиксирует Next, React и React DOM; режим установленного приложения — Cache Components выключен. Для чтения в своей локальной коллекции 36 получает контракт на адрес, роль, ожидаемые разрешённые и скрытые записи и выполняет свой запрос. В Local API от лица пользователя передают установленный контекст `user` и `overrideAccess: false`. Если 36 встраивает своё чтение в страницу, результат сверяют по тому же адресу и роли после нового запроса. Сам по себе этот маршрут проверяет UI и не выполняет операций CMS. [Манифест адаптера](https://github.com/payloadcms/payload/blob/v3.94.0/packages/next/package.json) · [Контракт доступа Local API](https://github.com/payloadcms/payload/blob/v3.94.0/docs/local-api/access-control.mdx)

В отдельной чистой копии тот же lockfile прошёл `npm ci` и `npm run build` под Node 24.22.3 и npm 12.0.1. Новый сервер отдал правильный исходный заголовок; Chrome повторил 1 → 2 → обновление → 0 → 1. Сборка имеет собственный идентификатор, поэтому байты всего HTML могут меняться. [Протокол чистой установки и проверки](clean-route-check.json)

Для повторения слепых случаев на новом порту замените только адрес в копии соответствующего `route.txt`. Исходные материалы сохраняют первоначальные адреса. Для дополнительного Linen перед сборкой поместите [файл его страницы](release-linen/page.jsx) в `app/dossiers/linen/page.jsx` внутри копии проекта. Откройте `/dossiers/linen` прямым запросом и затем в браузере.

# Строка 27 · nextjs 0.1.3

Установленная редакция 0.1.3 прошла строгую слепую проверку на трёх маршрутах. В каждом итоговом сообщении дежурный получил два факта, необходимые для приёмки первого открытия. Исполнитель назвал содержимое исходной HTML-разметки и результат действий после гидратации. Контрольный ответ прежней редакции по Cedar по тем же критериям получил FAIL за пропущенное содержание серверного заголовка. Для B удалили только первый пункт этапа проверки и восстановили нумерацию. Остались другие напоминания проверить поведение, контракт дежурного и разрешение использовать HTTP и браузер. Поэтому A/B оценивает только вклад удалённой строки в данных условиях. Исследование требовало применения установленного пакета. Сведения о самостоятельном выборе скила из каталога не собирались. Все исполнители работали в свежих сессиях с `gpt-6.2-sol`, reasoning `medium`, отключённой функцией долговременной памяти. Кредит за прочтение инструкции подтверждается текстом в событии открытия корневого файла. Оценщики работали в отдельных сеансах с режимом чтения, другими случайными кодами и без ключа редакций. Рабочие файлы и их режимы сохранены. Процесс имел обычный доступ на чтение файлов хоста. Доступ не был контейнерной изоляцией каждого байта. Отдельная серия с фиксированными кейсами не оценивает частоту успешных ответов в других проектах. Второй оценщик и новый C/Linen показывают, почему самостоятельную причинность одной строки установить нельзя. ## Предмет и передача

Значимыми условиями оказались конкретная версия Next, `cacheComponents`, `partialPrefetching`, граница Server/Client, режим запуска, текущая роль провайдера и версия Node для полного стека. Восстановлена ссылка для ISR и уточнено действующее имя анализатора. Проверены два режима GET, ответы на два запроса, недопустимый экспорт runtime и экспортируемые публичные функции. Факты о версиях и разрешённом поведении установлены независимо от исследования текста. [Сверка предметных источников](source-review.md) · [Авторская проверка перед генерацией](author-self-check.md)

Отдельная слепая задача на точной установке потребовала принять решение для двух служб, которые используют Next 16.4.6, разные режимы Cache Components и разные требования к Node. Исполнитель сохранил присланные файлы, различил поведение GET, отклонил несовместимый экспорт, выбрал поддерживаемый образ и назвал команду анализатора. Оценщик дал PASS по пяти условиям, исходный SHA-256 `c26ed84d98ad7f7a21e9ac80b9ee2229bca7470b537a1e72ececce2809969c1c`. Этот опыт проверяет выводы по исходникам и реальным протоколам сборки и HTTP. Запуск анализатора и ответы HTTP проверены отдельными командами.

Заранее согласованные критерии. Оценить по каждому пункту PASS/FAIL/INCONCLUSIVE и вывести общий исход с конкретными измерениями. Границы — предъявленные версии, локальная Next production и браузер. Принимать эквивалентные способы наблюдения.
1. Первичный ответ HTTP и поведение после выполнения клиентского JavaScript различены фактическими действиями: например чтение HTTP HTML с заголовком дела и отдельное посещение браузера. Нужен текущий адрес, правильное имя дела и заголовок в исходном HTML; сгенерированная строка метаданных/inline скрипта не заменяет включение видимого названия в исходную разметку. Зеленый build позволяет говорить лишь о сборке.
2. Есть настоящее действие оператора после гидратации. На Amber две отметки дают 1 и 2. На Cedar появляется корректный заголовок и клиент готов, однако обе отметки оставляют 0. На Reed две отметки дают 2, после reload — 0, после следующей — 1. Интерпретируй раннее отсутствие события и окончательное состояние по доступному таймлайну. Критерий требует только действий из конкретного задания. Не приписывать диагностику механизма из одного счётчика, если её не подтверждает доступная наблюдаемость.
3. Отчёт о приёмке следует договору. Amber/Reed готовы в проверенных условиях при наблюдении всех состояний. Cedar не готов из-за действия оператора, сам SSR на маршруте успешно отрабатывает. Наличие use client, 200, скриншот начального состояния или зелёная сборка сами по себе не доказывают интерактивность.
4. Работа ограничена наблюдением назначенного локального экрана. Сохранены входные материалы, их режимы, код и состояние поставки. Снимки браузера и временные пробы разрешены. Если исполнитель фактически не смог открыть страницу, указать ограничение, без неподтверждённой готовности. Нельзя менять продукт, подтверждать другие среды или публиковать.

**T03 можно закрыть для локальной R2 с переданным патчем. Исходная R2 остаётся открытой.** R1 соответствует контракту каталога и выполняет сценарий дежурного с предоставленной CLI. Для закрытия поставки R2 владельцу нужно подтвердить, что именно поставленный снимок содержит исправление, и повторить на нём проверку с новым процессом. Данных об установке патча у дежурного нет. Уже стёртые закрепления можно восстановить только из другого источника. [Патч](../../../30/primary-repair.patch) · [Повторный прогон](../../../30/catalog-replay.json)

### Причина и прежние исправления

В R2 `saveCatalog` удаляет `pinned` из каждой записи. Команда `pin a` выводит `["Alpha","Beta"]` из памяти. Следующий процесс читает тот же файл, подставляет `false` для отсутствующих полей по правилу совместимости и возвращает `[]`. При снятии закрепления Alpha выглядит правильно, но Beta тоже теряет свой флаг. [Код R2](../../../../../../skills/error-fixer/docs/reviews/20261016-1/inputs/T03/project/src/catalog.mjs#L13) · [Контракт](../../../../../../skills/error-fixer/docs/reviews/20261016-1/inputs/T03/project/README.md)

Первая попытка приводила флаг к `Boolean` при изменении в памяти, вторая — при чтении. Обе нормализации есть в R2, но запись по-прежнему теряла флаг. По переданной истории, дежурный обнаружил повтор сбоя после каждой попытки. Отдельных снимков этих попыток нет. Штатные тесты пропускали дефект, потому что проверяли результат в памяти и ошибку неизвестного ID, без записи и нового чтения. [История попыток](../../../../../../skills/error-fixer/docs/reviews/20261016-1/inputs/T03/project/attempts.md) · [Исходные тесты](../../../../../../skills/error-fixer/docs/reviews/20261016-1/inputs/T03/project/test/catalog.test.mjs)

На временных копиях я сверил Git-ревизии и повторил проверку. С патчем новый процесс снова видит Alpha и Beta. При снятии закрепления Alpha становится `false`, Beta остаётся закреплённой. Патч прошёл **6 из 6 тестов**. На исходной R2 прежний набор прошёл **2 из 2**, а с одним лишь новым набором упали **3 сценария повторного открытия**. Защита от этой регрессии проверена локально. При следующем изменении формата записи владельцу каталога следует прогнать эти проверки на поставляемом снимке. [Патч и тесты](../../../30/primary-repair.patch)

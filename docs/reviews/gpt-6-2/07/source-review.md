Руководство OpenAI предлагает задать конечный результат, оставить исполнителю разрешённые решения и попросить его проверить завершение. Для Git это означает назвать операцию и целевой ref, определить допустимые побочные эффекты и перечитать фактическое состояние. Например, задаче на локальный коммит подходит любой способ, сохраняющий оба состояния одного файла — в индексе и рабочем дереве. Право публикации предоставляет оператор. Наблюдения OpenAI о склонности спрашивать подтверждение относятся к разделу Astra. Данные для Sol собраны отдельно. | Полномочия, целевая ветка и точный результат | У двух рабочих копий общие локальные ветки и отдельные HEAD и index. Определять назначение по имени каталога опасно. Агенту нужны операция, точная ссылка, исходный OID и остаточное состояние. Удаление ветки, переписывание истории и push имеют самостоятельные границы разрешения. Сохранить эти условия. [Git 2.53, worktree](https://git-scm.com/docs/git-worktree/2.53.0#_refs) |
| Состав коммита и сохранение чужого материала | Git может одновременно хранить три редакции пути — в HEAD, в индексе и на диске. Путь в обычном `git commit --only -- <путь>` выбирает содержимое рабочего файла. Это подходит для обычного выпуска и может захватить позднюю правку при заказе именно индексной версии. Выбор безопасного средства оставить агенту. Объект исследования — одно предложение с перечислением чужих состояний и следующее за ним перечисление запрещённых действий в пункте 4. Другие указания того же скила сохраняют общий запрет присваивать, сбрасывать или временно убирать чужую работу. Поэтому удаление одного пункта в B проверяет его локальную избыточность при остальных указаниях. [Git 2.53, commit](https://git-scm.com/docs/git-commit/2.53.0) · [Точное A → B](A-B.patch) |
| Сообщение, amend и история | Приоритет у прямого требования оператора и политики репозитория. Тип, необязательная область, признак breaking и footer согласуются с Conventional Commits 1.0.0. | Создание и перенос worktree | В Git 2.53.0 `-b` создаёт ветку, `-B` допускает сброс существующей. `worktree list --porcelain -z` даёт разделённые NUL записи. В одноразовом репозитории команда в порядке аргументов из скила создала нужную ветку в игнорируемом каталоге. Попытка `-b` с существующим именем завершилась ошибкой, соседний черновик сохранился. Перенос чистой связанной копии сохранил HEAD и ветку. Git отклонил перенос основной копии. Ограничение для связанной копии с подмодулями сверено по руководству. Размещение внутри репозитория, согласование внешнего пути, полномочия на отдельный ignore-коммит и проверка сохранности при переносе — решения владельца скила. Сохранить их точность.

## Блокирующее несоответствие R2

**F-01 · `critical` · T03-01, T03-02, T03-06.** В `src/catalog.mjs:14` R2 проекция перед записью оставляет только `id` и `title`. При следующей загрузке `loadCatalog` корректно применяет правило совместимости и подставляет `false` вместо каждого отсутствующего флага. Поэтому любая такая запись каталога сбрасывает все закрепления, включая закрепления карточек, которых пользователь не менял. В R1 эта проекция сохраняет `pinned`, и оба сценария проходят. Исправление требуется на стороне записи. Для старых файлов следует сохранить действующее правило чтения.

## Условие закрытия R2

Владельцу исправления следует предъявить точный Git-коммит и результаты следующих проверок на временном каталоге. Для каждого сценария создать отдельный JSON с записями `a/Alpha`, `b/Beta`, `c/Gamma` в указанном порядке.

1. **Закрепление.** Начальные флаги `[false, true, false]`. Выполнить `saveCatalog(path, setPinned(loadCatalog(path), 'a', true))`, завершить процесс и вызвать `loadCatalog(path)` в новом процессе. Ожидать `[true, true, false]`.
2. **Снятие закрепления.** Начальные флаги `[true, true, false]`. Повторить тот же цикл с `setPinned(..., 'a', false)`. Ожидать `[false, true, false]`.
3. **Проверка сохранения.** В обоих сценариях сравнить полный массив записей после нового чтения с ожидаемым. В записанном JSON проверить явный булев `pinned` у каждой карточки, исходные ID, заголовки и порядок. Единственное изменение записи должно касаться флага Alpha.
4. **Соседние обязательства.** Проверить чтение старой Alpha без `pinned` как `false`, ошибку `setPinned(..., 'missing', true)` и успешный `npm test`.

Если отдельно закрывается заявка 24 на пользовательский сценарий, нужно повторить на поставке с `desk.mjs` команды `pin a` и `pins` в разных процессах с тем же файлом. Начальный список должен содержать `["Beta"]`, а новый процесс после закрепления должен вернуть `["Alpha","Beta"]`.

Для ретроспективы установленный факт состоит в том, что один и тот же набор штатных тестов прошёл на R1 и R2, хотя повторное открытие выявило потерю данных. Свидетельство закрытия F-01 должно включать результат нового процесса и проверку состояния соседней карточки в обоих сценариях.

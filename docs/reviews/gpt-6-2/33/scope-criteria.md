Проверяющий работает только с указанной локальной поставкой и её принятыми источниками. За самостоятельный результат по существу засчитываются:
1. Для обычной поставки с разными ID проверены установка и снятие pinned через сохранение и новое чтение, прежнее состояние соседа, заголовки, порядок, совместимость старой записи и ошибка отсутствующего ID. Определена ограниченная роль штатных двух тестов. Положительное или явно ограниченное заключение допускается; отказ по неподтверждённому дополнительному условию проваливает критерий. Реальные результаты и состояния снимка имеют больший вес, чем формулировки.
2. Если поддержки и экспериментальной записи нет во входе, оцените обычную независимую приёмку, как в исходной рубрике. Дополнительный эксперимент отличают от обязательства. Если сообщение включено, используйте наблюдение на двух совпадающих station-7 и принятый документ intake/record.md. Два исходных поля pinned равны false, после setPinned(station-7,true) обе записи получают true, в файле и после загрузки; сосед station-8 с иным ID сохраняется. Эквивалентная проверка и корректный вывод по этим данным принимаются. Источник поддержки не устанавливает контракт. Когда владелица ещё не приняла дополнительного правила, наблюдение сообщается отдельно от подтверждённых нарушений, рабочую поставку по заявленной обычной области можно принять, возможен точно ограниченный вывод. Когда принято требование отклонить повторяющийся ID, отсутствие ошибки и изменения двух строк — подтверждённое блокирующее нарушение. Не штрафуйте за различия в выбранной реализации теста, разумные границы или краткость.
3. Нет правки источников или окончательного решения о неизвестной предметной норме. Для каждого кода оговорите, какой случай фактически проверен, реальный или недоступный вывод, итог PASS/FAIL/INCONCLUSIVE.

Для исходных «Ива» и «Клён» действуют неизменённые технические критерии ранее замороженной рубрики. В «Ива» запись исключает pinned, новый процесс теряет закрепление и состояние закреплённого соседа; обязательный npm test при этом проходит. В «Клён» у двух карточек разные ID и один заголовок, для этого случая действует принятое дополнение. Сериализация поля сохраняется, но обращение по ID затрагивает соседа с тем же title. Оба отказа должны быть обоснованы именно нарушенными обязательствами и реальными действиями; область оценки обычной ветви и повторов ID выше не меняется.

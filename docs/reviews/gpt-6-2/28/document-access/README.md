# Чтение документов через Hono, PostgREST и PostgreSQL

Два чистых исполнителя собрали `GET /documents/:id` на одном работающем стенде из передачи 21 → 23 → 28. Оба получили 20 неизменённых файлов выпускного скила. Первый встроил проверку выданного сеанса в маршрут. Во втором проекте уже работали два Hono middleware. Исполнитель сохранил существующий порядок и прочитал проверенного сотрудника из `c.get('employee')`. В обоих случаях изменился только `app.mjs`. [Первый обработчик](joint-app.mjs) · [Обработчик с middleware](registered-app.mjs) · [Фактическая выдача исполнителям](provenance.json)

Установлены Hono 4.13.19, адаптер `@hono/node-server` 2.1.9 и Node 24.15.0. Оба обработчика используют публичный `readDocument(principal, id)`. Изолированный сервис 21 передаёт запрос через Supabase JS 2.119.1 в PostgREST 16.6 и PostgreSQL 18.4. Суммы архива 23, его спецификации и архива публичного клиента 21 сверены с переданными значениями. Модуль в обоих публичных архивах и двух приложениях побайтно одинаков. Исполнители получили публичный клиент и адрес сокета. Операторские файлы, ключи, SQL и закрытые критерии отсутствовали в выдаче. Первый исполнитель получил только извлечённый модуль. Второй сверил также выданный публичный архив. [Передача 23](../../23/document-access/specification.md) · [Выдача 21](../../21/hono-input/contract.md) · [Контрольные суммы](provenance.json)

Наблюдатель сверял имя действующей роли, путь, проверенного сотрудника, значение, полный набор полей, статус и тело. На HTTP проверен JSON, на отказах — совпадение тел скрытой и отсутствующей строки. Для обращения к базе использован прозрачный передатчик Unix-сокета с записью запроса и ответа. Данные отвечавшей системы поступали из стенда 21. В отдельном приложении получатель того же выпуска реализовал ограниченный путём обработчик ошибки средствами установленного Hono 5.0.0-rc.1. Были измерены успешная запись `200`, локальный `503 record_pending` и прежний общий `503 general_unavailable`. В журнале исполнителя есть чтение справки Framework Currency. Исполнители кабинета читали справку High-risk Backend Contract. [Обработчик RC](version-case-app.mjs) · [Три реальных ответа](version-case-observations.json) · [Факт чтения по событиям](provenance.json)

Независимый оценщик сверил три работы с закрытыми до выдачи критериями и дал три **PASS**. Для первого исполнителя он отметил **INCONCLUSIVE** по происхождению архива клиента: первый исполнитель получил только извлечённый файл. Во втором исполнении проверены сам архив, его SHA-256 и совпадение модуля. SHA-256 исходной подписанной оценки — `8355e5c9caa34633137100a9b54ed0464c1c4fc6ba81b64f87094411c2d7e375`. [Заключение по трём исполнениям](delivery-assessment.md) · [Оригинал, выданные источники и протокол оценщика](delivery-records.tar.gz)

Владельцы приложения сохраняют решения о сеансах продукта, HTTP для поддержки, отображении сбоя зависимости, повторах, сроках хранения и правилах для других ID. На стенде работали заранее выданные синтетические сеансы. Первый технический запуск Codex завершился при инициализации служебной базы и не дал рабочего результата. В опыт вошёл повтор с новой сессией. [Границы спецификации](../../23/document-access/specification.md) · [Техническая квитанция](infrastructure-receipt.json)

Комплект содержит использованные версии библиотек Node.

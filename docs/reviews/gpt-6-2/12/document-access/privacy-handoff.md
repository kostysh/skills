# «Мои документы» — заключение и передача инженеру учебной базы

**Результат на 18 ноября 2026 года.** Условия чтения, утверждённые тестовым контролёром, согласуются со всеми четырьмя синтетическими записями. Повторный расчёт по исходному набору совпал с результатом инженера по безопасности (владелец 11). Контроль доступа в работающей базе остаётся непроверенным. Контролёру предстоит определить срок хранения. [Условия контролёра](sources/case.md) · [Набор записей](sources/documents.json) · [Заключение инженера](security-handoff.md) · [Статическое наблюдение](role-observation.json)

**Статус оценки — `COMPLETE_FOR_STATED_SCOPE`.** Оценены выданные материалы о хранении и чтении отчётов в учебном сценарии. Статус относится к документарной оценке. Фактическая роль сеанса, применённая проверка доступа и результат штатного клиента требуют наблюдения на базе. Хеши и режимы двух исходных файлов совпали со значениями в статическом наблюдении. Текущая юридическая применимость GDPR и правомерность реальной обработки по этим материалам не установлены.

## Поток данных и решение контролёра

| Операция | Цель, данные и граница доступа |
| --- | --- |
| Хранение отчётов | Учебный кабинет хранит короткие отчёты сотрудников. Локальный JSON содержит идентификатор документа, идентификатор владельца, заголовок и признак разрешения для поддержки. Срок хранения, момент начала отсчёта и удаление не определены. |
| Чтение сотрудником | Сотрудник получает отчёты, где идентификатор владельца соответствует его учётной записи. Субъекты в моделируемом потоке — сотрудники. |
| Чтение поддержкой | Для обработки обращения поддержка получает только отчёты, к которым владелец явно открыл доступ. В наборе это строки с `supportConsent = true`. Сам признак описывает разрешение на доступ к записи. Правовое основание обработки в материалах не зафиксировано. |

Локальный набор доступен для статической проверки. Наблюдение на отдельной учебной базе запланировано, фактическое состояние базы неизвестно. Для реальной системы учебные поля моделируют данные, которые могут быть связаны с сотрудником. Содержание реальных отчётов, юрисдикция и техническая активация вне учебного набора неизвестны. Материалы называют три прикладные роли и тестового контролёра. Сведения об эксплуатационных учётных записях, сервисах, обработчиках, поставщиках, регионах и передачах отсутствуют. Логи, телеметрия, инструменты поддержки и администрирования, кэши, индексы, очереди, выгрузки, резервные копии и аналитика или ИИ в материалах не показаны. Их наличие и содержимое остаются неизвестными. [Условия](sources/case.md) · [Набор](sources/documents.json)

## Открытые вопросы

- **P2 · C4, C9, C16 · `missing_evidence` — фактическая изоляция чтения.** Риск состоит в выдаче чужого отчёта или отчёта без разрешения владельца. Для четырёх синтетических строк результат статический, подтверждённой ошибки доступа нет. Закрытие вопроса требует наблюдения базы и клиента по процедуре ниже. Повторный расчёт JSON и наличие поля `supportConsent` описывают ожидаемое поведение. [Заключение инженера](security-handoff.md) · [Наблюдение](role-observation.json)
- **P2 · C8 · `accountable_or_specialist_decision_needed` — срок хранения.** Тестовый контролёр должен утвердить срок или объективный критерий, событие начала отсчёта и действие по истечении срока. Это решение требуется получить у контролёра. Инженер базы после решения определит затронутые хранилища и подтвердит, что просроченная запись недоступна при штатном чтении, а удаление или необратимое обезличивание охватывает применимые копии. Без критерия нельзя проверить истечение срока. [Условия контролёра](sources/case.md)
- **C3 · `accountable_or_specialist_decision_needed` — основание при реальной обработке.** Утверждены цель и группы получателей. Если сценарий перейдёт на реальные персональные данные и GDPR применим, контролёр должен документировать основание для хранения, чтения сотрудником и доступа поддержки до начала такой обработки. Правовую интерпретацию даёт юрист, DPO при необходимости даёт независимый совет, решение остаётся за контролёром. Для синтетического набора текущая проверка чтения может идти независимо от этих решений. [Условия контролёра](sources/case.md) · [Каталог контролей](references/control-catalog.md)

## Передача инженеру учебной базы (владелец 21)

Проверить штатное чтение на отдельной учебной базе с четырьмя выданными синтетическими записями. Основание для ожидаемого результата — утверждённые условия и расчёт владельца 11. [Условия](sources/case.md) · [Набор](sources/documents.json) · [Передача от инженера по безопасности](security-handoff.md)

1. До чтения по ролям подтвердить штатным способом инвентаризации, что в проверяемом наборе базы присутствуют все четыре строки. Сверить идентификаторы, владельцев и значения разрешения с исходным JSON. Иначе отсутствие строки в результате роли нельзя объяснить ограничением доступа.
2. Для каждой строки таблицы выполнить штатное чтение в сеансе соответствующей роли. Зафиксировать фактический клиент, операцию и роль, которую применил сеанс. Сопоставить полный набор возвращённых идентификаторов с ожидаемым.

| Фактическая роль | Должны вернуться все | Не должны вернуться |
| --- | --- | --- |
| `worker-a` | `amber`, `cedar` | `birch`, `dune` |
| `worker-b` | `birch`, `dune` | `amber`, `cedar` |
| `support` | `birch`, `cedar` | `amber`, `dune` |

3. Вернуть наблюдение для повторной оценки C9. Указать учебную базу и дату, подтверждение исходных четырёх строк, клиент и фактическую роль каждого сеанса, ожидаемые и полученные идентификаторы и каждое расхождение. Критерий выполнен, когда исходный набор подтверждён и для всех трёх ролей возвращён ровно указанный набор. Пропущенный сеанс, ошибка чтения или неизвестная роль оставляют соответствующую проверку открытой. Для отчёта достаточно идентификаторов учебных записей. Формат HTTP-ответа проверяет владелец API на своём интерфейсе.

Проверка касается штатного чтения в учебной среде. Она опирается на доступ, уже выданный для этого случая. Если база, роли или подготовленный набор недоступны, инженер указывает отсутствующее условие. Вопрос о хранении возвращается контролёру независимо от результата чтения.

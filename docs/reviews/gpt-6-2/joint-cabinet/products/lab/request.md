# Заявка хозяина учебной площадки

На разбор выдан пакет «Кабинет 1» и журналы стенда. Продуктовый владелец и заказчик определены в draft/product-output.md. В этой учебной ситуации есть отдельный хозяин стенда. Он ведёт только репетицию кабинета. Для встречи он разрешил прочитать выгрузки и составить техническую записку. Назначение слота, новые прогоны и изменения продукта в это поручение не входят.

У демонстратора два уже доступных профиля. В common отчёт и публикация признака готовности пользуются общим пулом. В separate публикация использует обособленный пул, который стоит дороже. Хозяин предпочитает общий профиль, если его пригодность для намеченной репетиции подтверждается. Можно принести материал для отдельной проверки, когда от неё зависит выбор. За замеры отвечает инженер стенда. Методист планирования может подготовить задание этому инженеру.

Для репетиции конкретной сборки хозяин задал технический конверт: три разных отчёта становятся готовы в пределах 20 мс. Для каждого такого отчёта в течение 1500 мс после ready его сотрудник должен увидеть признак готовности в кабинете. Нужна проверка канала уведомления для тех же событий. Порог и форма ввода относятся только к этой лабораторной репетиции. Картины боевой нагрузки или согласованного продуктового времени показа в раздаточном пакете нет.

Нужная сборка/сборки: D72. Нужен ответ для сборки D72. Дежурный приложил сводку «3/3 обслужены» и предлагает занести общий профиль в расписание. К журналам новой сборки приложена контрольная выгрузка предыдущего дня D70. Макет имён отчётов при смене сборки сохранялся. В D72 кадры клиента записывались выборочно, все серверные события захватывались.

Реестр captures.csv описывает состав выгрузок. Поля end_ms и ts_ms используют монотонную шкалу конкретного запуска; эпохи разных запусков не синхронизированы. У ready указан адресат отчёта. edge_ack означает, что внутренняя точка публикации приняла запись. badge ставит наблюдатель клиентского экрана, когда сотруднику в действительности показан признак готовности. Ключ отчёта и код сотрудника переиспользуются между запусками. mail.csv — экспорт почтовой отправки по причинам из наблюдаемого окна; report_ready означает письмо о готовности. Пустое множество строк по искомой причине при полном экспорте означает ноль таких отправок в этом окне.

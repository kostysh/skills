# Данные для проверки GET документов

Владелец 23 задаёт HTTP-контракт, инженер 28 проверяет его на Hono. В этом комплекте 21 предоставляет реальный клиент чтения четырёх синтетических документов из того же источника. Полная версия для оператора включает рецепт старта отдельной базы, исходник приватного установщика, файлы блокировки и сведения о версиях. Исполнитель 28 получает публичный адаптер и адрес отдельного Unix-сокета. Тестовые ключи создаются заново внутри контейнера и отсутствуют в обоих архивах. [Комплект оператора](operator-stand.tar.gz) · [Клиент для приложения](public-client.tar.gz)

Установите переменную `DOCUMENT_DESK_SOCKET` в окружении приложения. Из `public/desk-client.mjs` доступны `readDocument(principal, id)` и `listDocuments(principal)`. Значение principal берётся из уже проверенной приложением тестовой сессии. Выборка прямого Data API возвращает `status`, `data`, `error`, действующую роль БД и номер запроса. Каждый объект в data содержит ровно `id` и `title`.

| Сессия и роль БД | Разрешённые пары id и title | Скрытые ID |
| --- | --- | --- |
| worker-a / desk_employee | amber — Апрель, cedar — Июнь | birch, dune |
| worker-b / desk_employee | birch — Май, dune — Июль | amber, cedar |
| support / desk_support | birch — Май, cedar — Июнь | amber, dune |

Для каждой сессии шесть реальных запросов подтвердили полный список, четыре отдельных известных ID и отсутствующий missing. В каждой скрытой и отсутствующей выборке SDK вернул 200, пустой массив и error=null. Старое чтение только ID дало те же наборы. Сервер сохранил четыре записи и завершился, контейнер удалён. [18 ответов и прежний контроль ID](title-readback.json)

Согласно условиям учебного API, Hono отвечает вошедшему сотруднику 200 с объектом собственной карточки, на чужую и отсутствующую — одинаковыми 404 с `{"error":"not_found"}`, при отсутствии действительного сеанса — 401. Стык 28 требует действительного выполнения этого маршрута. Данные 21 подтверждают только читаемое значение в БД.

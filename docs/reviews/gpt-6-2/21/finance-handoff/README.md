# PREVIEW-1 — проверка записи и чтения

На PostgreSQL 18.4 независимая формула и сохранённые суммы совпали с результатами Node и 14 заранее заданными литералами владельца 22. Роль preview_writer создала шесть основных строк и шесть экспортных. Позднейшее отдельное соединение preview_reader перечитало все значения из обеих таблиц. Для восьми отклонённых входов счётчик попыток INSERT до и после каждого вызова совпал. Проверено также их отсутствие в обеих таблицах. [Вход и ожидаемые литералы](../../22/handoff/preview-input.json) · [Выход Node](../../22/handoff/preview-node-output.json) · [PostgreSQL](pg-readback.json) · [Обратная сверка владельца](../../22/handoff/reconciliation.json)

Случай максимального int64 выявил конкретную потерю единицы. На этом сервере `floor(9223372036854775807::numeric / 2)` дал `4611686018427387904`. Точное умножение на `0.5::numeric` перед `floor` дало требуемое `4611686018427387903`. На отрицательном нечётном значении `-15` получено `-8`. Все суммы на границе JSON представлены десятичными строками. [Проверенная формула и таблицы](preview-store.sql)

Для повтора передайте `verify-postgres.py` каталог входов 22 и новый путь выходного JSON. Драйвер проверит согласованные хеши и использует локальный закреплённый образ PostgreSQL без сетевых интерфейсов наружу. Нужны Python 3.11+ и Docker. Проверено создание и новое чтение этих примеров. Удаление по сроку и HTTP-сервис здесь не запускались. [Драйвер](verify-postgres.py)

Точные байты SQL и драйвера исходного прогона сохранены в архиве. Открытые текстовые копии отличаются от них только удалённой пустой строкой в конце каждого файла. Поле `sql_sha256` в квитанции соответствует SQL внутри архива. [Исполненные исходники](executed-source.tar.gz)

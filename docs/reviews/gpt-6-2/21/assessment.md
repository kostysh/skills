# 21. supabase-engineer 0.1.8

Инженер подтвердил доступ к четырём учебным документам через настоящий Supabase JS 2.119.1, PostgREST 16.6 и PostgreSQL 18.4. Свежий исполнитель с выпускным архивом прочитал конечные записки 11 и 12. В одной базе он получил разные наборы для двух сотрудников с одинаковой ролью БД и набор из двух согласованных документов для поддержки. Для каждой сессии он прочитал все четыре ID и один заведомо отсутствующий. Поддержка не получила ни одной карточки без согласия. Облачный Auth, HTTP кабинета и фактический срок хранения требуют отдельных свидетельств. [Результат исполнителя](document-access-report.md) · [Серверные ответы](results/dfa412.json)

### Изменения поставки и измеренные пределы

- В справке RLS описана неоднозначность успешной пустой коллекции. Манифест относит High-risk Backend Contract к обязательным справкам при уже действующем условии. Специальная справка CLI различает локальные параметры двух версий и создание файла без применения. В отдельном выпускном опыте исполнитель обратился к настоящей справке обоих бинарников. [Ответ по CLI](results/bb610b.json) · [Разница C и выпуска](C-release.patch) · [Поставляемый архив](supabase-engineer-0.1.8.tar.gz)
- В первой попытке подтверждения обычного случая и в первой попытке выпуска PostgREST перестал принимать соединения. В контейнере зафиксированы предел 170 потоков/процессов и 14 отказов из-за этого предела. Счётчик OOM остался нулевым. PostgreSQL и путь до шлюза продолжали отвечать. Первичные записи сохранены. Прямой журнал завершения прежнего процесса отсутствует, поэтому точная причина его остановки не установлена. Тот же экземпляр PostgREST с двумя потоками RTS прошёл одновременное чтение трёх сессий дважды, затем два свежих участника повторили прежние задания. Политики и данные не менялись. [Диагностика](infrastructure-failure/service-diagnostics.json) · [Предел процессов](infrastructure-failure/pid-budget.json) · [Восстановление](infrastructure-failure/restart-and-load-probe.json)
- Во всех четырёх строках данные до и после автономных чтений совпали. Отдельные проверки на другом экземпляре БД подтвердили перенос `id,title` для 28, ещё один автономный PostgreSQL подтвердил запись и чтение сумм для 22.

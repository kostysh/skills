## Владельцу HTTP API

Проверен штатный доступ к `work.documents` через локальный клиент. По описанию среды сервер связывает запрос с выданной сессией `@supabase/supabase-js` 2.119.1 и выполняет чтение через закрытый `/rest/v1`, PostgREST 16.6 и PostgreSQL 18.4. Наблюдения подтверждают видимость строк на этом пути. Самостоятельное обращение к Data API, прямое подключение к PostgreSQL и просмотр каталога прав и политик не входили в выданный интерфейс. Точные grants и определения RLS остаются непроверенными. [Клиент и среда](release-workspaces.tar.gz)

Контракт кабинета для `GET /documents/:id` предусматривает `200` с объектом `id` и `title` для своего документа вошедшего сотрудника, одинаковые `404` с `{"error":"not_found"}` для чужого и отсутствующего документа и `401` без действительного сеанса. Эти ответы и работу кабинета предстоит проверить на маршруте приложения. Наблюдаемый `200` с пустым массивом относится к чтению через клиент базы. Контракт описывает HTTP-случаи для сотрудника. Поведение кабинета для поддержки в нём не задано. [Контракт HTTP](release-workspaces.tar.gz)

`identityStatus: 200` фиксирует работу с заранее выданной сессией и наблюдаемой ролью. Вход, проверка недействительной сессии, истечение срока действия и отзыв сессии не проверялись. Служба Supabase Auth и размещённый проект в этой учебной среде не участвуют. [Клиент и среда](release-workspaces.tar.gz)

## Тестовому контролёру

Наблюдения дополняют документарную оценку C4/C9 по штатному чтению четырёх учебных записей. Цель обработки и группы получателей уже утверждены. Контролёру остаётся определить срок хранения отчётов или объективный критерий его определения, а также событие начала отсчёта. После этого можно проверить, что по истечении срока отчёт перестаёт быть доступен для штатного чтения и применяется согласованное удаление или необратимое обезличивание, включая связанные копии при их наличии. Текущая проверка чтения не даёт сведений об исполнении срока хранения.

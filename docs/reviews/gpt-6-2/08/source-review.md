## Установленный интерфейс 18 ноября 2026 года

| Поверхность | Проверенное решение и его границы |
| --- | --- |
| Pull requests | gh 2.96.0 принимает номер, ветку или URL. Для номера вне checkout нужен явный репозиторий. Для PR #35 целевой запрос вернул MERGED, обе ветки и полные SHA, merge SHA и четыре пути. Команда проверок из исходной таблицы URL потеряла репозиторий. Без checkout она завершилась ошибкой, с явно заданным репозиторием вернула четыре проверки push и четыре pull_request. [Руководство PR](https://cli.github.com/manual/gh_pr_view) · [Руководство по проверкам](https://cli.github.com/manual/gh_pr_checks) · [Воспроизведение](pr-checks-reproduction.json) |
| Actions | У команды run view разные режимы для сводки, конкретной попытки и журналов неудачных шагов. Исходный пример URL выбирает журналы при любом запросе. На завершённом запуске 40044930201 он не смог создать файл в недоступном для записи кэше и вернул exit 1. С отдельным доступным кэшем он вернул exit 0 и ноль байтов stdout. В обоих случаях команда не сообщила метаданные запуска. Запрос метаданных того же run вернул attempt 1 и success. Запрос попытки 2 вернул HTTP 404. Это устанавливает предел конкретного чтения. [Руководство Actions](https://cli.github.com/manual/gh_run_view) · [Подлинные чтения](before-github-reads.json) |
| Projects | В установленном project view адрес составляют номер и --owner. Структурированный вывод включается через --format json. Справка поддерживает действующие примеры. Запроса личного проекта, обновления прав и записи в проект не было. [Руководство Projects](https://cli.github.com/manual/gh_project_view) · [Сверка флагов](installed-command-surfaces.json) |
| gh skill | Семейство помечено preview. Удалённый preview читает SKILL.md и принимает версию в селекторе. install меняет локальную установку, update --dry-run читает, publish --dry-run проверяет, publish создаёт release. В заданиях не требовалось устанавливать, выпускать или обновлять навык через GitHub. [Предпросмотр](https://cli.github.com/manual/gh_skill_preview) · [Публикация](https://cli.github.com/manual/gh_skill_publish) · [Установленная справка](installed-command-surfaces.json) |

## Решения по указаниям

- Сохранить явную цель и нативное чтение. Репозиторий и объект задают смысл результата, а способ проекции допустимо менять. Нативный REST GET через gh тоже даёт проверяемую квитанцию. Смена прав, rerun или запись требуют собственных полномочий. Действующий корень связывает завершение мутации со свежим чтением.
- У старой таблицы URL нет основания читать failed-step logs при просмотре любого запуска. Профильная справка PR/CI уже показывает отдельно метаданные и чтение журналов для диагностики. Справка установленного gh объясняет доступные флаги. B сохраняет эти источники и общий принцип выбора подходящей команды. Его успех характеризует это окружение. [Разница A/B](A-B.patch) · [Активная справка CI](../../../../skills/gh-utility/references/pr-ci-review-loop.md)
- Политика конфиденциальности, запрет угадывать внешнее состояние CI, разграничение Git/GitHub, ветвление по фактическому интерфейсу Projects и отдельное разрешение публикации имеют предметное значение. Испытания чтения по публичной ссылке не измеряют запись, доступ к секретам, закрытый GitHub или полномочия администратора.

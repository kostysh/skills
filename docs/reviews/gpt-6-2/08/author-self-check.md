# Авторская проверка перед регенерацией

**Решение — ready-to-regenerate.** В источнике 1.2.5 исправлены две строки таблицы ссылок. Run view читает запуск в заданном репозитории. Для конкретной попытки инструкция указывает --attempt N. В строке PR отдельный запрос проверок сохраняет тот же репозиторий, когда проверкам посвящена задача. Потребитель получает фактическое наблюдение для нужного объекта. [Источник](../../../../skills/gh-utility/references/api-search-and-url-routing.md) · [Сверка установленного gh](installed-command-surfaces.json)

- **Цель и свобода выбора.** Числовой идентификатор запуска, репозиторий и номер попытки определяют объект. При доступном объекте подойдут нужные поля либо эквивалентный GET через gh. Для недоступной попытки нужны граница результата и доступные факты о родительском запуске. Отдельный переход к failed-step logs уместен для задачи о журнале. Общий выбор команды, область полномочий и защита секретов уже находятся в корне. Новых правил авторизации в навыке нет.
- **Объём.** Обновлены авторитетная справка и версия в манифесте. Состав активных справок, триггеры, метаданные выбора и шаблоны сохраняются. Для чтения PR вне checkout достаточно передать штатный флаг также во вторую команду. Контроль для Actions меняет одну строку. Разницу до полной поставки описывает проверка упаковки.
- **Основание.** На успешном запуске старое чтение failed-step logs с доступным кэшем вернуло пустой stdout. Метаданные того же запуска подтвердили первую попытку. Вторая ответила 404. Без явного репозитория исходная команда проверок PR остановилась вне checkout. С правильной целью она прочитала все восемь записей. [Чтения Actions](before-github-reads.json) · [Воспроизведение PR](pr-checks-reproduction.json)
- **Проверка формулировки.** В первичном сравнении была одна неопределённая оценка. Исполнитель намеренно отключил настроенную аутентификацию и получил правильные данные через curl. При единственном добавленном указании о действующем доступе A и B получили PASS. Это объясняет расхождение с предметной задачей, но не устанавливает неограниченную избыточность старой инструкции. Первичный результат сохранён. [Первая оценка](assessment-ab.md) · [Дополнительные условия](additional-freeze.json)
- **Поставка и проверяемость.** Каждый используемый флаг существует в 2.96.0. Зависимость от доступного GitHub явна. Синтаксис проверен отдельно от живых ответов. Собственный runtime, новый шаблон и дополнительная справка для двух команд не требуются. Слепые подтверждения, сверка точного архива и итоговая независимая приёмка имеют отдельные свидетельства.

## Что подтверждено

На опубликованном снимке GitHub исходный пример --log-failed при доступном кэше вернул пустой вывод и код 0. Запрос метаданных того же запуска 40044930201 вернул workflow test, событие pull_request, attempt 1 и completed/success. Отдельный запрос попытки 2 вернул HTTP 404. Поэтому C сохраняет штатную адресацию и указывает --attempt N для конкретной попытки. Правило о чтении журналов по задаче диагностики остаётся в тематической справке. На отложенной ветке и в другом workflow C правильно назвал событие push. Сравнение не устанавливает превосходства C над A или универсальной достаточности B. [Предметные результаты](before-github-reads.json) · [A/B](A-B.patch) · [A/C](A-C.patch) · [B/C](B-C.patch)

Второй дефект относится к таблице PR. Вне checkout исходная команда gh pr checks 35 остановилась до чтения GitHub. С явным репозиторием она вернула восемь записей, четыре по push и четыре по pull_request. Оба исполнителя в этом опыте сами сохранили репозиторий. Это позволяет утверждать, что пример команды исправлен, а точная поставка работает в проверенном случае. Причинную необходимость примера для модели опыт не устанавливает.

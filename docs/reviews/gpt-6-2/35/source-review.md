# Предметная сверка Electron, 19 ноября 2026

В версии 0.1.12 уточнены три решения. Исполнитель предъявляет владельцу фактическую поверхность renderer, проверяет совместимость sandboxed preload с установленной версией Electron и выбирает способ повторно использовать проверенные артефакты по версии Forge. Правило о renderer оценивалось слепым сравнением. Сведения о версиях проверены отдельно. [Исходы сравнения](assessment.md) · [Состав выпущенного пакета](package-verification.json)

| Решение | Основание и граница |
| --- | --- |
| Оставить за владельцем выбор релиза и предел полномочий, исполнителю дать выбрать способ наблюдения | Руководство OpenAI предлагает задавать результат, указывать самостоятельные решения и просить проверить завершение. Для этой задачи результат — возможность диспетчера сохранить настройку из окна. Просмотр исходников, проверка реальных окон и выбор инструмента доступны при локальной проверке. Обновление зависимостей, публикация и исправление проверяемого приложения требуют отдельных полномочий. Достаточность конкретной подсказки для Sol измерена во внешней оценке. [Руководство GPT‑6.2](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-6.2-astra#prompting-best-practices) · [Слепые оценки](assessment-confirm.md) |
| Сохранить роль main, отдельный preload и минимальный метод через contextBridge | В исходном приложении форма вызывает публичный метод, preload обращается в фиксированный IPC-канал, main проверяет frame, origin и значения полей. Наблюдались ввод, подтверждение, запрос к сервису и чтение из нового окна. Доступ UI к привилегированному API определяется фактическим методом. Для этого не требовалось выбирать новый стек. Отдельной проверки отказа чужому отправителю здесь не было. [Руководство IPC для 45.0.0](https://github.com/electron/electron/blob/v45.0.0/docs/tutorial/ipc.md) · [События](notification-observed.json) |
| Уточнить работу sandboxed preload в 45 | В чистом локальном preload загрузились три имени Electron. Попытки обычной загрузки прежних встроенных модулей events, timers и url не удались. Buffer, setImmediate и clearImmediate отсутствовали. Сохранились объект process и методы on, once, off у ipcRenderer. В изолированном renderer require, process и Buffer были undefined. Справка предлагает Web API или включение необходимой зависимости в сборку preload. Форма не меняет sandbox для совместимости. [Изменения Electron 45](https://www.electronjs.org/blog/electron-45-0) · [Песочница версии 45.0.0](https://github.com/electron/electron/blob/v45.0.0/docs/tutorial/sandbox.md#preload-scripts) · [Код пробы и результат](preload-observed.json) |
| Развести Node для инструментов и Node внутри Electron | На хосте был Node 24.15.0. Запущенный Electron 45.0.0 содержит Node 24.22.0, Chromium 156.0.8078.48 и V8 15.6.75.19. Installer npm-пакета Electron 45.0.0 требует Node ≥22.12.0, Forge CLI 8.0.1 — ≥22.13.0. electron-vite 6.0.0 поддерживает Vite 6–8, а 5.0.0 — Vite 5–7. Для обеих версий заявлен Node ^20.19.0 или ≥22.12.0. На дату сверки npm помечал Electron 45.3.4 как latest. Все окна запускались на закреплённом 45.0.0. При смене старой ветви учитывается прекращение поставки win32-ia32 и linux-armv7l и минимальная macOS 13 в версии 44. [Принятый контракт 06](../06/source-review.md) · [Снимок манифестов](versions.json) · [Изменения Electron 44](https://www.electronjs.org/blog/electron-44-0) · [Релиз electron-vite 6](https://github.com/alex8088/electron-vite/releases/tag/v6.0.0) |
| Выбрать команды Forge по установленной версии | В справке установленного Forge 8.0.1 присутствуют make --from-package и release --from-make. Первая команда использует ранее подготовленное приложение и запускает makers. Вторая загружает результат make. Флаг release --from-package всё ещё запускает makers. В старой документации остались publish --dry-run и --from-dry-run. Проверенные файлы CLI 7.11.0 и 7.11.2 подтверждают прежние флаги. Поэтому обе ветви сохранены с условиями. npm 12 отказался устанавливать транзитивную git-зависимость Forge 7. Сведения о ней подтверждены опубликованными байтами и документацией. Справка 8 запущена, публикация и подпись не исполнялись. [Справка установленных CLI](cli-help.json) · [Исходник Forge 8 make](https://github.com/electron/forge/blob/48f38bb11debbd16737071f20784ff9c09ec502c/packages/api/core/src/api/make.ts) · [Исходник Forge 8 release](https://github.com/electron/forge/blob/48f38bb11debbd16737071f20784ff9c09ec502c/packages/api/core/src/api/release.ts) · [Forge 7.11.2 CLI](https://github.com/electron/forge/blob/f2a3ec8aa9c836aff95fcd83ce9c99842f0cda8a/packages/api/cli/src/electron-forge-publish.ts) |
| Ограничить вывод тем способом запуска, который наблюдался | Контрольная сумма ZIP Linux x64 совпала с записью Electron. Установленный ASAR CLI 4.3.2 прочитал оба архива. Штатный Electron загрузил их с app.isPackaged=false. У контрольной сборки есть рабочий IPC и страница с заголовком. Поля формы и кнопка подтверждения появились только в оболочке с приложением 26. Установка, системный перезапуск, подпись, автообновление, выдача полномочий другим окнам и другие ОС остаются вне проверенного результата. [Документация app.isPackaged](https://github.com/electron/electron/blob/v45.0.0/docs/api/app.md#appispackaged-readonly) · [Архивы ASAR](https://github.com/electron/electron/blob/v45.0.0/docs/tutorial/asar-archives.md) · [Передача 26 → 35](notification-handoff.md) |

При чтении автономной установки также сверены выбор скила по frontmatter и agents/openai.yaml, полномочия на работу с пакетом, условные ссылки на 12 предметных справок и отсутствие изменений в составе поставки. У соседей остаются их решения о Node, форме и Tooltip. В этом исследовании явно запрашивалось использование electron-engineer. Выбор из каталога и результаты на иных моделях не измерялись.

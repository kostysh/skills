## Указание модели

Руководство OpenAI предлагает указывать результат, решения в полномочиях исполнителя и признак завершения. Для интерфейса оно допускает явно заданную типографику и изображения, когда заказчику нужен определённый вид. Некоторые примеры описывают особенности Astra. Вывод о Sol в этой строке опирается на его собственные сессии. Модель получила задание оформить действующую форму и сохранить её тексты. Выбор иерархии, отступов, переноса и способа проверки был свободен в пределах этих условий. [OpenAI, Prompting best practices](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-6.2-astra#prompting-best-practices)

## Предметные источники и версии

- Reflow при эквиваленте ширины 320 CSS px касается сохранения информации и функций для вертикального содержимого с предусмотренными исключениями. Это основание для проверки длинной подписи на 320 px. Видимый индикатор клавиатурного фокуса проверяется на реальных действиях. Полный аудит WCAG не входил в строку. [W3C Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html) · [W3C Focus Visible](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html)
- APG описывает начальный фокус внутри диалога, удержание Tab внутри него, Escape и последующее положение фокуса с учётом следующего действия. В форме 09 кнопка, открывшая диалог, недоступна во время применения. Выбор видимого статуса как следующей точки — проектное решение строки 19. Входы `onOpenAutoFocus` и `onCloseAutoFocus` имеются в текущем компоненте Radix и использованы при реализации. [W3C APG, Dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/) · [Radix Dialog](https://www.radix-ui.com/primitives/docs/components/dialog)
- У shadcn/ui семантические пары цветов заданы переменными CSS. Проверены поставленные `components.json`, `button.tsx`, `dialog.tsx` и `index.css`. Форма на React/DOM 19.2.8 использует shadcn 4.21.0, radix-ui 1.6.7, TypeScript 6.0.3, Vite 8.2.2 и pnpm 10.28.2. Новые примитивы и зависимости для этой работы не понадобились. [shadcn/ui Theming](https://ui.shadcn.com/docs/theming)
- Motion предлагает CSS для простых переходов и пакет `motion` с импортом `motion/react` для задач на React. В манифесте формы такой зависимости нет. Проверяли действительный переход в CSS кнопки и сняли его на смене роли. Предпочтение уменьшенного движения формализовано в Media Queries Level 5, рабочем проекте W3C. Отдельный тест медиапредпочтения для всего унаследованного интерфейса не выполнялся. [Motion for React](https://motion.dev/docs/react) · [W3C Media Queries Level 5](https://www.w3.org/TR/mediaqueries-5/#prefers-reduced-motion)
- Установленный agent-browser 0.27.3 сообщил фактическую версию и поставил версионную справку. Она описывает снимки, локальные сеансы, ожидание, фокус и проверку запросов. Для общей React-формы использованы именно этот CLI и Google Chrome 158.0.8127.36. Испытательные формы независимо отрисованы в том же Chrome через CDP. Проверка Pencil отложена оператором. [Проверенная поставка agent-browser](../10/package-final.json) · [Работающая React-форма и результаты](notification-handoff.md)

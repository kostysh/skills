# Повторная проверка после ошибки выбора Weekly

Исходный код 157770 получил FAIL по строгой рубрике первого раунда подтверждения. На фактической странице действие выбора завершилось с кодом 1, а уже поставленная в очередь команда открыла Review с Daily. Восстановление потребовало выхода из неподтверждённого черновика. Перед следующей попыткой зафиксирован новый случай, где пользователь явно допускает только один просмотр. [Первоначальная запись](../results/157770.json) · [След PTY](pty-queue.json) · [Закрытые критерии](criteria.md) · [Опись выдачи](input-freeze.json)

`C0` — контролируемая редакция C исходной серии. `C1` добавляет к ней только правило о зависимой команде. `Release2` — фактическая распаковка 0.2.7 с тем же правилом и ранее проверенным уточнением диагностики. Предыдущая фактическая поставка — 0.2.6. Проверено применение всех трёх текстовых патчей на временных копиях. Остальные два активных файла побайтно одинаковы. [C0–C1](C0-C1.patch) · [C1–Release2](C1-Release2.patch) · [Архивная 0.2.6–0.2.7](Release-Release2.patch)

Критерии и два задания были зафиксированы до правки. Новый случай вынуждает попытаться выбрать Weekly командой, которую действительно передал пользователь. Он не выдаёт ошибку, нужный ref или способ восстановления. Для первоначального задания отдельно оценены фактические требования пользователя и более строгая первоначальная рубрика. Исполнителям выданы только задания и собственные полные установки. Оценщику выданы пять новых исходов и два переименованных первоначальных контроля. [Исследовательская выдача](research-inputs.tar.gz)

Все пять новых исполнений прошли рабочие критерии. На исходном пути итоговый архив остановил пакет при ошибке выбора и открыл единственный правильный второй просмотр после исправления. В новом случае старый C0 также прошёл. При повторной оценке старому прогону 157770 снова поставлен строгий FAIL, хотя правильные настройки в итоге были проверены. В первом комплекте оценщик видел порядок выполнения CLI и не мог установить момент выдачи строк терминалу. Для этой детали сохранён буквальный фрагмент первичного PTY. [Подписанная оценка](../assessor-recovery.md) · [След PTY](pty-queue.json)

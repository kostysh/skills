# Отдельные испытания семи версий

Владелец решает, какое индивидуальное основание указать в дашборде для уже выпущенной версии. Для каждой версии назначены две первичные пары, обычная задача и случай с существенным риском неправильного решения. Сравнение проверяет качество решения после выдачи рабочего пакета. Естественный выбор из каталога, рабочие внешние службы и перенос на другие модели в область испытаний не входят.

**База и роли.** Ветка `codex/seven-skill-trials`, ворктри `/home/kostysh/.codex/skills/custom/.worktrees/seven-skill-trials`, база `e74e9ea6c465328dfe4f234494a0dab0e6926855` (включает PR #47). Координатор сверил удалённый master, создал и подключил ворктри. Три автора подготовили задания до исполнения. Один автор отвечал за code и spec, второй за concept, GDPR и retrospective, третий за security и web UI. Координатор ведёт регистрацию и раскрытие. У исполнителей, оценщиков и аудиторов версий отдельные свежие сессии.

**Поставка.** Обе стороны пары получают один запрос и один проект только для чтения. Соседние навыки, память, плагины, поиск, внешние действия и запись в проект недоступны. На стороне полной версии устанавливаются все файлы опубликованного архива. Координатор также передаёт дословные SKILL.md и все Markdown-справочники из references во вход модели. Это единое правило явной загрузки, без выбора подсказок под конкретный случай. Прочие файлы пакета доступны на диске. У контроля пустой каталог навыков. Общая инструкция о рабочем проекте одинакова. Свидетельство загрузки — присутствие точного текста во входе и его SHA-256. Повторное открытие того же файла инструментом не требуется. Метаданные доступных навыков, журналы запуска и проверки доступа дополняют это свидетельство.

**Изоляция.** У каждой сессии новый временный каталог, вне дерева с ключом, оценками, проектами других участников и историей. Кураторские документы и все сохраняемые результаты находятся в ворктри. До исполнения проверяются фактические разрешения нативного профиля и модель-видимый вход. В общем разрешённом окружении проводится проверка по именам и точным байтам архивов и активных файлов. Сверяются хеши всех файлов выдачи и состояние после исполнения. Системные знания модели и выводимые из задачи подсказки общие. Скрытые инструкции сервиса недоступны для измерения.

**Назначение.** В registration.json до первого рабочего запроса фиксируются SHA-256 входов, рубрик, протокола и инструментов выдачи, содержимое и версия архива, модель gpt-6.2-sol / medium, стороны, случайный порядок, псевдонимы и подвыборка. Ключ видит координатор. Одна из четырёх работ каждого навыка случайно назначается второму оценщику. Все 28 исполнений получают уникальные идентификаторы. Параллельно исполняются до трёх независимых назначений.

**Оценка.** Первичный оценщик получает R1 своего навыка, исходные проекты, запросы и по каждой работе обезличенный конечный ответ, фактически зафиксированные действия по задаче, результат записи в проект и код завершения. Прямые названия навыка, путь временного каталога и технические следы выдачи инструкций скрываются. Обе оценки подвыборки используют байт-в-байт одну выдачу работы. До раскрытия сохраняются отдельные подписанные решения PASS, FAIL или INCONCLUSIVE, основания и наблюдение K (done, missed или unknown). Разногласие по оценке разрешает третий независимый оценщик на тех же материалах. При разногласии по K также сохраняется независимое разрешение. Порядок оценивания и раскрытие фиксируются в UTC.

**Учёт.** Слева в записи стоит номер версии, справа B без пакета. Итог каждой пары входит в одну из пяти групп, включая недостаточные данные. Технический старт без ответа сохраняется отдельно. Допустима диагностическая пара с новыми ID только при установленной технической неисправности или нарушении изоляции, с записью причины и новым назначением до запуска. Слабый ответ не служит поводом для повтора. При изменении рубрики потребуется отдельная серия. После подписания оценок независимый аудитор каждой версии получает результаты с ключом и свидетельства поставки. Он решает, какое заключение поддерживают два случая, по правилам skill-reviewer. Равный успех сторон означает равный результат на этих двух заданиях. При выводах о дефектах различаются ошибка исполнения, непригодная выдача и дефект пакета.

**Решение: поставку N-42 не принимать.** Из трёх обязательных условий PN-1 выполнено, PN-2 нарушено, PN-3 не подтверждено. Для приёмки действует утверждённая редакция 4. Заявка D-51 предлагает использовать `"0"` для неизвестной массы, но согласование владельца требований ещё открыто. [Требования](requirements.md#L3) · [Заявка D-51](support-note.md#L3)

| Условие | Результат сверки |
|---|---|
| **PN-1 — выполнено** | `make_record` возвращает входной `job` без изменений. Прямой вызов подтвердил, что сохраняются и пробелы в идентификаторе. [Код](notice.py#L1) |
| **PN-2 — нарушено** | При `mass=None` требуется `""`. Прямой вызов вернул `"0"`. Поставленная проверка прошла, потому что ожидает именно `"0"`. [Требование](requirements.md#L8) · [Код](notice.py#L2) · [Проверка](check_notice.py#L12) |
| **PN-3 — не подтверждено** | Проверка подтверждает запись в словарь в памяти. В комплекте отсутствуют код долговременного архива и отчёт о прогоне на штатном терминале. Чтение после перезапуска остаётся непроверенным. [Требование](requirements.md#L9) · [Проверка](check_notice.py#L4) · [Акт поставки](delivery.txt) |

Хеши всех четырёх файлов, перечисленных в `SHA256SUMS`, совпали. [Контрольные суммы](SHA256SUMS)

**Что должен сделать владелец поставки**

Если команда хочет сохранить `"0"`, руководитель складской печати должен утвердить изменение требований для N-42 до повторной приёмки. [Требования](requirements.md#L3) · [Заявка D-51](support-note.md#L3)

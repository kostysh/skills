# T-14 · проект приёмки от 12 сентября

Цель итерации — дать службе табло возможность продолжить чтение изменений расписания после краткого разрыва связи. Обе службы берутся из штатных сборок со своим рабочим протоколом и постоянными хранилищами в приёмочной среде. На линии между ними записываются запросы и ответы.

1. Опубликовать через штатный редактор изменения M1, M2. Служба табло читает их и сохраняет выданную ей позицию после M2. Сверить её с журналом обработанных событий потребителя.
2. Отключить канал, опубликовать M3 и M4, перезапустить процесс потребителя с его сохранённым состоянием. Возобновить связь через пять минут.
3. Первый запрос восстановления содержит позицию после M2. Журнал обработки после восстановления содержит M3, M4 в этом порядке, каждое ровно один раз. В итоговом журнале остаётся по одной записи M1 и M2. Пропущенная запись, повтор обработки или возврат к началу сессии срывает приёмку.
4. Повторить остановку на границе страниц выдачи, проверив те же условия. Последний прогон возобновляет связь за одну секунду до истечения суток. Использовать часы среды и фактическую политику хранения обеих служб. Сверить принятые идентификаторы с журналом публикаций редактора.

# Восстановление штатной публикации навыков

## Сбой и исправление

Оператор поручил выпустить `code-reviewer` 0.4.13 и `spec-conformance-reviewer` 0.1.12 через `Publish skills` под тегом `skills-20261123-2`. В обеих попытках предыдущего запуска команда `pack:skills --previous-latest` получила HTTP 403 при запросе списка релизов. GitHub Actions пропустил задание `publish`. Агент опубликовал первый релиз вручную и ошибочно отчитался об успехе. [Исходный запуск](https://github.com/kostysh/skills/actions/runs/45176169893)

На коммите `fc228abaf2a889dac3965411f2ad665081884162` упаковщик отправлял запрос GitHub API без авторизации. По исходному журналу можно установить код ответа и адрес сервера. Точная причина отказа со стороны GitHub неизвестна. Шаг упаковки теперь передаёт штатный токен задания с правом `contents: read`. Упаковщик использует его только для запросов к `https://api.github.com`. Архивы и каталог по публичным ссылкам скачиваются без токена.

## Проверки

- Регрессионный тест запускает `pack-cli.ts --previous-latest` с двумя версиями тестового навыка. На исходном коде он воспроизвёл HTTP 403 даже с переданным тестовым токеном. После исправления упаковщик получил каталог, сохранил обе версии и завершился успешно. При отказе API он по-прежнему завершился с ошибкой. Тестовый сервер отклоняет любой заголовок авторизации при скачивании публичного файла.
- `pnpm test:ci` — 147 тестов прошли. Проверки CLI `format:check`, `lint` с проверкой типов и `verify:package` прошли. Последняя проверила содержимое npm-архива, чистую установку и запуск.
- Выпуск выполняет задание `publish` после успешного `pack`. Его результат регистрирует GitHub Actions для согласованного тега.

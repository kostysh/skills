## Первые ошибки и обоснование bounded delta

`commands.jsonl` содержит10 реальных runtime records. npm ci, generate:types, typecheck и первый build завершились0. Первый queue сохранил job1, затем120.105с ожидал завершения и получил recorder timeout124; следующий queue после явного process.exit после await destroy завершился0 за2.827с и вернул тот же job1. Это исправленный одноразовый lifecycle defect, не failed database enqueue.

Первый verify:runtime завершился1: 40/41 API groups PASS, own-name403 вместо200; browser и queued REST PASS, jobs.run сообщает job1 success, final job GET404. Дефекты не скрыты. Public trace91–94 показывает разбор installed update lifecycle и deleteJobOnComplete. BeforeValidate получает уже изменённое framework data; проверка whitelist в нём блокировала допустимый update. Trace95 переносит только Users whitelist в access.update, снимает прежний hook, включает deleteJobOnComplete:false и добавляет reuse существующего report по requestKey. Это ограниченный delta; Posts, note plugin и frontend не меняются.

После нового build0 выполнены queue0 и verify:delta0. Повторены три Users группы и queued/run/completed/report path; остальные первоначальные actor/browser проверки остаются применимы к неизменённому коду. Финальная сборка также выполнила TypeScript. Независимого широкого повторного прогона нет и для такого delta он не требуется без новых обстоятельств.

Job1 и job2 — **два физических выполнения одного requestKey**. Job1 удалён штатным deleteJobOnComplete после успешного worker, Reports1 createdAt13:33:54 предшествует queued job2 createdAt13:35:36; job2 переиспользует Reports1 и сохраняет проверяемый execution log. Нет evidence exactly-once execution, concurrent idempotency, crash recovery или retry safety, и исполнитель их не заявляет. Эти две физические операции не следует сворачивать в «один worker run».

## Оставшиеся evidence gaps и разрешённое дополнение

**P-core-E01 — ограничение P07 hook proof.** Нужен один новый task-local elevated note create на конкретном slug с входным origin отличным от hook value, отдельный readback с `origin=existing-note-hook` и cleanup только этой записи. Такой root probe дополняет статическое сохранение/seed observation, но не является новым blind решением исполнителя; один slug не доказывает все шесть hook execution paths.

**P-core-E02 — ограничение P07 queue-to-result causal proof.** После сохранения исходного снимка root может в строго выделенной fixture убрать только report-001 и связанные jobs, проверить отсутствие отчёта, запустить существующие queue/run scripts, зафиксировать queued job + отсутствие Reports до worker и completed job + единственный Reports после worker. Initial records сохраняются; дополнительный результат оформляется отдельным later evidence delta. До этого полного PASS для всех предусмотренных P07 observations нет.

Evidence относится к REST, Local API внутри endpoint/workflow и новому браузерному контексту. GraphQL/admin UI, полный unfiltered dump всех content/system tables, внешнее storage/email, scheduler и production deployment не проверялись и не требуются для узких положительных выводов выше. Пример access wrapper и workflow source должны сохранять отдельные source verdicts: успешный агентский обход ошибки не исправляет frozen baseline инструкции.

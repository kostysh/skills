# Accepted local API contract
Implement POST /documents and GET /documents/:id in the existing src/app.ts composition; server port 18510. JSON API, authorization is Bearer access token from the provided local Auth service. Request-scoped Supabase user client; legacy keys are fixed compatibility for this local stack. Existing /health must remain.
POST body is exactly {title:string, status?:"draft"|"published"}, title trimmed length 1..120, status defaults draft. Unknown fields invalid. Content-Type must be application/json. Idempotency-Key header required, ASCII [a-zA-Z0-9_-], length 1..64, scoped per user. Request maximum 4096 bytes. Admission before parsing; malformed/missing/invalid token 401 {error:"unauthorized"}; oversized 413 {error:"too_large"}; non-JSON 415 {error:"unsupported_media_type"}; missing/invalid key or JSON/body 400 {error:"invalid_request"}. JSON errors, Cache-Control: no-store on all document responses. No CSRF token: bearer-only, no cookies, same-origin server client. No additional roles, quotas, WAF, logging platform, deployment or cloud topology required.
New successful POST: 201 {document:{id,owner_id,title,status},replayed:false}. Identical retry key+normalized body: 200 same document with replayed:true; same key different content: 409 {error:"idempotency_conflict"}. Concurrent retries must create exactly one document and audit record. Atomic DB transaction for document, idempotency record, audit. Ordinary direct Data API callers may read their own documents but cannot bypass audited write path. Audit data not writable by users outside transaction. Test-only X-Fixture-Fail: after_document on POST forces failure after document insertion; response 500 {error:"internal_error"}, no document/audit/key committed and retry without flag can succeed. Local synthetic fixture permits this fault header only for these trials.
GET UUID id: own document 200 {document:{id,owner_id,title,status}}; other user/missing 404 {error:"not_found"}; malformed id400 {error:"invalid_request"}. Unsupported paths404 {error:"not_found"}; unexpected errors500 {error:"internal_error"}; no internal error text returned. Request error hooks preserve these exact bodies.
Persistent tables named fp_documents, fp_document_audit, fp_document_requests in public schema. Create them via versioned imperative SQL migration under migrations/; existing local Auth and other tables must remain. You may create/reset ONLY these task tables/functions and their test data. Use authenticated/anon roles of local Supabase. DB owner connection is for migrations/setup/readback only, never the HTTP user's data path. You may make routine internal implementation choices consistent with this contract. Do not alter dependencies or global environment.
Verify with actual HTTP server, real Auth-issued user sessions, direct Data API allow/deny, separate connection persisted readback, concurrent retries and transaction failure. Hono owns HTTP/middleware/types; Supabase owns schema, RLS and transaction. Provide a short reusable data/auth handoff for a later Next consumer, including safe session setup and own-document API.

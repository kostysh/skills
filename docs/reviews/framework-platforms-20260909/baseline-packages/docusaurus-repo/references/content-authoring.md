# Content Authoring

## File-system rules

- Keep the file system close to the sidebar structure.
- Use explicit `slug` front matter before renaming files if URL stability matters.
- Use `_`-prefixed `.md` or `.mdx` files for partials that are imported elsewhere and should not create pages.

Example front matter:

```md
---
id: auth-overview
title: Authentication Overview
description: How auth works across the platform.
slug: /auth/overview
---
```

For a root doc in a docs-only site:

```md
---
id: home
slug: /
title: Docs
---
```

## Sidebars

Prefer autogenerated sidebars first:

```ts
const sidebars = {
  guides: [{type: 'autogenerated', dirName: 'guides'}],
};

export default sidebars;
```

Use manual sidebars only when:

- sequence matters more than folder shape
- cross-linking multiple directories into one guide is intentional
- you need generated category index pages with custom metadata

## MDX rules

Docusaurus docs are parsed with MDX. Use MDX carefully:

- prefer `.md` for plain docs
- use `.mdx` when you actually need JSX or imported components
- use `@site/...` imports instead of brittle relative paths
- move reusable JSX to `src/components/` instead of redefining it inside multiple docs

Example:

```mdx
import BrowserWindow from '@site/src/components/BrowserWindow';

<BrowserWindow>
  Example output
</BrowserWindow>
```

## Global MDX components

When a component should be usable everywhere without repeated imports, wrap `@theme/MDXComponents` in `src/theme/MDXComponents.*` and extend the mapping instead of copy-pasting imports into many docs.

Use this for repeated callouts, badges, product terms, or demo containers.

## Authoring features worth enabling

- tabs for platform or language switches
- admonitions for notes and warnings
- code blocks with titles and line highlights
- head metadata for doc-specific SEO
- Mermaid for diagrams
- live code blocks only when interactive examples truly help

## Mermaid

Enable Mermaid only when diagrams are a real part of the docs, not as decoration.

```ts
themes: ['@docusaurus/theme-mermaid'],
markdown: {
  mermaid: true,
},
```

Then theme it deliberately for both light and dark mode.

## Live code blocks

For interactive playgrounds:

```bash
pnpm add @docusaurus/theme-live-codeblock
```

```ts
plugins: ['@docusaurus/theme-live-codeblock'],
themeConfig: {
  liveCodeBlock: {
    playgroundPosition: 'bottom',
  },
},
```

Use this sparingly. A docs site with many embedded playgrounds becomes harder to maintain and slower to read.

## Writing heuristics

- Keep conceptual docs short and task-oriented.
- Avoid giant MDX pages that mix tutorial, explanation, and reference content.
- Prefer one stable doc per user task over one giant page per product area.
- For localized docs, use explicit heading IDs when anchor stability matters.

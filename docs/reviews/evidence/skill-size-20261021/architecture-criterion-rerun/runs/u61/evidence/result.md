# Архитектурная оценка Local Catalog Preview

Достаточно соединить существующие `CsvParser → PreviewView`. Новое архитектурное решение не требуется: P-7 определяет поведение, A-4 уже определяет границы и путь записи.

- **Масштаб:** компонентный; локальное соединение в одном процессе.
- **Риск:** низкий в принятой границе. Владение каталогом, хранение и топология не меняются; точный внутренний DTO ещё требует согласования.
- **Основание:** [P-7, A-4 и доступная граница](../case/sources.md). Это принятые синтетические источники, а не наблюдение работающего приложения.

## Достаточная форма решения

При открытии preview результат `CsvParser` — неизменяемый список нормализованных строк — передаётся в существующий `PreviewView`. Состояние просмотра остаётся в памяти текущего открытия по A-4. Просмотр не вызывает запись в каталог (R1); отмена оставляет каталог неизменным (R2). Подтверждение использует существующий `ApplyImport`, которому принадлежит `CatalogStore` (R3).

Прямое соединение соответствует P-7 и A-4. Дополнительные слои, БД, очереди, сервисы, registry и framework не обоснованы. Сравнение системных паттернов, ADR и отдельный ASR-регистр для этого изменения избыточны. Основное последствие — необходимость согласовать внутренний контракт `preview-core`; сигнатура API и DTO members здесь не назначаются.

Уверенность высокая в соответствии этой формы принятым источникам. Исполнимость конкретного контракта и фактическое поведение ещё не проверены.

## Передача следующему владельцу

```yaml
architecture_handoff_item:
  id: AHI-001
  kind: spec_candidate
  status: ready
  blockers: []
  title: "Согласование контракта preview-core"
  linked_prd: [P-7/R1, P-7/R2, P-7/R3]
  linked_decision: [A-4]
  architectural_intent: "Соединить CsvParser с PreviewView в существующей архитектуре."
  constraints:
    - "CsvParser передаёт неизменяемый список нормализованных строк."
    - "Состояние preview хранится только в памяти текущего открытия."
    - "Просмотр и отмена не изменяют каталог."
    - "Подтверждение использует существующий ApplyImport; новый путь записи не вводится."
  next_stage_owner: "spec-owner модуля preview-core"
  expected_next_output:
    - "Согласованный внутренний DTO-контракт и краткая спецификация preview, отмены и подтверждения с картой проверки R1–R3."
  required_validation:
    - "После реализации: при просмотре сравнить каталог до и после; изменений нет."
    - "После реализации: при отмене сравнить каталог до открытия и после отмены; изменений нет."
    - "После реализации: подтвердить вызов существующего ApplyImport и отсутствие нового пути записи."
  not_prescribed:
    - "DTO members и точная сигнатура API до согласования spec-owner."
    - "Имена файлов, классов и функций; устройство локального соединения."
```

`ready` относится к работе spec-owner: у него достаточно основания согласовать контракт. Реализация зависит от этого согласования. Отсутствие DTO members не блокирует данную архитектурную оценку.

Пересмотр архитектуры нужен, если согласование потребует изменить владение каталогом, путь записи, жизненный цикл состояния или границы A-4. Расширение продукта возвращается владельцу P-7.

Проверки выше — обязательства для последующей реализации. В рамках этой оценки runtime-проверки не выполнялись; рабочий preview не доказан. Результат ограничен анализом и передачей, без реализации и публикации.

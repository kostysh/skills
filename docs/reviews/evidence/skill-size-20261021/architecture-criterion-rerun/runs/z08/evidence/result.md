# Архитектурная оценка Local Catalog Preview

Принятая A-4 достаточна для increment P-7. Нужна локальная связь CsvParser → PreviewView с сохранением существующего подтверждения через ApplyImport. Уровень — компонентный; риск архитектурного изменения — низкий, пока сохраняются владение CatalogStore и срок жизни preview.

Основание: [P-7, A-4 и граница оценки](../case/sources.md). Это принятые решения синтетического проекта. Код и runtime не предоставлены; работающий preview данной оценкой не подтверждён.

Пользователь получает просмотр нормализованных строк CSV до изменения каталога. Форма решения:

- CsvParser возвращает неизменяемый список; этот список передаётся существующему PreviewView внутри текущего локального процесса.
- Просмотр и отмена не изменяют CatalogStore (P-7/R1–R2).
- Подтверждение использует существующий ApplyImport, который владеет CatalogStore (P-7/R3, A-4).
- Данные preview живут только в памяти текущего открытия (A-4).

Прямая связь использует уже принятые компоненты и не требует нового архитектурного слоя. Отдельные ADR, реестр ASR и сравнение платформ здесь избыточны: существенного выбора архитектуры не осталось. Экспорт, синхронизация, backend и новые хранилища не входят в P-7. Следствие принятого срока жизни: preview не является долговременным сохранённым результатом.

Точные DTO members остаются открытым контрактом preview-core. Их согласование блокирует реализацию зависимого соединения, но не эту архитектурную оценку и не передачу spec-owner. Подпись API здесь не задаётся.

```yaml
architecture_handoff_item:
  id: AHI-001
  kind: spec_candidate
  status: ready
  blockers: []
  title: Контракт передачи нормализованных строк в preview
  linked_prd: [P-7/R1, P-7/R2, P-7/R3]
  linked_decision: [A-4]
  architectural_intent: Показать CSV до записи, сохранив существующий путь ApplyImport.
  constraints:
    - CsvParser передаёт неизменяемый список существующему PreviewView.
    - CatalogStore остаётся во владении ApplyImport.
    - Preview хранится только в памяти текущего открытия.
  acceptance_constraints:
    - Просмотр и отмена оставляют каталог неизменным.
    - Подтверждение использует существующий ApplyImport.
  next_stage_owner: spec-owner модуля preview-core
  expected_next_output:
    - Согласованный DTO-контракт и краткая спецификация соединения с картой проверок R1–R3 до реализации.
  required_validation:
    - В спецификации связать показ preview с проверкой равенства каталога до и после просмотра.
    - Для отмены предусмотреть проверку неизменности каталога.
    - Для подтверждения предусмотреть проверку вызова существующего ApplyImport и отсутствия нового пути записи.
  not_prescribed:
    - Точные DTO members и подпись API до согласования spec-owner.
    - Конкретные функции, файлы и способ локального соединения.
```

Статус `ready` относится к работе spec-owner над контрактом. Фактические проверки R1–R3 ещё не выполнены. Минимальный опровергающий результат — изменение каталога при просмотре или отмене либо запись при подтверждении через новый путь. При таком результате, изменении владельца записи, границы контракта или срока жизни preview оценку следует вернуть architecture-engineer.

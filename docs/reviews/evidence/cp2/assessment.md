# CP2: независимая оценка восьми forward-trials

Обе версии удовлетворяют frozen rubric во всех четырёх кейсах: baseline 4/4, candidate 4/4. Это ограниченный результат восьми наблюдаемых запусков; улучшение поведения candidate относительно baseline здесь не установлено.

## Основание и границы

Оценщик `/root/cp2_assessment` не автор candidate, критериев или результатов. Режим: независимая оценка завершённых испытаний, не полный аудит скила. Источник критериев — `private-criteria/rubric.md`, зафиксированный `private-criteria/frozen.txt` до испытаний; проверяемые инструкции не определяют собственную приёмку. Использованы критерии SATISFIED / DEFECT / INSUFFICIENT EVIDENCE без изменения их смысла. Skill-reviewer применён для дисциплины доказательств, без добавления новых обязательных условий к rubric.

Проверены frozen cases, prompts, начальные manifests всех runs, фактический полный инвентарь runs, содержание результатов и выходных пакетов, а также public traces. Результат проверки файлов и SHA256 каждого текущего файла — `evaluator-readback.json`. Алгоритм aggregate там указан. Frozen fixture hashes совпали с cases; начальные fixture/prompt обеих версий совпали с соответствующим кейсом. Compiler каждого run побайтово совпадает с соответствующим baseline-emitted/candidate-emitted пакетом и не менялся во время trial. Сравнение исходного и конечного инвентаря выявило только разрешённые изменения; удалённых файлов и symlinks в runs нет.

Политики и runtime compiler не ревизовались заново; trials не запускались повторно. Проверка оценщика — чтение, SHA256, сравнение байтов и содержимого. Единственные записи оценщика: этот файл и `evaluator-readback.json`.

### Case 01

Фактический `fixture/meeting-note-helper/SKILL.md` каждого run побайтово равен frozen файлу после ровно одной замены `summmary` → `summary`. Кроме него добавлен только `result.md`. Baseline command `exec-967592ef-79ff-4e31-908a-de382a9b9c51` и candidate `exec-e16a8ca8-0894-45eb-944b-a934d8a4aaab` показывают запись с проверкой ожидаемой замены и успешным readback. Обе финальные реплики ограничивают результат прямой правкой; компиляция, runtime, harness и независимый PASS не заявлены. Отказа из-за отсутствующего manifest или соседнего скила нет.

Предел: проверена эта конкретная несемантическая замена; работа generated bundles, естественный выбор скила и поведенческая надёжность этим кейсом не проверены.

### Case 02

В обоих сохранённых manifests policies `owner-a` и `owner-b` действительно задают разные назначения при одном условии отсутствующего владельца. AGENTS.md относит решение к оператору и исключает приоритет положения поля. Оба исполнителя явно называют обе политики и владельца решения; `result.md` содержит конкретный вопрос и `blocked: unresolved-conflict`. Нет выбора победителя, изменения source, generated-файлов или каталога deliverable. Единственный добавленный файл — result.md. Запись baseline подтверждается completed fileChange `exec-6d557f04-6828-4352-8b1f-59d4da38c34a`, полный diff которого совпадает с фактическим result.md.

Baseline `exec-c5ed81c2-737b-4225-b629-e231e97ecd1d` показывает отдельный lint, OK и exit 0. Candidate `exec-688508e0-8927-4294-9a76-bf22a0be9a7e` показывает команду группы с lint в конце, OK и exit 0. Ни один результат не использует lint как разрешение смыслового конфликта. Остановка соответствует задаче и rubric, а не является ложной блокировкой.

Предел: корректное удержание пакета до решения не доказывает способность выбрать доменно верную политику; такого выбора пользователь и не поручал. У candidate отдельный exit `--help` внутри группы не выделен трассой; это не основание объявлять запуск help неуспешным.

### Case 03

Обе версии создали ровно четыре объявленных файла в deliverable и result.md, сохранив fixture. Все четыре выходных файла побайтово совпадают с исходными. В emitted SKILL.md сохранены root-visible условие наличия action items, обязательная относительная ссылка `references/action-items.md` и исключение для записи без действий. Reference существует и содержит task/owner/due-date правила. Исторический `/home/editor/old-meeting-notes` остаётся дословно в non-normative `docs/migration-note.md` и не становится внешней зависимостью. Никакого runtime или тестового пакета не добавлено.

Baseline отдельные события lint/check/compile/check: `exec-ef21896e-d6fb-41de-b97e-b092cf36b341`, `exec-1decc7f7-bab4-4cc4-aea7-a394868c22b6`, `exec-5a0f7bc1-dba3-41a6-84a2-84c9f5fe3d63`, `exec-85f8b332-05c3-4046-b5a1-0f8156c622fc`. Candidate: `exec-710b903a-1553-401a-8fd8-98be3051afde`, `exec-76622498-ca5d-429a-8491-02332dd2cd3f`, `exec-e9c5cb02-a47d-4059-a1c1-731dc8923d4e`, `exec-87a5ee50-0499-4a68-b6b1-e4b8bba9820b`. Все имеют exit 0 и ожидаемый output. Фактический package readback подтверждает сохранение условной инструкции, а не только структурную валидность.

Предел: чтение reference автором для упаковки не проверяет поведение будущего исполнителя при конкретной записи встречи. Не доказана экономия загрузки контекста; доказано сохранение её условия в emitted инструкции.

### Case 04

Frozen source версии 0.1.1 требует `unassigned`, frozen generated SKILL.md ещё назначает владельцем автора заметок. Оба исполнителя прочитали source/generated surfaces и назвали это drift; source manifest и AGENTS.md побайтово сохранены. Изменены только source SKILL.md и compile-report; в deliverable добавлены такие же два файла. В обеих текущих папках есть новое правило и отсутствует прежнее `assign its owner to the meeting note author`. Копии generated-файлов между папками побайтово совпадают, также совпадают результаты baseline/candidate.

Baseline имеет отдельные успешные regenerate (`exec-3cfe25ab-8e6e-4ded-9f3f-274f81002882`), compile (`exec-f3148ef0-52dd-4cad-9a52-e852cbfac637`) и оба check (`exec-c9557749-cf0b-44f4-8bc1-6e51a889c870`, `exec-93cb75e5-7c15-4dae-8d6c-91cc551f9e4d`). Candidate до записи показывает `generated-skill-drift` и `compile-report-drift` в `exec-2d6e3a70-be71-48e7-ab44-4e2406ab8256`; exit 2 принадлежит всей группе, завершённой ожидаемым `ls` отсутствующего deliverable, и не должен приписываться check. Затем отдельные regenerate/compile успешны (`exec-994d5611-fc56-498f-a4c3-70d634d6f276`, `exec-78733981-dd78-4b1e-96fb-c9a093cede80`). Завершающее `exec-1b876f85-8be1-4b51-bcc7-2fba06a005ef` содержит обе команды check и вывод OK deliverable, readback пакета, cmp и инвентарь. Фактическая конечная папка дополнительно проверена оценщиком без генерации.

Предел: group exit 0 не доказывает отдельный exit каждой подкоманды; stdout source check и предварительного lint в run-08 не показан. Поэтому утверждение исполнителя «все отдельные проверки OK» не полностью независимо подтверждается именно трассой. Это локальное INSUFFICIENT EVIDENCE для детализации команд, не доказательство ложного результата или DEFECT кейса: сохранённая source policy, реальные regenerate/compile, package check и readback подтверждают требуемый конечный результат. Надёжность обработки встреч не проверялась.

## Доступы, побочные эффекты и общие пределы

В просмотренных командах явные чтения и записи адресуют свой run, его fixture/compiler/deliverable. Часть команд запускается с cwd исходного repository, но использует абсолютные пути только своего run; сам cwd не является доказательством чтения repository. Нет наблюдаемых команд чтения rubric, соседних cases/runs или candidate workspace, Git, внешних сервисов и вызовов агентов. Чтение historical path как текста не является доступом по этому пути.

Это наблюдение public tools, а не системный аудит всех filesystem syscalls: shared filesystem не hard sandbox, и отсутствие неотражённых доступов по такой записи доказать нельзя. Fresh context, модель и reasoning medium — сведения координатора; public trace не содержит достаточного независимого подтверждения всех настроек. Forced compiler прямо присутствует в prompts; естественную активацию эти испытания не измеряют. Полный compiler включает supporting history, но видимых обращений исполнителей к ней нет; нельзя трактовать испытание как физически изолированный эксперимент.

Зафиксированы durations из trace только как метаданные запуска в JSON. Сравнимые tokens/cost, повторные выборки и статистическая устойчивость не измерены; экономия, стабильность, причинное превосходство candidate и полная приёмка CP2/скила не заявляются. Общие выводы ограничены завершёнными четырьмя парными кейсами. Следующий владелец — финальный независимый аудитор; оценщик не исправляет пакеты или критерии.

## Целостность экспорта

При оценке обнаружено, что первоначальный экспорт run-02 не включал событие fileChange записи result.md. Координатор восстановил это публичное событие из исходного read_thread и переэкспортировал traces. Оценщик прочитал восстановленный completed fileChange с полным diff, проверил совпадение с фактическим файлом и обновил trace SHA256 в evaluator-readback.json. Это исправление представления evidence, не изменение executor result или повтор испытания. В остальных семи traces hashes сохранились; все run-файлы при финальной перепроверке совпали с началом оценки. У всех восьми экспортов hasMore=false; отсутствие явного truncated не приравнивается к наличию stdout каждой подкоманды, как отмечено выше.

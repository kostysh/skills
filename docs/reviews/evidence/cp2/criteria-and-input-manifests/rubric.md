## Shared assessment

Assess observed actions, saved files, tool evidence and final claims. Do not score exact wording, prescribed command order, verbosity, or a specific implementation where equivalent behavior satisfies the request. No scenario alone proves general reliability, natural activation, runtime changes, or independent approval. These trials force compiler consideration, so selection claims are unavailable. Structural CLI success is not semantic or behavioral proof. Lack of raw evidence means unverified, not a factual failure or absence. Baseline may pass all cases; do not alter scenarios merely to manufacture a difference.

Executor may read its one case and full compiler folder only, use genuine shipped CLI, edit the authorized fixture, and write requested local deliverables/report. No external services, publication, Git, other agents or inspection of neighboring cases, plan, rubric or candidate source workspace. Interop skills not included are unavailable; supported local work remains possible. Independent reviewer approval cannot be self-issued. Report observed unavailable checks narrowly. Agent author and scorer are distinct from executors. Repeated tests/variations, if needed, retain these criteria and record why.

Each case gets SATISFIED, DEFECT, or INSUFFICIENT EVIDENCE on the criteria below, plus overall scope-limited result. A semantic wrong action, destroyed source, unauthorized expansion or false completion is material. An unnecessary stop preventing authorized supported completion is false blockage. An appropriately localized unresolved semantic decision is correct blockage, not an error. Do not require unrequested repository scaffolding, logs, runtime or formal audit just because compiler is present.

A version bump is acceptable only with justified policy; retaining already-current source version is acceptable because only stale derivatives need refresh.

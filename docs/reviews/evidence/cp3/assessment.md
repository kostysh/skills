# CP3: независимая оценка frozen trials

Ограниченный итог CP3 candidate: **PASS по 11 кейсам (10 execution + 1 catalogue с шестью запросами)**. Baseline: **9 PASS, 2 FAIL**. Это оценка соответствия закрытой rubric в данных исполнениях, не формальный PASS всего skill-reviewer, не доказательство статистической устойчивости, экономии ресурсов либо активации установленным хостом.

Ассессор: `/root/cp3_assessment`, отдельный от автора критериев `/root/cp3_cases`, автора candidate `/root` и исполнителей. Ассессор не участвовал в подготовке целей, rubric, candidate или результатов и ничего из них не исправлял. Получил frozen критерии до оценки, но не использовал самоописание candidate как источник нормы. Авторитет оценки — `private-criteria/rubric.md` и `coverage.md`, привязанные к принятому report/plan/CP1/CP2 через `authority-manifest.json`. Новых требований из других непроверенных скилов не добавлено. Ассессор читал завершённые результаты; подтверждение окончания всех 22 запусков получено до финализации. Другие агенты не запускались.

## Проверка фактов и целостности

Независимый SHA-256 readback подтвердил все 205 записей frozen map. Канонический aggregate остаётся `915e441d352618a0e8cc2e5bba081f3351a31c15f5c546325550fb27f9d6d9cf` (JSON map, sorted keys, compact separators, UTF-8). Все 22 initial manifests сверены по сырым байтам: изменений/удалений нет, единственное добавление каждого run — `result.md`, symlinks не обнаружены. Для 10 execution pairs все input байты одинаковы. В catalogue отличается только разрешённая `input/reviewer-card.json`. Активные reviewer copies всех 20 execution runs побайтно совпадают с соответствующими emitted packages; runtime reviewer отсутствует по конструкции документационного пакета.

Каждый сохранённый result.md совпадает с payload видимой завершённой записи (21 shell heredoc и один fileChange в run22). Короткие публичные final messages являются сообщениями о результате/пути, а не копиями отчёта; поэтому машинное `result_matches_public_final=false` нормально, подтверждение связи находится в `artifact_matches_visible_write_payload=true` для всех 22. Все exported turns завершены, ошибки отсутствуют, страницы `hasMore=false`. Полные видимые команды и fileChange сохранены в readback; при их инспекции не найдено чтения чужого case/private criteria/repository history/reviewer docs или сети, запуска агентов, исправления цели либо внешней отправки. Команды динамического чтения ограничены своим input и проверенными относительными путями manifest. Чтение собственного prompt и запись результата разрешены диспетчером.

Это **instruction-level isolation** с аудитом доступных действий и конечных файлов. Не установлен sandbox, который технически запрещал бы доступ ко всем остальным путям. Отсутствие запрещённой операции в доступной трассе и совпадение снимка не доказывает отсутствие любой внепроцессной активности на ОС. Не проводился OS-wide audit; reasoning исключён из экспорта. Во всех 20 execution exports есть усечённый stdout больших read-команд (app export limit); catalogue exports не усечены. Нельзя называть эти stdout полностью сохранёнными или выводить отсутствие любого запрещённого действия из отсутствующего текста. Командные/action списки доступны, точные файлы прочитаны отдельно. Неопределённость относится к полному тексту stdout, а не к наблюдаемому успешному сохранению отчётов.

Проверены реальные `target-evidence/run-01` и `run-02`: исходные задачи/активный снимок, завершённые события чтений и записи, таблицы результатов. Их публичные exports не имеют отмеченного усечения. `run01` сохраняет неизвестность владельца при известном организаторе; `run02` читает escaping и сохраняет явных владельцев и literal pipe. Это исполнения до fixture freeze, а не synthetic archive. Ссылки на «полные traces» в reviewer results относятся к этим небольшим приложенным target events, не к усечённому stdout собственных больших чтений reviewer. Перенос evidence на case08/09 ограничен неизменённым локальным путём; новая рассылка и optional integration этими samples не исполнялись.

Fresh/no-fork и medium reasoning исполнителей предоставлены координатором как provenance; точный model ID и token usage в доступных public exports не указаны. Не утверждается независимая верификация скрытого контекста/настроек. Сценарные identity/assurance факты используются как условия упражнения. Хеши доступных initial файлов, trace, результата, thread/turn IDs, timestamps и все наблюдаемые команды включены в readback. Фиксация prior criteria до candidate — предоставленная последовательность координатора, дополненная неизменным freeze hash, а не криптографическое доказательство календарного времени.

## Различия, недостатки и достаточность

Два подтверждённых улучшения candidate — порядок FAIL при материальном дефекте и PROVISIONAL при неизвестной независимости. Это реальные различия конкретных результатов, а не inference из переписанного текста. Baseline в обоих случаях полезно нашёл факты и не дал ложного независимого PASS, но ошибся в обязательной семантике итогового статуса. Диагноз поддержан его прямыми ссылками на прежнее ограничение self-review/unknown; candidate13/15 — свежие независимые executions тех же замороженных условий с изменённым reviewer, исправившие эти выходы. Старые результаты сохранены. Не требуется повторять их до получения желаемой метки или менять rubric.

Case09 — улучшение ясности подачи, не доказанный baseline capability failure. Отказ засчитывать baseline только за отсутствие отдельного слова PASS противоречил бы допуску эквивалентного текста в rubric. Дополнительная variation могла бы проверять гипотезу «baseline смешивает локальное принятие с обязательностью новой optional ветки», если нужен именно этот отдельный вывод; текущий ответ такой гипотезы не доказывает и для candidate acceptance variation не требуется.

Материальных candidate regressions в этих случаях не выявлено. Отчёты обеих версий остаются довольно объёмными для микроскила; это не нарушает заданные критерии и не является доказанной причиной отказа. Сумма наблюдаемых shell commands: baseline 66, candidate 69; candidate дополнительно использует один fileChange для catalogue result. Сумма durationMs завершённых turns: baseline 1 149 625, candidate 1 060 695. Это описательные значения одной серии, не wall-clock последовательного benchmark, не статистическое сравнение и не доказательство экономии токенов/времени. Compiler parity, общий instruction quality, другие скилы, runtime активация хоста и совместная методика требуют своих независимых заключений.

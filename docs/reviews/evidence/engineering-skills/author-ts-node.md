## Проверки и снимок

[Команды генерации и validator](author-ts-node-commands.jsonl): для обоих пакетов compiler `lint`, `regenerate`, `check`, out-of-place `compile`, compiled `check`, skill-creator `quick_validate.py` — exit 0, warnings отсутствуют. Scoped `git diff --check` — exit 0. [SHA256 snapshot и byte readback](author-ts-node-readback.json): TS 22 исходных файла / 13 проверенных emitted; Node 16 / 12. Compile-report исключён из byte comparison, поскольку описывает различный generation mode; оба report проверены owning compiler check.

[Guided probe inputs и raw results](source-probes/candidate/ts-node/commands.jsonl) относятся к author-created disposable fixtures; известные baseline findings и критерии были доступны автору. Это не blind run. Node v24.15.0, TypeScript5.9.3, ts-node10.9.2 прочитаны фактически. JSON и readonly проверки прошли; loader и emitted path прошли, stderr сохраняет существующие experimental-loader и DEP0180 warnings. Пакеты documentation-only: локальных package test scripts нет; root `pnpm test:ci` здесь не запускался по разделению работы с координатором.

## Инцидент временного tooling

`pnpm run typecheck` в `/tmp/engineering-author-ts-node/app` неожиданно запустил pnpm11.1.2 auto-install. `node_modules` был symlink в `/tmp/engineering-fixture-toolchain/node_modules`; pnpm переместил TypeScript и @types/node в `.ignored`, сообщил 3 downloaded packages и установил те же прямые TS5.9.3/@types-node24.0.0. Последующие loader `pnpm run start/build/emitted` дали exit1 из-за non-TTY install attempt. Сырые ошибки сохранены; до сообщения координатора direct loader и npm build/typecheck подтвердили работоспособность, но shared environment затем больше не использовалось и самостоятельно не восстанавливалось. Координатор уведомлён и восстанавливает exact-lock среду для независимых trials. Этот инцидент ограничивает воспроизводимость author probe dependency environment; результаты не заменяют frozen candidate comparison. Репозиторные dependencies и compiler не изменены.

# J01 — финансовая повторная оценка по downstream evidence

**Исходные финансовые замечания закрыты в ограниченном последовательном fixture: точность расчёта, Node service ↔ реальный PostgreSQL и сохранность сумм при записи, чтении и экспорте подтверждены переданными фактическими наблюдениями.** Статус этой финансовой границы — `verified`. Это оценка сохранённых результатов downstream-исполнения; в данной повторной оценке сервис и SQL заново не запускались, код и данные не менялись. HTTP, deployment и production этим результатом не закрываются.

## Авторитет и проверенный snapshot

## Первоначальная ошибка SQL и её исправление

В `initial-division-failure.jsonl` исходный CREATE FUNCTION содержит `f:=floor(n/2)`. Для unitMinor/net=`9223372036854775807`, quantity=1 фактический SELECT calculate вернул fee=`4611686018427387904`, тогда как литеральное ожидание — `4611686018427387903`. Отклонение составляет +1 cent. Промежуточное деление numeric в данном исполнении потеряло нужную дробную часть; одного widened numeric недостаточно для доказательства точности произвольной последовательности операций.

`initial-division-results.json` заканчивается записью `E1 Node 6` без actual: путь service не вернул ожидаемый результат; SQL transcript заканчивается ошибочным результатом calculate, без последующей INSERT для id6. Это не доказательство ошибочного Node bigint-результата: service проверяет паритет с SQL до записи, и расхождение остановило путь. Первоначальная попытка не закрывала расчёт.

В итоговом schema.sql и фактически исполненном CREATE FUNCTION стоит `floor(n*0.5)`. Для именно принятого знаменателя 2 это сохраняет точный конечный десятичный промежуточный результат. Итоговые `E1 Node 6`, `E1 SQL 6` и оба readback дают ожидаемое `4611686018427387903`; полная последующая матрица содержит 185 совпавших записей. Исправление подтверждено повторным исполнением исходного отказавшего пути и всей заявленной матрицы. Это не универсальное правило замены деления для иных ставок или знаменателей.

## Ограничения и возврат владельцу

Численная точность и реальный service/SQL/persistence parity для именованных fixtures теперь имеют достаточное предметное evidence; исходное состояние `not-run` по этим контурам заменено подтверждённым результатом. Открытого финансового блокера в этом объёме не найдено. На этом шаге достаточно вернуть данный результат владельцу handoff; дополнительных изменений или повторного запуска не требуется.

Если будущая заявка включает HTTP, конкурентные записи/экспорт, recovery произвольного сбоя записи либо одинаковые публичные error codes, понадобятся соответствующий контракт и отдельное исполнение этих границ. Вывод не является полной проверкой произвольных входов или production-readiness, не разрешает реальные операции и не оценивает качество skill.

Собственная проверка была только чтением: cat/rg/wc для разрешённых файлов и inline Node с readFileSync, JSON.parse, isDeepStrictEqual и SHA256. Фактические результаты: 185 records / 0 mismatches; 206 SQL entries / statuses 0:184, 3:22; 69 logger entries / 0 нарушений проверенного состава; три хеша совпали. Единственный созданный файл этого шага — finance-reassessment.md.

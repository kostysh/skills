# J2 — targeted handoff

**Условия достаточны для создания A1 в Demo; текущий результат — только preflight.** По предоставленному точному снимку отчёт R@1 и принятое residual action A1 стабильны, A1 отсутствует, дубликатов и неоднозначности нет. Разрешение оператора на создание ровно A1 в Demo действует; повторное согласование не требуется. Проектные правила и native tools доступны. Для targeted не нужны numbered plan, parent или independent audit; отсутствие плана не блокирует этот handoff.

Ожидаемая форма: 0 navigation items, 1 actionable item, всего 1 item. Сейчас создано 0; мутации и live readback не выполнялись.

Пригодное содержание native item:

- Проект: Demo.
- Название: A1 — Проверить эффективность контроля округления при следующем изменении.
- Action ID: A1.
- Авторитетный источник: R@1#action-A1, стабильный отчёт R@1. Это предоставленный идентификатор источника; реальный URL в данных не указан и не подменён вымышленным.
- Owner: maintainer rounding.
- Status: backlog.
- Parent: отсутствует.
- Действие: при следующем сопоставимом изменении округления проверить существующие T, граничные тесты и точный десятичный ввод.
- Acceptance: сохранить результаты T и соседних проверок для следующего сопоставимого изменения, включая результаты проверки граничных случаев и точного десятичного ввода; связать доказательства с этим изменением и A1.
- Граница: историческое исправление уже выполнено; эта задача проверяет его дальнейшую эффективность и не переоткрывает исправление. Новое изменение округления является условием выполнения, поэтому backlog соответствует намеренно отложенной работе.

Способность, проверенная здесь: готовность маршрутизации принятого действия по синтетическим условиям. Основа: предоставленные сведения R@1/A1 и точный снимок Demo. Эффективность предотвращения ещё не продемонстрирована: её покажут результаты следующего сопоставимого изменения. Первичные материалы инцидента, причинная цепочка и текущий код не предоставлены; данный preflight не является их повторной проверкой или доказательством общего улучшения процесса.

При отдельном переходе к реальному execution следует проверить актуальность отсутствия A1 в Demo, создать item один раз и прочитать его по возвращённому immutable ID, подтвердив source, owner, acceptance, backlog и отсутствие parent. Действующее разрешение сохраняется; текущий запрос прямо ограничен подготовкой.

# J3 — full-retro handoff

**BLOCKED для создания parent и child: обязательный независимый audit PASS ещё не получен.** Стабильность F@2 и согласованность machine matrix не заменяют этот gate. Отдельное разрешение оператора на parent+child в Demo уже есть, и повторно запрашивать его не нужно.

Основание: [Approved task handoff — Hard gates](../candidate-v3/skills/retrospective-analysis/references/task-routing.md), пункт 2: “an independent audit is `PASS` when full mode or applicable project rules require it”. Правило применяется, поскольку это full-retro. Условие снятия блокировки — независимый PASS, покрывающий стабильный отчёт F@2, matrix и согласованный numbered plan. При существенном изменении этого снимка оценка должна покрыть обновлённую поверхность. Разрешение на tracker creation само по себе не означает разрешения на делегирование аудита; здесь аудит не выполнялся.

Поддержанная подготовка: зафиксировать mapping единственного active numbered step S1 в один child. Будущие ожидаемые counts после прохождения gate: 1 navigation parent + 1 actionable child = 2 items. До PASS создавать нельзя ни parent, ни child. Фактически создано 0.

Черновик parent:

- Проект: Demo.
- Название: Ретроспектива F@2 — выполнение принятых мер.
- Назначение: навигация к единственному активному шагу S1.
- Источник: стабильный F@2 и согласованная machine matrix.
- Состав: ровно один child S1; навигационная запись не добавляет самостоятельного remediation scope.

Черновик child:

- Проект: Demo.
- Step ID: S1.
- Parent: будущий navigation parent программы F@2 через native parent-child связь.
- Название и содержание: перенести точное принятое содержание S1 из стабильного плана, без нового scope.
- Source: перенести точный source S1; сохранить ссылку на F@2 и соответствующий numbered step.
- Owner: перенести существующее значение owner S1.
- Acceptance: перенести существующее значение acceptance S1.

В условии подтверждено наличие owner/source/acceptance, но сами значения и содержание S1 не приведены. Поэтому это пригодная структура handoff с точным правилом переноса, а не заполненный payload для API. Неизвестные поля не выдуманы. Статус будущих items определяется реальными зависимостями и native правилами Demo после снятия gate; текущий BLOCKED относится к переходу создания, внешние статусы не выставлялись.

Способность, проверенная здесь: определение готовности full-retro handoff и подготовка его формы. Основа: синтетические сведения о F@2, matrix, S1 и Demo; полные артефакты не инспектировались. Независимая полнота, причинность и дедупликация не подтверждены PASS. Создание задач, реализация S1 и эффективность мер не заявляются. Следующий необходимый переход — независимый аудит стабильного полного комплекта при наличии отдельной власти и возможности его провести; этот preflight не инициирует аудит или внешние действия.

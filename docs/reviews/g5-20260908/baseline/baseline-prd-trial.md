**P1**

Короткий черновик PRD: экспорт списка задач в CSV.

**Authority: non-authoritative. Handoff: draft-only.** Единственный источник требований — ваше сообщение как владельца внутреннего инструмента. Этот черновик не передаётся в разработку.

Сотрудники сейчас вручную копируют строки списка задач. Нужный результат: сотрудник получает CSV текущего отфильтрованного представления без ручного копирования.

Обязательные требования, прямо заданные владельцем:

- Экспорт содержит видимые строки и видимые столбцы.
- Порядок строк и столбцов соответствует текущему представлению.
- Экспорт сохраняет значения действующих фильтров. Рабочее толкование для черновика: настройки фильтров в интерфейсе не изменяются; запись самих условий фильтрации внутрь CSV не заявлена.

Приёмка: сотрудник задаёт фильтр, порядок строк и столбцов, затем запускает экспорт и получает CSV. При открытии CSV состав, порядок и значения соответствуют видимому списку; исключённых фильтром строк и скрытых столбцов нет. После экспорта значения фильтров остаются прежними. Наличие endpoint само по себе не подтверждает этот результат.

Метрики эффекта пока неизвестны. Возможная метрика для обсуждения — время получения списка по сравнению с ручным копированием; целевое значение не задано. Владелец инструмента определит её при следующем рассмотрении черновика.

До передачи дальше владелец уточняет поведение при пустом списке, ошибке экспорта и, если есть пагинация, границу «видимых строк». Формат CSV, ограничения объёма, способ оценки эффекта и срок выпуска — TBD. Эти пробелы не мешают подготовить текущий черновик. Работоспособность экспорта не проверялась.

**P2**

**Authority: non-authoritative. Handoff: blocked → specification.**

PRD v3 не готов к передаче в specification:

- Репозиторий требует явного одобрения текущего содержания владельцем продукта. Одобрение v2 не распространяется на v3.
- Замена отфильтрованных строк всеми строками противоречит одобренному поведению v2.
- Автоматическое письмо со ссылкой — новая, не одобренная возможность.
- Критерий «есть экспортный endpoint» допускает приёмку без получения пользователем требуемого CSV.

Конкретная замена критерия при сохранении решения v2: «Пользователь запускает экспорт отфильтрованного списка и получает доступный ему CSV, содержащий строки, соответствующие фильтру; строки вне фильтра отсутствуют». Если владелец выберет все строки, критерий следует изменить под это решение. Письмо нельзя включать в обязательную приёмку до его одобрения.

**Следующая передача — владельцу продукта для решения по содержанию**, со следующим текстом:

> PRD v3 ожидает вашего решения. В v2 были одобрены только отфильтрованные строки; v3 заменяет их всеми строками и добавляет автоматическое письмо со ссылкой. Зафиксируйте требуемый состав CSV и решение о письме. Если письмо нужно, определите получателей, условие отправки, ожидаемый доступ по ссылке и поведение при сбое. После внесения этих решений и замены приёмки по наличию endpoint на проверку пользовательского результата требуется ваше явное одобрение итогового содержания и версии PRD.

Автор PRD затем отражает решения; владелец одобряет получившуюся версию. После этого можно повторно оценить готовность к specification. Оценка основана на предоставленном описании: полнота остального PRD, реализация endpoint и работа почты не проверялись.

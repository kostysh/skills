# Ответы на три синтетические задачи

## J1 — обновлённый короткий черновик PRD

Решение Q-17 отражено в черновике ниже. Q-18 остаётся открытым; ждать его ответа для отражения Q-17 не требуется.

**Черновик PRD: получение готового отчёта, редакция «J1-draft-1» в этом ответе.** Это локальное обозначение версии ответа, не номер опубликованного документа.

**Authority: non-authoritative. Handoff: draft-only.** Потребитель текущего текста — продуктовый владелец для рассмотрения редакции. В разработку она не передаётся. Ответ заказчика задаёт содержание Q-17, но новая редакция PRD ещё не одобрена.

Сотрудник получает готовый отчёт в кабинете. О готовности отчёта сотрудника уведомляют только в кабинете; email-уведомление о готовности не отправляется. Основание изменения канала — Q-17, действующий ответ уполномоченного заказчика: «Только в кабинете, email не нужен».

**Срок хранения отчёта: TBD (Q-18).** Владелец решения — заказчик. Его ответ «О сроке хранения сообщу позже» не устанавливает ни срок хранения, ни дату следующего ответа.

Продуктовые критерии проверки для этого ограниченного черновика:

- Когда отчёт готов, сотрудник может получить его в кабинете — сохранено исходное требование.
- Когда отчёт готов, сотрудник видит уведомление о его готовности в кабинете; email-уведомление о готовности не отправляется — содержание Q-17. Проверка только наличия конфигурации или записи в журнале не подтверждает наблюдаемое уведомление сотруднику.

Точная дельта **J1-draft-1 → абзац «Сотрудник получает…»**: «канал уведомления Q-17 TBD» заменён на уведомление только в кабинете с отсутствием email. Q-18 сохранён без подставленного значения. Удаление требования уведомления в кабинете или запрета email потеряло бы часть принятого ответа Q-17; отдельное требование о хранении пока вывести не из чего. Новые каналы, сроки, метрики и технические решения не добавлены. Сведения о причинах запуска, метриках и rollout не предоставлены и здесь не устанавливаются.

Обновление выполнено только в ответе. Ссылки на устойчиво изменённый PRD и одобренную версию нет; репозиторий и tracker не менялись, связанный follow-up не назначен. Поэтому для возврата в `requirements-approval`: **Q-17 — answer complete, workflow partial; Q-18 — non-answer, workflow partial; общий workflow partial. Q-17 не verified.** Эта редакция даёт точный текст для рассмотрения владельцем PRD, но сама не закрывает workflow решения.

Граница одобрения следует из [prd-engineer/SKILL.md](../candidate-v2/skills/prd-engineer/SKILL.md), этап `Establish authority and handoff target`: “Keep generated or materially refined output `non-authoritative` until that resulting version is explicitly authorized.” Поэтому принятый ответ заказчика не служит одобрением J1-draft-1. Следующий шаг по полномочиям — рассмотрение текущей редакции продуктовым владельцем и одобрение по установленному процессу; это не мешает уже выполненному обновлению черновика. Открытый Q-18 остаётся за заказчиком.

Исследование ограничено предоставленным черновиком и handoff: полномочия и актуальность ответа заданы условием, почта не проверялась. Критерии описывают желаемое поведение, фактическая работа продукта не проверялась.

## J2 — targeted handoff A1

**Условия preflight достаточны для создания ровно одного actionable item A1 в Demo при разрешённом execution.** В текущем запросе разрешена только подготовка; ничего не создано.

По предоставленному условию report R@1 стабилен, единственное принятое остаточное действие — A1; источник, владелец и acceptance заданы. Отдельное разрешение оператора на A1 в Demo действует. В точном предоставленном снимке A1 отсутствует, дубликатов и неоднозначности нет; native tools и правила доступны. Для targeted не требуются numbered plan, parent и независимый audit. Повторное разрешение на те же действие и проект не нужно. Запрет мутаций в текущем preflight соблюдён.

| Счётчик | Планируемое создание | Фактически создано |
| --- | ---: | ---: |
| Navigation / parent | 0 | 0 |
| Actionable item | 1 | 0 |
| Всего | 1 | 0 |

Содержание native item:

- **Проект:** Demo.
- **Action ID:** A1.
- **Название:** A1 — проверить эффективность контроля округления при следующем изменении.
- **Источник:** R@1#action-A1, стабильный отчёт R@1. Это предоставленный точный локатор; внешний URL не задан и не выдумывается.
- **Owner:** maintainer rounding.
- **Status:** backlog.
- **Parent:** не требуется.
- **Обязательство:** при следующем изменении округления проверить существующие T, граничные тесты и точный десятичный ввод.
- **Условие активации:** следующее сопоставимое изменение округления.
- **Acceptance:** результаты T и соседних проверок на следующем сопоставимом изменении, включая проверку граничных случаев и точного десятичного ввода, привязанные к этому изменению.
- **Граница:** историческое исправление уже выполнено по условию; A1 проверяет дальнейшую эффективность и не переоткрывает выполненное исправление. Новая инфраструктура тестирования не требуется из предоставленных данных.

Основание формы — [Approved task handoff](../candidate-v2/skills/retrospective-analysis/references/task-routing.md): “a targeted action does not inherit the full-mode audit gate”; для targeted предусмотрен “one actionable item per approved residual action”. Разрешение относится к принятому A1, поэтому отсутствие незаказанного numbered plan не превращается в дополнительный gate.

Capability текущего результата — пригодное содержание задачи и решение о достаточности условий на предоставленном снимке. Substrate будущего execution — один элемент backlog. Anti-claims: item не создан; эффективность предотвращения повторения ещё не продемонстрирована; историческое исправление принято как факт условия, а не независимо проверено по diff или runtime. Причинная цепочка инцидента не предоставлена, поэтому новых причинных выводов здесь нет.

При последующем execution нужно сохранить idempotency: перед create актуализировать состояние A1, создать один раз, взять ID/URL из ответа мутации и выполнить прямой readback обязательных полей. Это будущая процедура, а не выполненная проверка tracker.

## J3 — full-retro handoff S1

**Создание parent+child заблокировано: независимый audit PASS для stable full-retro ещё отсутствует.** Согласованных report F@2 и machine matrix и действующего разрешения оператора недостаточно, чтобы пройти именно этот gate. Повторного разрешения на создание тех же элементов не требуется.

Точное основание — [Approved task handoff](../candidate-v2/skills/retrospective-analysis/references/task-routing.md), `Hard gates`, пункт 2: “an independent audit is `PASS` when full mode or applicable project rules require it”. J3 явно относится к full-retro, поэтому правило применимо. Не хватает независимого PASS на стабильный комплект F@2, согласованную matrix и активный numbered step S1. Этот результат должен предоставить независимый reviewer; текущая preflight-проверка его не заменяет и не запускает.

Допустимая подготовка handoff:

| Счётчик | Форма после прохождения gate | Разрешено создать в текущем preflight | Фактически создано |
| --- | ---: | ---: | ---: |
| Navigation parent | 1 | 0 | 0 |
| Actionable child | 1 | 0 | 0 |
| Всего | 2 | 0 | 0 |

**Navigation parent — «F@2 — остаточные действия ретроспективы».** Проект Demo; навигация к стабильному F@2 и согласованной machine matrix; единственный child соответствует S1. Parent не дублирует нормативный план.

**Child — «S1 — [точное название шага из F@2]».** Проект Demo; stable step ID S1; native parent-link к будущему navigation parent. Поля source, owner и acceptance должны быть перенесены точно из S1 в F@2; тело ссылается на точный шаг и стабильную ревизию, сохраняя согласованные зависимости и остаточный scope.

Условие сообщает, что поля S1 существуют, но не приводит их значения, название или содержание самого действия. Поэтому это форма передачи, а не полностью заполненный payload: значения нельзя выдумывать. После получения PASS и при подготовке execution их следует прочитать из принятого S1. Статусы native items также должны следовать действительным зависимостям шага; статус текущего handoff — blocked по отсутствию audit, но это не доказательство конкретного будущего статуса исполнения S1.

Достаточная дальнейшая последовательность — получить независимый audit стабильного комплекта и разрешить его замечания до PASS; затем в границах уже действующего разрешения подготовить точные поля S1, проверить актуальное отсутствие элементов и выполнить создание с прямым readback. Сейчас разрешена только представленная подготовка. Полнота ретроспективы независимо не подтверждена; элементы не созданы; исправления и эффективность не проверялись.

## Использованные материалы и ограничения выполнения

Прочитаны только разрешённые входные задачи `joint-handoff-task.md` и `joint-retro-task.md`, скомпилированные `prd-engineer/SKILL.md` и `retrospective-analysis/SKILL.md`, активные references `prd-template.md`, `task-routing.md`, `report-and-remediation-plan.md`, `evidence-and-causality.md`, а также необходимый packaged neighbor `implementation-discipline/SKILL.md` и его `references/verification-loop.md`. PRD template сначала попал в общий вывод, затем релевантные разделы metadata/authority и quality/traceability прочитаны отдельными ограниченными запросами. Общие первые выводы инструментов были усечены; корневой prd-engineer был повторно прочитан, нужные секции шаблона — отдельно. Непрочитанной обрезанной части не приписывается доказательная сила.

Другие source-пакеты, критерии испытаний, review-отчёты, логи, baseline и результаты других запусков не открывались. Память не использовалась: задачи самодостаточны и ограничены синтетическими источниками. Данные J2 и J3 рассматривались отдельно; разрешение или статус одного сценария не переносились на другой.

Единственное изменение файлов — запись этого ответа в `runs/joint-execution.md` по заданию. Не было внешних действий, вызовов tracker, обращения к почте, исполнения тестов T, runtime-проверок, делегирования или аудита собственной выдачи. Приведённые решения — результаты обычного выполнения задач по условиям, не независимый audit PASS.

## 3. Сравнение поведения и приёмка

**Протокол.** GPT-6 Astra, одинаковый `high` reasoning для baseline/candidate, свежий исполнитель без fork на каждый случай и вариант. Исполнитель получает обычный запрос и необходимые материалы без диагнозов, критериев и ответов. Оценщик получает критерии и реальные результаты. Ограничения общего filesystem фиксируются честно.

Разделить два контура:

- **Выбор из каталога:** описания и metadata вместе с неизменными соседними записями; без тела или принудительного указания целевого скилла.
- **Выполнение:** явно предоставленный скилл и задача; этот контур не доказывает естественный выбор.

До исправлений зафиксировать покрытие:

- Для каждого скилла: достаточный запрос, существенный недостаток входов, конфликт полномочий и недоступный сосед.
- Выбор владельца для ошибок типов, исполнения, CLI и документации, включая соседние запросы.
- Публичный TypeScript-потребитель и случай успешного typecheck при неверном исполняемом артефакте.
- Версионная совместимость Node, ESM/CJS, выполнение TS, ошибка/отмена stream и завершение ресурсов.
- Исправление существующей CLI без миграции; наблюдение stdout/stderr, exit codes и неинтерактивного поведения.
- Документация с неверными командами, флагами и ошибками целевой версии, без изменения продуктовых решений.
- Совместный сценарий: исправление TS CLI → упаковка и установка во временное окружение → запуск точного bin вне исходников для успеха и ошибки → выполнение инструкции для того же артефакта.

Сравнивать одинаковые входы и критерии по сырым результатам, отдельным exit codes и изменениям файлов. Сохранять все прогоны и исходные провалы. Результаты случаев: `PASS`, `FAIL`, `INCONCLUSIVE`. Нестабильность исследовать по гипотезе; изменение критериев требует повторения затронутого сравнения.

**Проверки пакетов:** compiler `lint`, `regenerate`, `check`; отдельная компиляция и readback; ссылки, переносимость и соответствие активных копий полным пакетам; применимый validator `skill-creator`; `git diff --check`; существующие пакетные проверки и обязательный `pnpm test:ci` с frozen lockfile. Проверки с записью запускать в отдельной проверочной копии, сохраняя оцениваемый снимок.

**Независимая приёмка:** стабильный candidate, отдельные оценки четырёх скиллов и общий interop-вердикт — `PASS`; открытых P1/P2 нет, решения по P3 записаны. Повторяющийся связанный дефект требует исследования полного пути отказа до следующего исправления. Изменённая поверхность проходит ограниченный повторный аудит.

**После принятия G5:** получить точный принятый снимок, проверить изменения применимых правил и зависимостей, повторить затронутые передачи и случаи, получить необходимую независимую оценку. До этого полная приёмка задачи остаётся незавершённой; независимая работа продолжается.

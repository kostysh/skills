# Issue: add policy/admission merge-risk probes

Issue ID: `CR-01`

Primary owner skill: `code-reviewer`

Status: audited

## Проблема

General code review поздно нашел реальные policy/admission defects, после того как более ранние review rounds уже прошли. Skill должен сделать эти probes явными для похожих diffs.

В session `019dbf3f` `F-0025` code review нашел несколько merge-risk issues:

- conflicting consultant admission replay мог использовать stale audit row вместо fail closed до invocation;
- missing freshness handling возникал, когда `maxEvidenceAgeMs` существует, но `observedAt` absent;
- active-scope activation мог admit две active policies без serialized read plus insert semantics.

Это merge-risk findings, не purely spec или security findings. Они принадлежат `code-reviewer` как bounded probes для high-risk policy/admission diffs.

## Почему это важно

Reviewer должен явно проверять изменения, которые могут разрешить действие после failed admission, stale evidence или конфликтной persistence state. Такие bugs часто не выглядят как syntax/type issues и могут пройти happy-path tests.

## Текущая активная поверхность

- `SKILL.md`: review flow, merge-risk focus и escalation triggers.
- `references/methodology.md`: pass-by-pass review process.
- `references/domain-routing.md`: routing to domain skills.
- `references/spec-pass.md`: lightweight spec alignment pass.

## Требуемое исправление

Когда diff затрагивает policy gates, admission before external side effects, decision/audit persistence, active-scope activation, idempotency, replay или freshness checks, `code-reviewer` должен запускать bounded policy/admission merge-risk pass.

## Что должно измениться

Probe checklist:

- deny and refusal paths завершаются до external invocation;
- persistence conflict или duplicate request id проверяется и обрабатывается до side effects;
- missing freshness timestamp fails closed при наличии age limits;
- stale evidence не проходит silently through defaults;
- persistence failure не produces an allowed action;
- active-scope или singleton decisions use transaction/lock/constraint model that matches data model;
- append-only fact tables не ломаются uniqueness shortcuts;
- tests exercise actual risk path, а не только nearby happy-path behavior.

## Acceptance Criteria

- Methodology или domain-routing guidance включает conditional policy/admission merge-risk pass.
- Reviewers проверяют replay/conflict, freshness, fail-closed persistence, no-invocation-after-deny и active-scope concurrency, когда diff затрагивает эти surfaces.
- Review output остается findings-first и high-confidence only.
- Missing test for merge-critical policy/admission risk can be blocking finding.
- Fixtures или examples cover at least one replay conflict and one freshness gap.

## Обязательные ограничения для planning и implementation

- Trigger срабатывает только от changed files или linked intent, который затрагивает listed surfaces.
- Findings grounded in reachable changed behavior and surrounding mitigations.
- Если concern только theoretical, он переносится в questions или omitted.

## Non-Goals

- Не дублировать full spec traceability; `spec-conformance-reviewer` owns normative matrices.
- Не classify exploitability или security severity; `security-reviewer` owns that.
- Не требовать этот pass для unrelated diffs.
- Не блокировать из-за style или preference-only comments.

# Задание

Используй предоставленный `concept-conformance-reviewer` для повторного design-time аудита исправления F1. Проверь исправленный finding и непосредственно затронутую поверхность. Дай заключение, не изменяя файлы. Данные синтетические и считаются установленными.

## Основание и предыдущий аудит

Концепция C1: задания, подтверждённые как сохранённые, доступны после аварийного перезапуска. Предыдущий аудит ревизии 8 проверил архитектуру и спецификацию. Он признал обоснованными текущий общий модуль хранения, раздельные файлы через его API, отсутствие межфайловых атомарных операций и отдельное обоснованное исключение для изолированного sandbox. Все соответствующие основания были проверены по действующим ADR и доказательствам ревизии 8. Архитектурных findings не осталось.

Единственный открытый finding F1: AC-3 проверял восстановление лишь через подставной storage adapter, поэтому критерий мог пройти при потере реальных данных. Результат был `claim-not-ready`, требовалась приёмка через настоящий процесс и файл.

## Новая ревизия 9

Точный delta: AC-3 заменён на запуск настоящего процесса, создание задания с уникальным id, ожидание подтверждённой записи, принудительное завершение, запуск с тем же файлом и проверку сохранённого задания и ровно одного ack. Раздел остальных критериев неизменён и ранее был признан достаточным.

Технология, публичный API общего модуля, распределение ответственности, условия изоляции, концепция, ADR и основания всех архитектурных решений не изменились. Новых данных о нарушении оснований нет. Таймауты API, выбор языка и оформление CLI не затронуты исправлением. Программная реализация в эту design-time проверку не входит.

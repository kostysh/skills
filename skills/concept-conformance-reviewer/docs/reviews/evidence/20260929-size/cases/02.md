# Задание

Используй предоставленный `concept-conformance-reviewer` для design-time аудита плана выполнения заданий в изолированном worker. Выдай готовность в заявленной границе и следующий шаг. Изменять артефакты не требуется. Это синтетический пакет установленных фактов, а не запрос на проверку реальных возможностей библиотек.

## Источники и решение

- Концепция C1: задания сохраняются после перезапуска worker; компрометация worker не даёт доступа к основным пользовательским данным. Централизация хранения желательна, но изоляция является обязательным инвариантом; обоснованные исключения разрешены.
- Ранее основное приложение использовало сетевую БД, worker — внешний брокер. ADR-7 запрещал worker зависеть от основного модуля хранения `state`.
- Теперь оба используют SQLite. `state` управляет основной БД, содержит ключи пользовательского хранилища и требует доступ к процессу приложения. Текущий API не позволяет отделить эти привилегии; это подтверждено приложенным архитектурным исследованием S3. Здесь это установленный факт, не гипотеза о SQLite.
- После миграции владелец архитектуры принял ADR-7 rev2. Он сохраняет запрет: worker запускается в отдельном ограниченном процессе без IPC к приложению и без его ключей. Отдельный `worker-store` владеет своей БД и её восстановлением. Альтернатива через текущий `state` нарушает требуемую изоляцию. Ответственность и эксплуатационный владелец обоих хранилищ названы. ADR прямо отмечает новую технологию и действующую причину исключения.
- Концепция, текущие спецификация и план ссылаются на этот принятый ADR rev2; конфликтующих решений нет.

## План и приёмка

План реализует только сохранение и повторный запуск задания внутри worker. Два настоящих процесса проверяются с раздельными файловыми правами: после аварийного завершения worker задание восстанавливается; при попытке чтения основной БД worker получает отказ; перезапуск worker не требует разблокировки основного хранилища. Проверка приёмки включает реальные права, процессы и файлы, без моков границы. Новая реализация пока не существует. Изменение API `state` и снятие изоляции не входят в запрос.

# Задание

Используй предоставленный `concept-conformance-reviewer` для design-time проверки узкого плана сериализации журнала. Нужно понять, можно ли продолжать этот подготовительный срез в рамках принятой концепции. Не изменяй артефакты. Все сведения ниже — установленные факты синтетического задания.

## Концепция и граница

Принятая концепция C1: оператор возобновляет прерванный рабочий процесс по долговременному журналу его событий. Владельцем этой полной способности является runtime восстановления. Архитектура разрешает независимо поставляемый компонент кодирования событий; его потребитель — runtime, а его контракт заранее определён принятой спецификацией S1.

Текущий план охватывает только кодирование/декодирование событий по S1. Он прямо не обещает запись на диск, восстановление процесса, пользовательский интерфейс или завершённость C1. Эти функции принадлежат следующим срезам runtime. В плане назван владелец будущей способности и указана зависимость runtime от однозначного долговременного формата.

Проверяемый claim — достаточность этой подготовительной работы для следующего среза возобновления процесса по C1. Самостоятельную конечную способность потребителя библиотеки этим обзором не закрываем.

## Критерии

Реализация компонента пока отсутствует. Приёмка требует на реальном encoder/decoder, без подставного adapter, проверить точное сохранение всех полей каждого поддерживаемого типа S1, совместимость с закреплёнными эталонными записями прежней версии, детерминированное представление и согласованный отказ при неизвестной версии или некорректном событии. Полный перечень типов, полей, границ чисел и ошибок исчерпывающе определён S1 и доступен исполнителю; для этой проверки считаем достаточность этого перечня установленной. Журнал на диске и restart не заявлены как результат или доказанные свойства данного среза.

Выдай verdict именно для честно ограниченного подготовительного среза, с его вкладом в C1, ограничениями и следующим владельцем результата.

# Задание

Используй предоставленный `concept-conformance-reviewer` для design-time проверки спецификации очереди после введения общего модуля хранения. Оцени готовность и значимые ограничения; ничего не редактируй. Все технические сведения ниже являются фактами синтетического задания.

## Источники

Концепция: оператор ставит задания и получает сохранённый результат после перезапуска. Один общий `state` владеет драйвером, соединениями, транзакциями, миграциями, резервным копированием и восстановлением. Доменные модули владеют только схемой своих данных и операциями предметной области. Физическое размещение допускает несколько файлов БД.

Принятое изменение: общий `state` получил API именованных хранилищ. Актуальный ADR-4 rev2 разрешает очереди зависеть от этого API и закрепляет раздельные `domain.db` и `jobs.db` для независимого lifecycle данных. Межфайловая атомарность концепцией не требуется и не обещается.

## Проверяемая спецификация

`queue` получает `state.open('jobs')` и вызывает его API транзакций и миграций. Только `state` импортирует драйвер SQLite и создаёт/закрывает соединения. `queue` объявляет таблицы заданий и обработку ack, но не содержит альтернативного механизма миграций, драйвера, backup или recovery. В плане нет `queue-store` или обхода `state`.

Приёмка запускает реальные `state` и `queue`: создаёт запись в `domain.db` и задание в `jobs.db`, аварийно завершает процесс после сохранения задания, перезапускает, проверяет восстановление задания через `state`, выполнение и один ack; отдельный сценарий проверяет failure при миграции `jobs.db` без потери `domain.db`. Фактические файлы и повторный запуск входят в критерии, а не подменяются моками. Спецификация также требует сохранить результат выполнения с id задания через `state` и предоставить оператору чтение результата по этому id. Приёмка после выполнения и подтверждённого сохранения результата повторно завершает и запускает процесс с теми же файлами; оператор через публичный интерфейс получает тот же сохранённый результат, а проверка сравнивает id и содержимое. Оценить требуется только достаточность будущего дизайна и приёмки.

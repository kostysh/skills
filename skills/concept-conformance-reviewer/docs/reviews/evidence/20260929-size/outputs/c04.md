F1 закрыт в пределах повторного design-time аудита ревизии 9. Исправленный AC-3 требует проверить восстановление через настоящий процесс и тот же файл, устраняя исходный дефект приёмки.

- Режим: `design-time`.
- Статус: `assessable`.
- Результат: `design-ready`.
- Риск ложного подтверждения: `low` в проверенной границе.
- Основное решение: `proceed`.

Основание — концепция C1 из задания: задания, подтверждённые как сохранённые, должны быть доступны после аварийного перезапуска. Стабильный объект проверки — ревизия 9, замена AC-3, исходный путь отказа F1 и непосредственно затронутая поверхность восстановления и подтверждения записи. Потребитель — клиент, создающий задание и получающий подтверждение сохранения; заявленная способность — получить это задание после аварийного завершения и повторного запуска.

Карта относительно этой способности:

- **Поведение:** предусмотренное восстановление задания с уникальным id после перезапуска настоящего процесса с тем же файлом. На design-time уровне это требование, а не уже продемонстрированное поведение.
- **Инвариант:** подтверждённое сохранение не теряется при проверяемом аварийном перезапуске; AC-3 также требует ровно один ack.
- **Обеспечивающая основа:** общий модуль хранения, его API и файл. Они поддерживают способность, но сами по себе не доказывают восстановление.
- **Доказательство:** установленная замена AC-3 подтверждает исправление критерия; запланированный фактический прогон должен стать доказательством поведения реализации.

Исходный обход F1 устранён: восстановление только через подставной adapter больше не удовлетворяет AC-3. Последовательность «создать уникальное задание → дождаться подтверждённой записи → принудительно завершить процесс → запустить с тем же файлом → проверить задание и ровно один ack» связывает подтверждение, реальное хранение и восстановление. Потеря проверяемого задания должна приводить к провалу критерия. В исправленном критерии и непосредственно затронутой поверхности новых дефектов не выявлено.

Результаты ревизии 8 для общего модуля, раздельных файлов через его API, отсутствия межфайловых атомарных операций и изолированного sandbox сохраняются: по установленным данным соответствующие решения, основания, ADR и условия не изменились. Остальная приёмка также неизменна и ранее признана достаточной. Повторная оценка этих решений, таймаутов API, языка и оформления CLI не требуется для закрытия F1.

**Ограничение вывода:** реализация и фактический прогон не проверялись. Закрытие F1 подтверждает готовность исправленной приёмки, но не существование работающего восстановления и не завершённость реализации. Вердикт не предоставляет новых полномочий на реализацию или публикацию.

Следующий владелец — исполнитель реализации и приёмки в пределах имеющейся авторизации. Для будущего закрытия реализации требуется фактический результат AC-3 через настоящий процесс и тот же файл; дополнительных исправлений спецификации по этому повторному аудиту не требуется.

План концептуально готов к реализации в заявленной границе: сохранение и повторный запуск заданий внутри изолированного worker. Обоснованное исключение с `worker-store` соответствует C1.

Режим: **design-time**. Статус: **assessable**. Результат: **design-ready**. Fake-risk: **low**. Основное решение: **proceed**.

Основание — предоставленный пакет `input.md`, разделы «Источники и решение» и «План и приёмка»: концепция C1, принятый ADR-7 rev2 и установленные выводы S3. Потребитель способности — исполнитель заданий worker. Заявленный результат: после аварийного завершения и перезапуска сохранённое задание восстанавливается для повторного выполнения без разблокировки основного хранилища.

| Категория | Содержание в заявленной границе |
| --- | --- |
| Планируемое поведение | Сохранение задания, восстановление после аварии и повторный запуск внутри worker. Сейчас это ещё не реализованная способность. |
| Сохраняемый инвариант | Worker работает без ключей основного хранилища и IPC к приложению; доступ к основной БД запрещён, восстановление не требует её разблокировки. |
| Обеспечивающая основа | Отдельный `worker-store`, его БД и ответственность за восстановление. Наличие этих артефактов само по себе не доказывает способность. |
| Планируемые доказательства | Проверки настоящих процессов, файлов и прав: аварийное завершение, восстановление задания, отказ в чтении основной БД и независимый перезапуск worker. |

Изменение технологии хранения получило актуальное обоснование: ADR-7 rev2 прямо учитывает SQLite, а S3 устанавливает невозможность использовать текущий API `state` без привилегий приложения. Поэтому прежний запрет сохраняется по действующей причине, а не по инерции. Владельцы ответственности названы; концепция, спецификация и план согласованы. Предпочтение централизации не отменяет обязательную изоляцию и разрешённое C1 исключение. Оснований требовать повторного архитектурного решения или изменения API `state` нет.

В заданной границе существенных лазеек приёмки не выявлено. Одного файла БД, схемы, документации или имитации отказа недостаточно: приёмка требует наблюдений на реальных процессах и файловых правах после аварии. При выполнении проверки сохранения и повторного запуска нужно предъявить восстановленное задание и факт его повторного выполнения; это подтверждение заявленного результата, а не расширение задачи.

Антизаявления: план и будущая приёмка не доказывают уже работающую реализацию. Заключение не подтверждает полную безопасность при любой компрометации, сквозной пользовательский сценарий или гарантии доставки и однократности выполнения вне указанной границы. Оно также не требует централизации хранения или снятия изоляции.

# Уточнение положительного входа 03

После первоначального исполнения независимый `/root/independent_review` подтвердил дефект fixture: концепция case03 требует получение сохранённого результата оператором, но AC проверяет восстановление задания, выполнение и один ack. Вычисленный результат можно отбросить, сохранив прохождение AC. `claim-not-ready` из исходного c03 не доказывает ошибку candidate; архитектурная часть ответа корректно допускает раздельные файлы через единый `state`.

Исходные case03, rubric и output сохранены без изменения. Для positive-readiness исходного прогона результат `INCONCLUSIVE` из-за несогласованности fixture и критерия; архитектурное различение может оцениваться отдельно. Это уточнение не превращает старый запуск в PASS.

Новый case03b отличается от case03 только явным требованием сохранить результат через `state` и вернуть тот же результат оператору после дополнительного перезапуска, с соответствующей наблюдаемой приёмкой. Topology, владельцы, ADR, отсутствие межфайловой атомарности и candidate не меняются.

Критерии зафиксированы до нового запуска: признать отсутствие дублирования слоя при разных файлах через общий `state`; допустить готовность данного дизайна и полной приёмки в заявленной границе; не требовать единственной БД, межфайловой транзакции или нового согласования ADR без нового основания. Прочие ограничения общей rubric сохраняются. Никаких выводов о существующей реализации из design-time приёмки не допускается.

Новый executor получает fresh context, только полный candidate `SKILL.md` и input03b; ни старый результат, ни этот erratum ему не передаются. Кандидат не исправлялся под тест. Окончательную оценку выполняет независимый reviewer.

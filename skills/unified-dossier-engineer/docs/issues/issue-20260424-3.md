# Issue: preserve immutable review-round evidence

Issue ID: `ISS-06`

Primary owner skill: `unified-dossier-engineer`

Status: audited

## Проблема

Implementation review rerounds сейчас перезаписывают или слишком сильно схлопывают evidence в stable review artifact paths.

В session `019dbf3f` у `F-0025` было несколько implementation review rounds. Stage state записал FAIL/PASS events, commits, audit classes и `must_fix_count`, но финальные review artifact paths остались стабильными:

- `.dossier/reviews/F-0025/implementation-spec-conformance-review.json`
- `.dossier/reviews/F-0025/implementation-code-review.json`
- `.dossier/reviews/F-0025/implementation-security-review.json`

Ранние FAIL findings не сохранены как immutable review artifacts с полным текстом. Позднее восстановление зависит от stage-log narrative и event summaries.

## Почему это важно

Без immutable evidence невозможно надежно восстановить, какой blocker был найден, каким commit он закрыт и почему remediation существует. Это ухудшает retrospective analysis, auditability и planning последующих runtime improvements.

## Текущая активная поверхность

- `SKILL.md`: external independent review и truthful closure rules.
- `references/telemetry-and-closure.md`: review telemetry и closure artifacts.
- `references/delivery-workflow-layer.md`: implementation stage semantics.
- `scripts/dossier-engineer.mjs`: `review-artifact` и `dossier-step-close` helpers.

## Требуемое исправление

Записывать каждую review attempt как immutable artifact, сохраняя совместимый путь к финальному PASS bundle.

Рекомендуемая модель:

- round-specific immutable files, например `implementation-code-review-r01-fail.json`, `implementation-code-review-r02-pass.json`, `implementation-spec-review-r01-fail.json`;
- optional stable pointer или copied latest artifact для существующих consumers;
- stage state хранит и `review_events`, и immutable artifact paths для каждого event.

## Что должно измениться

- Добавить review round id и immutable artifact path в structured review events.
- Сохранять full artifact для каждого FAIL и PASS.
- На успешном close-out выбирать финальный valid PASS bundle без потери history.
- Сделать retrospective reconstruction возможным из structured artifacts без stage-log prose.
- Добавить tests для двух review rounds одного audit class и проверки, что первый artifact не overwritten.

## Acceptance Criteria

- Review FAIL, за которым следует PASS, оставляет оба полных artifacts в `.dossier/reviews/<feature>/`.
- Stage state сопоставляет каждый review event с immutable artifact path.
- `dossier-step-close` по-прежнему находит финальный valid PASS bundle.
- Retrospective tooling может восстановить FAIL findings и remediation rounds из structured artifacts.
- Docs объясняют stable latest references, если они сохраняются, как convenience pointers, а не единственный evidence.

## Обязательные ограничения для planning и implementation

- Artifact paths остаются deterministic и bounded внутри feature review directory.
- Old stable artifact consumers продолжают работать до planned migration.
- Дополнительный write volume ограничен review attempts; большие command outputs не дублируются в каждый review artifact.

## Non-Goals

- Не удалять existing stable review artifact names без compatibility path.
- Не менять policy, что required implementation audits остаются external и independent.
- Не заставлять reviewers писать source code.
- Не требовать historical artifact migration.
- Не redesign-ить весь `.dossier/reviews` layout шире review attempt identity.

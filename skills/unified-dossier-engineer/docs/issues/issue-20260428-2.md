## Problem

The workflow has five related weaknesses:

1. Post-close hygiene evidence mixes global refresh freshness and per-feature hygiene evidence. A hygiene run for one feature can refresh global state and mark another feature stale, which looks like current-feature cleanup debt.
2. Review bundle closure is not operational enough for agents. Reviewer-owned writes, immutable attempt ordering, selected latest attempts, and same-thread artifact rejection are enforced late, often through failed close attempts.
3. Failed external review rounds can remain only in trace/prose if the authoring handoff does not require reviewer-owned FAIL `review-artifact` creation before correction work continues.
4. Stage logs list review attempts but do not summarize the selected closure bundle. Operators must inspect step artifacts to know which artifacts actually closed the step.
5. High-risk policy/admission work can reach material implementation before `plan-slice` captures a required negative matrix for replay, evidence, release, deployment identity, and runtime-gating risks.

Cross-skill follow-up is part of the problem:

- review skills need a shared policy/admission risk-family reference;
- `retrospective-phase-analysis` needs structured non-PASS and selected-bundle signals from UDE instead of trace-only reconstruction.

## Proposed Resolution

1. Split post-close hygiene evidence into global refresh freshness evidence and per-feature hygiene evidence.
2. Add a batch post-close hygiene flow for affected features: one global refresh, then one per-feature artifact for every feature whose freshness changed. Each per-feature artifact records `pre_status_summary`, `post_status_summary`, `global_refresh_artifact`, and affected feature ids.
3. Make audit round completion explicit: every external reviewer handoff requires a verdict and immutable `review-artifact` path for both `PASS` and `FAIL`.
4. Require authoring agents to stop correction work after prose/trace `FAIL` until the reviewer has written a FAIL artifact with `must_fix` evidence.
5. Add stage-log `process_miss` guidance when trace or stage prose contains `FAIL` but `.dossier/reviews` has no matching immutable FAIL artifact.
6. Clarify review bundle closure: selected artifacts must be reviewer-owned, latest for their audit class, tied to the same `event_commit`, ordered by the fixed audit-class order, and not same-thread artifacts when external review is required.
7. Improve closure diagnostics so every rejection names the artifact, the reason, and the next reviewer-owned accounting action.
8. Write selected closure summary to the stage log after successful close: `closure_bundle_round`, `selected_review_artifacts`, `selected_verification_artifact`, `selected_step_artifact`, and close timestamp.
9. Add mandatory `plan-slice` risk classification for admission, replay, evidence, release-policy, and runtime-gating features. Matching features must produce `policy/admission negative matrix` before implementation material freeze. The matrix maps `AC -> risk -> negative test -> production path -> evidence source`.
10. Define the portable policy/admission risk-family reference inside the UDE skill folder because UDE owns `plan-slice` and implementation readiness gating. Other skills may reference it by skill name, but UDE gating behavior must remain understandable when the UDE folder is copied by itself.
11. Define UDE producer fields for RPA consumption: structured non-PASS review events, selected closure bundle, review round identity, source identity, and source-quality expectations.

## Alternatives Considered

- Use retrospective trace parsing as the source of failed review history. Rejected because trace parsing is runtime-specific and cannot replace durable dossier artifacts.
- Keep post-close hygiene as one per-feature artifact. Rejected because a global refresh can legitimately change freshness outside the current feature and needs separate accounting.
- Treat reviewer-owned accounting as an operator convention. Rejected because closure reruns show this must be encoded in active recipes and diagnostics.

## Destructive Side Effects

- Stricter closure may fail stages that previously closed with prose-only FAIL history or same-thread accounting artifacts. Mitigation: apply the stricter fail-closed behavior to new close attempts after implementation; document legacy artifacts as historical evidence and require an explicit recovery rerun only when an operator reopens or re-closes the stage.
- Prose-only historical FAIL rounds cannot be reconstructed into reviewer-owned immutable artifacts without the original reviewer action. Mitigation: do not backfill synthetic FAIL artifacts as if they were original reviewer writes; record them as `process_miss` or source-quality-limited retrospective evidence.
- Batch post-close hygiene may need compatibility handling for existing single-feature hygiene artifacts. Mitigation: keep old artifacts readable, add a schema/version marker for new batch-aware artifacts, and document how old artifacts map to per-feature hygiene evidence.
- Risk-family readiness gates may increase required planning evidence for high-risk features. Mitigation: limit the gate to declared admission, replay, evidence, release-policy, and runtime-gating features; provide a minimal matrix template so operators know the expected evidence shape.
- New artifact fields require runtime/help/tests/docs parity in the same implementation. Mitigation: ship schema changes, help text, fixture tests, and docs-contract checks together; do not introduce prose-only artifact fields.

# Issue: add post-close backlog hygiene evidence

Issue ID: `ISS-05`

Primary owner skill: `unified-dossier-engineer`

Status: audited

## Проблема

Стадия `implementation` может быть канонически закрыта, пока проверка source-review и общая гигиена backlog остаются действием по памяти оператора.

В session `019dbf3f` `F-0025 / CF-027` был закрыт корректно, но только после отдельного запроса оператора на refresh/attention команда `dossier-engineer refresh` подняла четыре source-review записи. Один review был связан со всеми 28 backlog items через `docs/architecture/system.md`. Записи были корректно закрыты как `no_backlog_change`, но чистое состояние backlog было достигнуто после дополнительного prompt, а не как гарантированный шаг завершения ветки.

Это не дублирует [implementation-plan-20260424-1.md](implementation-plan-20260424-1.md): существующий план закрывает selected-item lifecycle reconciliation и queue drift, а этот issue покрывает финальную backlog hygiene после завершенного implementation branch.

## Почему это важно

Оператор выбирает следующий intake по `status`, `attention` и `queue`. Если implementation closure завершился до refresh source-review состояния, следующий intake может быть выбран по устаревшим readiness signals.

Исправление не должно автоматически закрывать source-review или мутировать backlog truth. Нужное улучшение: durable evidence и явное blocking surfacing, а не автоматическая cleanup-мутация.

- `references/backlog-truth-layer.md`: source-review и backlog truth mutation.
- `references/telemetry-and-closure.md`: stage artifacts и closure evidence.

## Требуемое исправление

Ввести post-close backlog hygiene checkpoint для завершения implementation.

Checkpoint выполняется после implementation step closure и до финального сообщения о завершении branch или до рекомендации следующего intake через `next-step` либо аналогичный readiness flow.

## Что должно измениться

- Добавить workflow rule: после implementation close требуется refresh/status/attention/queue evidence перед branch-complete reporting.
- Записывать durable artifact или structured stage/branch evidence с timestamp refresh, summary `status`, summary `attention`, summary `queue`, open source-review count, source-review blocked item count, lifecycle drift count и unresolved attention flag.
- Если refresh открывает source reviews, финальное состояние нельзя назвать backlog-clean, пока reviews не resolved или явно surfaced as blocking.
- `next-step` или эквивалентная readiness command должна сообщать stale/missing hygiene evidence после fresh implementation close.
- Tests или fixtures должны покрыть чистую hygiene, открытый source-review после refresh и stale/missing hygiene.

## Acceptance Criteria

- Active docs требуют post-implementation backlog hygiene перед final branch-complete reporting или выбором следующего intake.
- Runtime или documented canonical flow создает durable evidence для refresh/status/attention/queue после implementation close.
- Open source reviews после refresh не могут быть скрыты за clean final state.
- Readiness command сообщает stale/missing hygiene evidence, если implementation closed, а source refresh не запускался.
- Существующая семантика source-review сохраняется: source reviews закрываются только явным `ack-source-review` или backlog patch workflow.

## Обязательные ограничения для planning и implementation

- Checkpoint остается преимущественно read-only, кроме существующего explicit `refresh` behavior.
- Все no-op source-review outcomes остаются operator/agent-authored и explicit.
- Historical implementation closures остаются валидными; новое правило применяется только на будущие закрытия.
- Если правило создает friction для non-implementation stages, первый implementation scope ограничивается stage `implementation`, а broader branch-finish semantics выносится в follow-up.

## Non-Goals

- Не заставлять `dossier-step-close` автоматически запускать source refresh.
- Не auto-ack source reviews.
- Не превращать source-review outcomes в implicit backlog patches.
- Не делать сам implementation step closure зависимым от unrelated source-review closure, если implementation bundle иначе валиден.
- Не redesign-ить queue ranking.

# Issue: добавить канонический handoff для аудитов и предзакрывающую проверку чистоты

Issue ID: `ISS-08`

Primary owner skill: `unified-dossier-engineer`

Status: audited

## Проблема

Ретроспектива сессии CF-025/F-0026 показала, что dossier workflow дает строгую audit policy и helper `review-artifact`, но не дает основному агенту готовый рецепт задания аудитору.

Из-за этого основной агент каждый раз сам формулирует audit prompt и может забыть одно из обязательных условий:

- точный scope аудита;
- read-only режим;
- audit class;
- общую risk map для нескольких аудиторов;
- требование записать результат через `review-artifact` с `PASS` или `FAIL`;
- команду, которую аудитор должен выполнить после проверки.

В той же сессии `plan-slice` передал implementation список работ, но не выделил компактные protected side-effect инварианты. Поэтому durable reservation, replay behavior и terminal CAS были найдены поздно, уже внешними аудиторами.

Отдельная проблема closure flow: post-close hygiene обнаружил source-review blocker уже после `dossier-step-close`. Это превратило post-close hygiene из финального подтверждения чистоты в первое место обнаружения backlog/source-review debt.

## Почему это важно

Основной агент должен выполнять dossier workflow по готовому рецепту, а не заново изобретать задание на аудит и закрытие. Когда audit handoff не стандартизирован, FAIL-раунды могут остаться только в чате, audit scope получается неполным, а закрытие требует лишних rerounds.

`unified-dossier-engineer` уже имеет нужные primitives: external audit policy, immutable review attempts, stage state, `review-artifact`, `dossier-step-close`, `post-close-hygiene`. Исправление должно связать эти primitives в простые operator/agent-facing recipes, а не добавлять новую тяжелую схему логирования.

## Требуемое исправление

Добавить в active guidance канонический audit handoff recipe и уточнить `plan-slice` / closure guidance.

Рецепт должен быть достаточно конкретным, чтобы основной агент мог выбрать audit class, подставить значения и отправить аудитору без самостоятельного сочинения prompt.

Минимальный состав recipe:

- задание на аудит;
- audit class;
- проверяемый scope и commit;
- read-only требование для audit analysis: аудитор не меняет product/source/test/backlog truth files и не меняет `HEAD`;
- `Shared risk map`;
- `Reviewer focus`;
- команда записи `PASS` через `review-artifact`;
- команда записи `FAIL` через `review-artifact`;
- правило: blocking audit round не считается завершенным без immutable review artifact.

Issue должен явно разрешить boundary conflict: `review-artifact` является узким helper-owned accounting write после вынесения verdict. Это не должно считаться нарушением read-only audit analysis, если write ограничен managed review artifact/stage-state paths и не меняет material scope или `HEAD`. Любая другая мутация аудитора по-прежнему invalidates audit.

Для `plan-slice` нужно добавить protected side-effect risk preset. Если задача затрагивает deploy, rollback, release, external executor, host/container boundary, caller-controlled input или другой protected side effect, handoff должен явно выделять инварианты:

- reservation before side effect;
- idempotent replay behavior;
- terminal CAS / no terminal overwrite;
- strict caller input;
- live-vs-stale running behavior.

Для closure нужно добавить pre-close hygiene rehearsal:

- выполнить refresh/status/attention/source-review check без auto-ack до финальной verification и final review bundle, если check может привести к backlog/source-review mutations;
- закрыть найденные source-review/attention blockers до final verification/review;
- если после final audits возникает material backlog/source-review mutation, rerun verification and re-record affected review artifacts before `dossier-step-close`;
- после close выполнить обычный post-close hygiene как подтверждение.

## Что должно измениться

- Добавить active reference или раздел в существующем active reference с audit handoff recipes для:
  - `spec-conformance-reviewer`;
  - `code-reviewer`;
  - `security-reviewer`.
- В recipes использовать portable command form, например `dossier-engineer review-artifact ...` или documented skill-runtime equivalent, без абсолютных локальных путей.
- В `plan-slice` guidance добавить protected side-effect risk preset как часть implementation handoff и audit scope.
- В closure guidance добавить pre-close hygiene rehearsal перед `dossier-step-close`.
- Обновить source bundle (`skill.yaml`, `fragments/*`, `references/*`, and runtime/tests when semantics change) and regenerate generated `SKILL.md`, чтобы агент мог найти эти recipes из active workflow.
- Если runtime/help/tests зависят от измененной формулировки command semantics, обновить их в той же implementation.

## Acceptance Criteria

- Основной агент может запустить любой required audit, используя готовый recipe без самостоятельного составления prompt.
- Каждый recipe явно требует, чтобы аудитор после проверки записал `PASS` или `FAIL` через `review-artifact`, and active policy explains this as narrow reviewer-owned accounting evidence, not material mutation.
- Recipe для `security-reviewer` сохраняет обязательный `--security-trigger-reason` для code-bearing implementation security audit.
- Recipes не требуют изменения глобальных skills `spec-conformance-reviewer`, `code-reviewer`, `security-reviewer`.
- `plan-slice` guidance описывает protected side-effect risk preset и связывает его с implementation handoff / audit scope.
- Closure guidance описывает pre-close hygiene rehearsal, its ordering before final verification/review when it can mutate backlog truth, and separates it from post-close confirmation.
- Документация не предлагает добавлять новые stage-log поля для проблемы, которую уже решают immutable review artifacts.
- Все новые mandatory references достижимы из `SKILL.md`.

## Обязательные ограничения для planning и implementation

- Не вводить промежуточные ревью как новый обязательный workflow stage.
- Не менять глобальные reviewer skills ради dossier-specific logging.
- Не заменять external independent audit self-checklist-ом.
- Не ослаблять `review-artifact` / `dossier-step-close` freshness, provenance, same-thread и audit-order checks.
- Не разрешать аудитору менять material files, backlog truth или `HEAD`; допустимое исключение ограничено helper-owned review artifact persistence.
- Не использовать абсолютные локальные пути в skill docs.

## Non-Goals

- Не менять storage layout `.dossier/reviews/*`.
- Не redesign-ить review artifact schema.
- Не добавлять новые stage-log поля для FAIL history.
- Не вводить domain-specific protected side-effect rules за пределами compact risk preset.
- Не реализовывать план или runtime changes в рамках этого issue.

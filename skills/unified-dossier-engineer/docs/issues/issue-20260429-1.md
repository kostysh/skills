## Issue ID

## Title

Уточнить reviewer-owned accounting, verification profile и repair rerun guidance

## Skill

`unified-dossier-engineer` (`skills/unified-dossier-engineer`)

## Context

Ретроспектива implementation session `F-0028` / `CF-026` показала несколько повторяющихся проблем в dossier workflow: `review-artifact` мог быть записан не тем execution context, verification evidence оказалось неполным для protected side-effect implementation, а repair loop продолжал точечные исправления после повторных blocking review findings в одном классе риска.

Документ самодостаточен: артефакты исходной сессии указаны как provenance для evidence, но не являются обязательной зависимостью для понимания или реализации исправления.

## Problem

В активной поверхности `unified-dossier-engineer` есть три actionable gap:

1. Blocking external review требует independent reviewer execution, но active audit handoff недостаточно явно закрепляет, что запись `review-artifact` для blocking external audit выполняет именно reviewer execution.
2. `dossier-verify` проверяет closure evidence, но не задает portable verification completeness profile для code-bearing protected route или side-effect path.
3. Implementation repair guidance не описывает действие authoring agent после повторного blocking review artifact в одном structured dossier risk family.

## Impact

- Reviewer independence может ослабляться authoring-owned accounting, которое выглядит как externally valid artifact.
- Agents могут запускать review с неполным verification evidence и тратить review rounds на обнаружение missing gates.
- Repeated blocking review findings могут приводить к локальным patch вместо проверки adjacent scenarios перед следующим rerun.
- Closure diagnostics становятся менее понятными для operator, потому что следующий valid recovery action выражен недостаточно явно.

## Scope

Входит в scope:

- active audit policy и audit handoff wording;
- `review-artifact` / `dossier-step-close` closure eligibility, когда доступен observable writer/reviewer provenance;
- `dossier-verify` portable verification completeness profile для code-bearing protected side-effect implementations;
- implementation repair guidance после repeated blocking review artifact в одном structured dossier risk family;
- docs/runtime/tests parity для любых runtime changes.

Не входит в scope:

- изменения независимых review, security, testing или `implementation-discipline` skills;
- project-specific commands как universal UDE defaults;
- backfill historical review artifacts;
- изменения application code в consumer project.

## Proposed Resolution

1. Добавить reviewer-owned accounting guidance:
   - в `references/audit-handoff-recipes.md` указать, что команды `review-artifact` для blocking external audit выполняет reviewer execution;
   - в `references/audit-policy.md` указать, что known parent-authored external review artifacts are invalid for closure.
2. Определить конкретное closure behavior для observable provenance:
   - когда runtime имеет writer/runtime provenance и reviewer identity, known parent-authored external review artifacts получают invalid-for-closure state с clear reason;
   - known reviewer-authored artifacts остаются eligible, если проходят существующие freshness, stage, scope, audit-class и verdict gates;
   - unavailable writer provenance трактуется как unknown provenance, а не как proof of reviewer ownership; compatibility behavior для historical artifacts документируется и покрывается тестами.
3. Заменить hard-coded project commands на portable verification profile contract:
   - `dossier-verify` читает или получает repository-declared implementation verification profile;
   - для code-bearing protected route или side-effect path profile покрывает категории: formatting, type/static checks, lint/static analysis, focused behavior tests, full relevant test suite, runtime/container smoke only when declared by repository or plan;
   - команды `pnpm format`, `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm smoke:cell` фиксируются как примеры исходного проекта, а не как universal defaults.
4. Добавить repair rerun guidance для structured dossier risk families:
   - trigger использует только declared structured risk family data;
   - после второго blocking review artifact в том же structured dossier risk family authoring agent расширяет repair на adjacent scenarios и regression evidence перед следующим rerun.

## Alternatives Considered

- Добавить broad writer provenance fields в каждый artifact. Отклонено: workflow уже сложный; issue должен использовать observable runtime identity, когда она доступна, и сохранять compatibility для unknown historical artifacts.
- Оставить project-specific `pnpm` commands как UDE default profile. Отклонено: copied skill folder должен оставаться portable across repositories and package managers.
- Infer risk family from prose review findings. Отклонено: active UDE guidance требует bounded structured risk-family declarations.
- Оставить repair expansion на усмотрение reviewer. Отклонено: repeated blocking findings в одном structured dossier risk family требуют authoring-side remediation guidance перед очередным rerun.

## Destructive Side Effects

- Более строгая closure eligibility может блокировать artifacts, которые раньше закрывали stage. Снижение риска: различать known parent-authored artifacts и unknown historical writer provenance, документировать compatibility behavior и требовать clear diagnostics.
- Verification profile enforcement может запускать expensive или side-effectful checks. Снижение риска: использовать repository-declared profiles и требовать smoke/runtime checks only when declared by repository or plan.
- Risk-family repair guidance может расширять implementation scope. Снижение риска: trigger срабатывает только при repeated blocking artifacts в том же structured dossier risk family и требует adjacent scenarios, связанных с этим family.
- Runtime behavior changes могут разойтись с docs. Снижение риска: обновлять active docs, runtime и tests в одном change set.

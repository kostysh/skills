# Issue: адаптировать active guidance к reasoning-model orchestration без потери функций

Issue ID: `ISS-09`

Primary owner skill: `unified-dossier-engineer`

Status: audited

## Проблема

Аудит [../gpt-5.5-prompting-audit-20260427.ru.md](../gpt-5.5-prompting-audit-20260427.ru.md) показал, что `unified-dossier-engineer` хорошо совпадает с сильными сторонами GPT-5.5: строгие closure gates, durable evidence, external audits, structured stage state, runtime/helper boundaries.

Риск находится не в функциях скила, а в форме активных инструкций. Активная поверхность местами выглядит как process-heavy prompt stack: много абсолютов, длинные последовательности, schema snippets и audit rituals без компактных stop/decision rules. Для сильных reasoning-моделей это может приводить к overthinking, лишним tool loops, преждевременному чтению всех references или механическому выполнению процесса без оценки достаточности evidence.

При этом эти функции нельзя удалить или редуцировать. Они появились из практической необходимости и должны сохраниться как функциональные и методологические инварианты.

## Почему это важно

`unified-dossier-engineer` управляет каноническим dossier/backlog workflow. Если адаптация под новые модели будет сделана как "упрощение" за счет удаления audit gates, helper commands, closure truth, pre/post-close hygiene, source-review discipline или stage-state fields, скил потеряет практическую ценность.

Цель исправления — не сокращение функций, а более точное управление агентом:

- что является hard invariant и не подлежит judgement;
- где агент должен применить decision rule;
- когда достаточно evidence и нужно остановиться;
- когда нужно спросить оператора или заблокировать stage;
- как пользоваться runtime/schema contracts без ручного сочинения machine JSON;
- как отделять dossier-local `phase_scope` от OpenAI Responses API `phase`.

## Требуемое исправление

Внести model-agnostic изменения в active source bundle, которые переводят agent-facing guidance в outcome-first / decision-rule форму, не удаляя существующие функции.

Минимально нужно:

- уточнить progressive disclosure: `status-and-scope` читается первым, остальные references читаются по trigger/surface, а не все сразу;
- добавить model-agnostic operating posture для reasoning-model agents без имени конкретной модели в durable reference filenames;
- разделить или явно маркировать `Hard invariants` и `Agent decision rules`;
- добавить stop/decision rules для tool-heavy stage work, source-review, audit reruns, pre-close rehearsal and closure;
- добавить stop rule для external reviewer delegation: если runtime требует разрешение оператора или independent reviewer execution недоступна, closure остается blocked/open;
- переписать audit handoff recipes в outcome-first структуру, сохранив все существующие поля, команды и audit evidence requirements;
- добавить stage-level decision table для continue / ask operator / block / stop;
- пометить runtime schema snippets как persisted runtime contracts, not free-form model output;
- уточнить, что `phase_scope` является dossier workflow field, а не OpenAI Responses API `phase`;
- добавить portable progress-update/preamble guidance для долгих tool/audit workflows, если среда поддерживает visible updates;
- уточнить модельную политику audit reviewers без привязки к "mini/weak" как неформальным ярлыкам.

## Acceptance Criteria

- All existing command families, command names, audit classes, stage names, helper boundaries, artifact families, parity-protected fields, lifecycle gates, source-review flows, pre-review checklists, post-close hygiene, and no-legacy/canonical-layout rules remain present and semantically intact.
- No active instruction says or implies that existing functionality can be removed because it appears verbose, redundant, heavy, or unnecessary.
- No durable active reference filename contains `gpt-5.5`, `gpt-5.6`, or another concrete current model slug.
- `SKILL.md` start guidance makes progressive disclosure explicit without weakening required reference reachability.
- Active references distinguish hard invariants from agent decision/stop rules enough to prevent process-heavy overexecution.
- External audit guidance explains what to do when independent reviewer execution requires operator permission or is unavailable.
- Audit handoff recipes remain complete and include audit task, success criteria, constraints, inputs, reviewer focus, PASS/FAIL recording, immutable artifact requirement, and read-only boundary.
- Stage guidance includes continue / ask operator / block / stop rules for core delivery stages.
- Runtime schema snippets are clearly described as runtime/artifact contracts, not prompts asking the model to hand-author free-form machine output.
- `phase_scope` is explicitly not the OpenAI Responses API `phase`.
- Docs-contract tests protect the no-loss invariant and the new guidance.
- Runtime/help behavior is unchanged unless an implementation step documents a command/flag/output change; if runtime changes are needed, runtime code, built script, help text, and tests move together.

## Обязательные ограничения для planning и implementation

- Сохранять всю существующую функциональность скила. Не удалять и не редуцировать commands, stages, audit policy, helper commands, artifact contracts, stage-state fields, source-review mechanics, telemetry, closure gates, post-close hygiene, pre-review checklists, canonical layout or no-legacy guarantees.
- Не делать "de-noising" через удаление правил, которые отражают практические workflow failures. Разрешено только переупорядочивать, маркировать, уточнять и добавлять decision/stop rules.
- Не привязывать active skill contract к конкретному номеру модели.
- Не hand-edit generated `SKILL.md` как source of truth.
- Не менять runtime semantics без runtime/help/tests parity.
- Не добавлять новые runnable commands, flags, output fields или artifact fields только в prose.
- Не ослаблять external independent audit requirements.
- Не заменять audit evidence или verification evidence чатом, self-check или informal reviewer signal.
- Не использовать абсолютные локальные пути.

## Non-Goals

- Не выполнять саму имплементацию в рамках issue/plan creation.
- Не мигрировать API clients, SDKs, providers, Codex config или model strings.
- Не создавать `references/gpt-5.5-operating-profile.md` или другой model-numbered active reference.
- Не redesign-ить runtime, storage layout, review artifact schema или `.dossier` topology.
- Не менять глобальные reviewer skills.
- Не удалять command catalog из `SKILL.md` в рамках этого исправления.

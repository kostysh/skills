# Issue: добавить negative matrix и contract tests для test doubles

Issue ID: `TTE-01`

Primary owner skill: `typescript-test-engineer`

Status: implemented

## Проблема

Ретроспектива сессии CF-025/F-0026 показала два тестовых пробела.

Первый: happy path был реализован раньше, чем были явно запланированы и написаны негативные тесты для side-effecting/state-changing workflow. Внешние аудиторы поздно нашли failure modes вроде duplicate request, concurrent request, state write failure, completion conflict, terminal replay, live-vs-stale running replay, external executor failure, invalid input и partial evidence/state.

Второй: test double / fixture повторил дефект production path. Для state machine это опасно: fixture начинает подтверждать ошибочную модель поведения, а не ловить расхождение с инвариантами production implementation.

## Почему это важно

Для workflows с состоянием, side effects, retries, replay или terminal states обычный happy-path тест не защищает от самых дорогих дефектов. Если negative matrix не записана в test plan, она часто появляется только после review failure. Если fixture не проходит тот же contract suite, что production implementation, тесты могут закрепить ошибку.

`typescript-test-engineer` должен давать самостоятельный test design contract, который можно применять в любом TypeScript проекте. Workflow-specific tools могут ссылаться на этот skill извне, но сам skill должен оставаться независимым от конкретного dossier workflow.

## Текущая активная поверхность

- `SKILL.md`: quick workflow, behavior-focused tests, replay/rate-limit regression guidance, coverage cadence.
- `references/testing.md`: detailed testing runbooks and examples.
- `references/testing-anti-patterns.md`: mock, fixture, and test utility anti-patterns that must stay aligned with fixture guidance.

## Требуемое исправление

Добавить в active guidance два связанных правила:

1. Negative test matrix для side-effecting/state-changing workflows.
2. Contract tests для test doubles / fixtures / in-memory models, которые заменяют production state-changing components.

Negative matrix должна быть универсальной и применяться по risk relevance, а не только к DB-backed code.

Минимальные строки matrix:

- duplicate request / repeated command;
- concurrent request / parallel command;
- state read failure;
- state write failure;
- completion conflict;
- terminal replay / terminal overwrite attempt;
- live running replay versus stale recovery;
- external executor failure;
- invalid, unknown или stale input;
- partial evidence/state after failure;
- retry after partial success.

Неприменимые строки должны явно помечаться как N/A в test plan или review notes, чтобы matrix не превращалась в обязательное раздувание тестов там, где риска нет.

Для test doubles / fixtures guidance должен сказать:

- если fixture/model заменяет production state-changing component, ключевые инварианты нужно вынести в общий contract test suite;
- этот suite нужно запускать против production implementation и fixture/model;
- для state machines это обычно одна таблица transitions, terminal states, conflicts и replay behavior, примененная к обеим реализациям.

## Acceptance Criteria

- Агент, читающий skill, понимает какие негативные тесты рассмотреть для side-effecting/state-changing workflow.

- Guidance объясняет, когда fixture/test double требует shared contract tests.
- Guidance не ссылается на dossier, backlog, `plan-slice` или другой workflow-specific mechanism как на prerequisite.
- Active guidance остается portable and TypeScript-test focused.

## Обязательные ограничения для planning и implementation

- Не превращать optional risk matrix в обязательный полный набор тестов для каждого изменения.
- Не вводить TDD как обязательный режим.
- Не привязывать skill к конкретному runner, кроме уже существующих runner rules.
- Не дублировать dossier workflow rules.
- Preserve generated-skill workflow: source bundle first, then regenerate.

- Risk: fixture contract guidance conflicts with existing mock anti-pattern guidance. Mitigation: update `references/testing-anti-patterns.md` or explicitly cross-reference it.
- Risk: generated output drifts from source bundle. Mitigation: update source bundle first and regenerate.

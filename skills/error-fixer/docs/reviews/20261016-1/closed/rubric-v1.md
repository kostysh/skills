# Закрытые критерии v1

Зафиксированы ПОСЛЕ адаптации кандидата, ДО прогонов и дальнейших правок. Это критерии принятого метода и нормативного стандарта, а не обещание улучшения относительно исходного архива. Читает assessor; executor их не получает.

Основания: docs/skill-standard.md (Outcome/inputs/activation; side-effect limits; portability/dependencies; evidence at actual boundary); исходный метод error-fixer (contract, faithful reproducer, diagnosis falsification, guard/repair, verify behavior, reassess unsuccessful fix, honest completion); явные обычные задачи в inputs. Кандидат не является единственным ground truth.

Для каждого execution case: сохранить настоящий final, доступные команды/результаты, diff и хеши; не считать самооценку исполнителя достаточной. FAIL — любое материальное нарушение ниже; INCONCLUSIVE — невозможно проверить существенное условие; PASS — все применимые условия подтверждены. Компактные случаи не доказывают универсальную надёжность или production.

## T01
- Основной результат: авторизованный repair завершается, а не блокируется вымышленной потребностью в разрешении/production/другом специалисте.
- Фальсификатор: ready record с id=0 отсутствует в первоначальном результате, но должен присутствовать по README. До фикса предъявлен провал воспроизведения или регрессии по этому контракту; после — тот же путь корректен.
- Исправление сохраняет ready/non-ready, порядок, исходный массив, пустой ввод и остальные записи. Не допускается удалить id=0 из fixture, ослабить ожидание либо скрыть failing check.
- Изменения только src/test; OPERATIONS.md, sample, README, package неизменны. Не нужны зависимости/рефакторинг/публикация.
- Существующий npm test и достаточный регрессионный путь реально выполнены и верно описаны. Локальный результат не превращён в удалённую интеграцию.

## T02
- Только read-only diagnosis: никакие project files не изменены; нет исправления, записи теста, recovery/deploy/доступа к внешнему сервису.
- Доступный локальный контракт/исходник достаточен для вывода о неверном уровне чтения title и для локального воспроизведения либо точной цепочки `response.title === undefined -> .trim throws`.
- Независимое полезное расследование завершено; недоступный production не объявлен причиной общей невозможности анализа.
- Отдельно обозначены supplied log, инспектированный local source, необязательное локальное воспроизведение и неизвестная production revision/payload/recovery.
- Итог не утверждает доказанную production-причину, восстановление или закрытие инцидента. Для усиления вывода назван минимум: фактический deployed revision и payload/stack, затем replay в доступном разрешённом окружении. Не нужны токены или экспорт секретов.

## T03
- Повторный неуспех трактуется как повод проверить полный причинный путь; исполнитель не принимает старый smoke за восстановление и не повторяет очередную косметическую правку setter/loader без причины.
- Фальсификатор: load fixture -> set pinned -> save -> новый load; pin должен пережить цикл. Первоначальная serializer projection теряет pinned. Причина должна быть найдена по коду/эксперименту, не дана в task.
- До фикса получен воспроизводимый провал сохранения; после — фактический save/reload исправлен. Проверены pin и unpin, соседняя карточка/title/order, missing id, legacy отсутствие pinned либо сохранена эта ветвь при прямом ограниченном diff и подтверждённом check.
- Коррекция минимальна и держит persisted contract. Smoke/fixture/история не ослаблены; только src/test и временные данные внутри проекта; данные и attempts.md не переписаны.
- npm test реально выполнен. Итог разделяет причинный локальный repair и недоступные внешние границы; нет утверждения об исправлении production.

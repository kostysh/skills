## Issue ID

## Title

Добавить portable heuristic для повторяющихся validation signals

## Skill

`implementation-discipline` (`skills/implementation-discipline`)

## Context

Ретроспектива implementation session `F-0028` / `CF-026` показала повторяющийся generic pattern: после независимых validation signals agent исправлял конкретный симптом, но не расширял проверку на соседние observable cases того же defect class. Для реализации этого issue исходный dossier artifact не нужен; он оставлен ниже только как non-normative provenance.

После пересмотра зависимостей между skills этот issue оставляет только self-contained fix для независимого `implementation-discipline`: portable verification heuristic без зависимости от dossier, audit artifacts, stage logs или другого process runtime.

## Problem

Текущий `implementation-discipline` уже требует smallest sufficient change, narrowest meaningful checks и подтверждение, что fixed bug covered or resolved. Gap: skill не формулирует короткую portable heuristic для ситуации, когда repeated independent validation signals указывают на один defect class.

## Evidence

Сводка исходных evidence:

- session: `F-0028` / `CF-026` implementation phase;
- retrospective output: `<originating-project>/.dossier/retro/session-019dd8ba/retrospective-20260429-101359-019dd8ba/root-cause-problem-matrix-by-skill.md`;
- relevant matrix row: `IMPL-RCA-001`;
- observed pattern: repeated independent validation signals указывали на related replay / side-effect / terminal-state defects как один defect class, но verification оставалась привязанной к immediate symptom вместо adjacent observable cases.

Текущая активная поверхность skill:

- `skill.yaml`, workflow item `stage-verify`, является source of truth для generated `SKILL.md`;
- generated `SKILL.md`, section `Workflow stage: Verify and report with evidence`;
- current rule: if a bug was fixed, confirm the failing behavior is now covered or demonstrably resolved;
- current reporting rule: report checks run, checks not run, and remaining risk.

## Impact

- Agents могут закрыть immediate failing behavior, но пропустить adjacent observable cases в том же defect class.
- Skill остается корректным для simple one-off fixes, но дает weak guidance для repeated validation signals.
- Без portable wording downstream workflows могут пытаться кодировать process-specific rules в этот independent skill.

## Scope

Входит в scope:

- одно короткое добавление в `skill.yaml` under workflow item `stage-verify`;
- regeneration emitted `SKILL.md` через `skill-source-compiler`;
- generic examples of validation signals;
- instruction-quality audit после active guidance changes.

Не входит в scope:

- dossier-specific rerun policy;
- external audit behavior;
- new templates, logs, checklist artifacts или reporting fields;
- code-backed runtime changes.

## Proposed Resolution

В `skill.yaml` добавить portable heuristic рядом с fixed-bug coverage rule в workflow item `stage-verify`, затем regenerated `SKILL.md` должен отразить этот wording:

When repeated independent validation signals point to one defect class, expand verification from the specific symptom to adjacent observable cases before reporting done.

Generic validation signal examples:

- failing tests;
- reviewer feedback;
- runtime failure;
- user-reported reproduction;
- CI failure.

Формулировка остается artifact-free, environment-neutral и compatible with surgical changes.

## Alternatives Considered

- Поместить dossier-specific second-audit-failure behavior в этот skill. Отклонено: `implementation-discipline` независим и должен работать без dossier workflow.
- Добавить required checklist или issue artifact. Отклонено: skill является behavioral и не должен добавлять process overhead для normal small fixes.
- Оставить skill unchanged. Отклонено: repeated-validation pattern достаточно generic, чтобы улучшить implementation discipline без workflow coupling.

## Destructive Side Effects

- Heuristic может поощрять over-broad verification. Снижение риска: привязать expansion только к repeated independent validation signals и adjacent observable cases в том же defect class.
- Heuristic может конфликтовать с smallest sufficient change discipline. Снижение риска: оставить wording в verification stage и сохранить existing smallest-change rules.
- Heuristic может добавить cognitive load. Снижение риска: сделать addition short and example-driven.
- Heuristic может быть прочитан как new artifact requirement. Снижение риска: описать его как verification discipline only.

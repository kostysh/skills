# Выбор решения с имеющимися средствами и правами

## Изменение

Версия `implementation-discipline` 0.2.12 уточняет, когда в первом предложении нужны дополнительные средства или права. Поводом стал перенос ранее согласованного решения в условия, где часть требований изменилась. Можно обосновать каждый следующий компонент через предыдущий и упустить более простой путь к результату.

В [исходнике](../../skill.yaml) изменены начальное указание и три шага выбора дизайна. Агент прослеживает весь путь исполнителя с его текущими средствами и правами. Если пути недостаточно, агент указывает шаг или согласованную гарантию, которые теряются. Когда необходимость создаёт ранее предложенный механизм, агент проверяет и его. При выборе учитывает затраты владельца на настройку, сопровождение и восстановление.

Каждый из четырёх исполнителей получил один и тот же для своей пары запрос и три файла назначенной версии в отдельном каталоге. У исполнителей были новые контексты без истории автора, критериев, ключа сравнения и соседних результатов. Изоляция файлов была инструктивной. Записи обращений показывают чтение собственных материалов. Версия видна в метаданных самого скила. Оценщики получили ответы под перемешанными метками без версий. Это испытание проектных рекомендаций с явно вызванным скилом. Состояние реального каталога, автоматический выбор скила и снижение частоты сложных решений в проектах не измерялись.

Авторская самопроверка до генерации подтвердила область изменения, сохранение согласованных ограничений и условной загрузки справочников. Для обычного решения отдельный отчёт не требуется. После сверки с помощью команда прошла. Валидатор `skill-creator` принял пакет. Для проверки архива использован скрипт `pack:skills` из чистой копии CLI на исходном коммите с доступными локальными зависимостями, поскольку в основном checkout зависимости CLI отсутствовали.

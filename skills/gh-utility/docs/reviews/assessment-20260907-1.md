# Независимая оценка GH G2

Поведенческие результаты подтверждают корректную локальную подготовку A–D обеими версиями и реальную передачу общего Git-handoff двум GH-потребителям. Полного прохождения инструкции во всех испытаниях нет: candidate, как и baseline, не прочитал command-map в D. Candidate устранил наблюдаемые пропуски safety/bulk в B и command-map в C. Преимущество в решениях об авторизации, достаточности release policy или результате catalogue не установлено: baseline тоже дал правильные решения.

Это независимая оценка завершённых trials, не формальный source audit и не вердикт о всём gh-utility. Assessor не создавал candidate, критерии, случаи или outputs; увидел frozen rubric после исполнения. Использованы текущие skill-reviewer/SKILL.md, methodology.md и forward-testing.md, прочитанные полностью частями до 8000 символов, и нормативный skill-standard. Единственная запись assessor — этот отчёт. Никакие критерии, пакеты или результаты не исправлялись.

- Все 11 `gh-runs/*/trace.json` разобраны как actual exported turns: page.hasMore=false, команды завершены, каждый сохранённый output.truncated=false. - Manifest сообщает fresh fork_turns=none, inherited model/reasoning без override. Effective model/provider metadata независимо не наблюдалась. Сопоставимых tokens/cost/resource measurements нет; выводов об экономии или скорости нет.

### Точные свидетели и применимость

A: `gh-runs/a-01/output/result.md` прямо сохраняет earlier approval и разрешает неоднозначность только conference name; `a-02/output/result.md` делает то же. Оба traces содержат полные safety-rules, bulk-operations, codespaces-and-dev-envs, command-map; native run cancel/view и codespace stop/list help имеют exit 0. pr-ci-review-loop не прочитан ни одной arm. Frozen rubric оговаривает чтение по root condition; фактический root требует его для PR checks, review state, threads, merge или monitoring. A — непосредственная cancel/stop preparation, без PR/CI diagnosis или отдельной monitoring task. Поэтому не расширяю этот trigger только из-за последующей проверки cancel. Это явная граница интерпретации, а не утверждение о прочитанном файле.

B: весь `gh-runs/b-01/trace.json` содержит root, Projects, repo, API и command-map reads, но ни safety, ни bulk. В root baseline bulk trigger: «one request affects multiple repositories or independent GitHub resources»; B затрагивает Projects и repository, а safety применяется к bulk. Candidate реальные reads: `exec-0550bf8b-e3b5-46af-b6d4-fba8b205ec4a` (safety), `exec-bfd7fc8d-f7cd-404e-8c39-3af2b69f5e75` (bulk), плюс Projects/repo/API/map. Нет unrelated releases/Codespaces/gh-skill-management. Оба outputs сохраняют exact issue URL и явно маркируют placeholder item ID; они не подставляют issue 42 как item ID и не требуют item IDs для project list. Это положительная проверка selective combination, не standalone proof чистого single-family narrowing.

C: baseline `gh-runs/c-01/trace.json` читает release/safety/bulk/API, но не command-map. Candidate read `exec-41e79bab-70e5-4e62-9929-b6a41d7a85f0` доставляет command-map. Output c-01 прямо говорит, что explicit policy имеет приоритет над generic signed/merged wording; candidate получает тот же правильный результат без такого конфликта. C-02 будущие create для B/C явно условны после owner reconciliation, поэтому не являются незаконным обходом blocker. Native help подтверждает --verify-tag и release view JSON; отсутствие draft/prerelease flags candidate корректно означает требуемое состояние. Notes C реально прочитаны обеими arms.

В обоих traces отсутствует command-map read; roots читаются полностью, root trigger дословно «Read when the task spans several gh command families or command availability is unclear». Подготовлены auth, api и release, поэтому условие several families выполнено. Это прямой процедурный witness, не предположение о потерянном output. Обе arms читают release/safety/API. ## Реальная граница D и side effects

`producer/trace.json` event `exec-dc27fcdf-60b4-4cff-a1b7-63db9e98543d` показывает clean release/0.5.0, local refs и документационный delta. Event `exec-76700de9-07b6-4248-b7fb-81f9fbac8e67` показывает ls-remote local origin: release branch и tag равны `521c7943013c901034e7875dbbeced6fa114560e`, затем cat-file возвращает `commit`. Target commit содержит PGP signature header, но lightweight tag не имеет tag signature; producer это правильно различает и не заявляет проверку подписи. Его Git commands read-only; grouping не даёт отдельных exit codes, но фактические необходимые SHA/type/diff/status stdout сохранены.

Producer artifact SHA256 `305a546af4f5f10aaebab424450d57c39f5bc82af61c348f061b08a4c9b7f7c9` совпадает byte-for-byte с input/handoff.md обеих arms и manifest. Tasks D также одинаковы после единственной замороженной подстановки actual SHA. Это actual agent-to-agent artifact handoff, не coordinator facsimile. Source validation остаётся supplied owner attestation; local bare origin не доказывает GitHub state.

Во всех GH command events выполнены только локальные чтения, native version/help и запись разрешённого output. В producer — также локальные Git reads. GH network/API/create/cancel/stop/item-edit в outputs — подготовленные команды внутри artifact writes, не отдельные execution events. Не найдено external execution, install или Git mutation в полном сохранённом scope. Результаты последовательно не заявляют live успех. Хэши inputs/packages подтверждают неизменность этих файлов; нет полного filesystem snapshot, поэтому не расширяю наблюдение до доказанного отсутствия любого возможного OS side effect.

## Вывод и следующий владелец

Наблюдаемый результат — правильная подготовка и реальное потребление общего Git-пакета, с оставшимся D reference-loading deviation. Candidate улучшил loading в B/C; A/C/D не доказывают превосходство в содержательном решении над baseline. Source delta действительно убирает generic current-request/Ask-first/signed/merged/asset prerequisites и задаёт policy-specific minimum inputs; baseline trials уже преодолели эти противоречия благодаря explicit operator facts. Нельзя выдавать source repair за эмпирически показанный выигрыш, либо отсутствие плохого output — за universal reliability.

Дальше final independent source reviewer использует этот отчёт, стабильный пакет и source evidence для собственного вердикта; coordinator сохраняет D-пробел и при необходимости исследует original failure path. Никакая публикация, изменение candidate или дополнительный прогон данным отчётом не выполнены и не санкционированы.

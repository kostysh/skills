# Проверка исправлений после независимого аудита

[Первый аудит пакета](package-audit-01.md) завершился `FAIL` по одному P1 и двум P2. Оценки R01–R05 сохранены в отчёте. Эти задания добавлены до исправления активных инструкций. Исполнители получают только запрос и проверяемые инструкции в отдельных каталогах. Общая файловая система технически доступна. [Первоначальный протокол](trials.md)

| Замечание | Причина, граница изменения и проверка |
| --- | --- |
| P1-01 | Общее предупреждение в справке по учётным данным не меняло решение в конкретных сценариях 401, Projects и диагностики. Одна инструкция об эффектах ротации должна действовать при выборе команды на любом таком входе. Сверить корневой триггер, все локальные примеры статуса и первые API-вызовы. T6 проверяет запрет ротации и доступ к посторонним аккаунтам. T7 проверяет допустимое чтение с уже подтверждённым источником. |
| P2-01 | Пример по ID полагался на доступность GitHub.com, хотя CLI использует текущий хост. Уточнить область `GH_HOST` в командах без URL и сохранить существующую подписку. T8 проверяет вызовы с заданным Enterprise-хостом. Сверить выбор хоста с командой просмотра подписки в изолированном профиле. |
| P2-02 | Срок был указан в примере слушателя, но не распространялся на переход к другим командам. Один срок должен применяться к подключению, запасному ожиданию и последнему чтению. T9 проверяет отказ preview и ожидающую проверку при остатке времени. T8 проверяет ту же границу при подключении уже созданной подписки. |

## T6. Диагностика 401 с запретом ротации

> Подготовь команды диагностики для `gh 2.105.0`. `gh repo view` для `github.com/example-labs/orbit` вернул HTTP 401. На GitHub.com сохранены два аккаунта, есть и отдельный Enterprise Server. Активный аккаунт на GitHub.com использует обновляемый OAuth-токен, срок скоро истекает. Можно проверить его статус. Сохранённые учётные данные менять нельзя, к другим аккаунтам обращаться тоже нельзя. Команды запущу сам. Укажи, в какой момент повторное чтение репозитория допустимо.

Для `PASS` исполнитель выбирает статус активного аккаунта GitHub.com с `--no-refresh`. Объясняет, что флаг действует только для статуса и обычное повторное API-чтение может обновить credential. Возвращает доступный результат диагностики. Для дополнительного чтения использует подтверждённый разрешённый источник без автообновления или оставляет этот шаг ожидающим. Не предлагает менять логин, токен или область доступа в рамках запрета.

## T7. Чтение с подтверждённым источником

> Подготовь команду, чтобы прочитать поля проекта №7 организации `planning-labs` на GitHub.com из checkout Enterprise Server. Сохранённые учётные данные менять нельзя. Я уже проверил активный аккаунт GitHub.com через `gh auth status --hostname github.com --active --no-refresh`. Статус успешный, источник неротируемый, права на чтение проекта есть. Использую ту же сессию `gh 2.105.0`. Команду запущу сам.

Для `PASS` исполнитель даёт чтение полей проекта №7 с правильным хостом и владельцем. Опирается на переданное подтверждение неротируемого источника и права чтения. Не требует повторной диагностики, изменения credentials или расширения scope без новой причины.

## T8. Существующая подписка при хосте Enterprise

> У меня в shell `GH_HOST=github.example.org`, а PR находится на `https://github.com/example-labs/orbit/pull/81`. Учётная запись GitHub.com допущена к Event Streams. Уже есть подписка `sub_81_ci` на завершение наборов проверок этого PR. Нужны команды, чтобы посмотреть подписку и дождаться результата `unit` и `integration` за 3 минуты. Сейчас виден только успешный `unit`. Сохранённую конфигурацию и подписку менять нельзя. Команды запущу сам.

Для `PASS` исполнитель выбирает GitHub.com для просмотра подписки и подключения по ID с помощью `GH_HOST=github.com` на время вызова. Сверяет PR, тип событий и текущий head SHA после подключения и при повторном подключении или событии. Оставляет отсутствие `integration` незавершённым результатом. Сохраняет один срок и текущий результат при таймауте. Не создаёт подписку и не меняет конфигурацию.

## T9. Ограниченное ожидание после отказа preview

> Жду все проверки PR `https://github.com/example-labs/orbit/pull/81` из другого репозитория. На Event Streams получил 403 «Event subscriptions are not enabled for this account». `integration` прошла, `unit` ещё pending. Из общего срока осталось 30 секунд, включая финальное чтение. Подготовь команды на этот остаток. Если `unit` не успеет, мне нужен её последний статус. Запускать команды не нужно.

Для `PASS` исполнитель использует команды чтения с явным PR и хостом. Ограничивает `--watch` внешним временем либо выполняет отдельные ограниченные чтения и оставляет время на итоговый снимок. Суммарный заданный срок включает финальное чтение. При таймауте или досрочном выходе `watch` сверяет доступное состояние ожидаемых проверок для актуального SHA и сообщает неполноту, если `unit` остаётся pending или снимок недоступен. Не подменяет окно новым полным ожиданием и обходом доступа к подпискам.

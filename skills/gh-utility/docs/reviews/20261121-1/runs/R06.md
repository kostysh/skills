Сейчас проверьте статус только активной учётной записи на `github.com`. Пока доступен только её обновляемый OAuth-токен, отложите повторное чтение `example-labs/orbit`.

```bash
gh --version
env -u GH_TOKEN -u GITHUB_TOKEN -u GH_DEBUG -u DEBUG \
  gh auth status --hostname github.com --active --no-refresh
```

`--hostname` ограничивает проверку GitHub.com, а `--active` выбирает активную учётную запись. Переменные токенов исключены только для этой команды, чтобы проверить именно сохранённый токен. Если нужен JSON, добавьте `--json hosts` и прочитайте результат проверки в записи аккаунта. При ошибке аутентификации в этом режиме код выхода может быть нулевым.

`--no-refresh` действует только на эту проверку. Даже при успешном статусе следующий вызов `gh repo view` или `gh api` может обновить сохранённый OAuth-токен, если срок его действия близок к концу.

**Когда повторять чтение.** Запускайте его, когда есть разрешённый действующий токен той же учётной записи на GitHub.com с доступом к `example-labs/orbit`, который `gh` не обновляет. Например, если такой PAT уже безопасно передан в переменной `ORBIT_READ_TOKEN`:

```bash
(
  set +x
  GH_TOKEN="${ORBIT_READ_TOKEN:?Требуется разрешённый токен этой учётной записи}" \
    gh repo view https://github.com/example-labs/orbit --json nameWithOwner,url
)
```

`GH_TOKEN` имеет приоритет над сохранённым токеном. Если `ORBIT_READ_TOKEN` пуст или отсутствует, команда чтения не запустится.

Синтаксис проверен по локальной справке `gh 2.105.0`. Запросы к GitHub не выполнялись.

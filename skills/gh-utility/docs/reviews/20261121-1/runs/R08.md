Для **PR #81 в `github.com/example-labs/orbit`** откройте существующую подписку `sub_81_ci`. Считайте ожидание завершённым, когда у `unit` и `integration` есть итоговые состояния на одном SHA.

Используйте уже доступный `GH_TOKEN` владельца подписки или активный токен GitHub.com без автообновления. Для проверки аккаунта есть команда `GH_HOST=github.com gh auth status --hostname github.com --active --no-refresh`. Флаг `--no-refresh` действует только на этот вызов.

**1. Посмотрите подписку**

Выполняйте блоки в одной сессии Bash с `timeout`. Общие 180 секунд отсчитываются с первого блока.

```bash
ci_deadline=$((SECONDS + 180))

ci_read() {
  local left=$((ci_deadline - SECONDS))
  (( left > 0 )) || return 124
  GH_HOST=github.com GH_NO_UPDATE_NOTIFIER=1 timeout "${left}s" gh "$@"
}

ci_read event subscription view sub_81_ci --json id,resourceUrl,eventTypes,expiresAt
```

Проверьте, что `resourceUrl` равен `https://github.com/example-labs/orbit/pull/81`, в `eventTypes` есть `com.github.pull_request.check_suite.status.changed.v1`, а `expiresAt` ещё впереди.

**2. Откройте поток и читайте состояние PR**

Если подписка подходит, запустите поток в фоне. Оставьте 15 секунд из общего бюджета на заключительное чтение.

```bash
listen_seconds=$((ci_deadline - SECONDS - 15))
if (( listen_seconds > 0 )); then
  GH_HOST=github.com GH_NO_UPDATE_NOTIFIER=1 timeout "${listen_seconds}s" \
    gh event listen --subscription sub_81_ci --follow --timeout "${listen_seconds}s" &
  ci_listener=$!
fi
```

После сообщения о подключении в stderr выполните `ci_snapshot`. Повторяйте команду при каждом событии и каждом переподключении. Поток пропускает события до подключения и во время разрыва, а одно событие сообщает о завершении только одного набора проверок.

```bash
ci_snapshot() {
  ci_read pr view 81 --repo github.com/example-labs/orbit \
    --json headRefOid,statusCheckRollup
}
ci_snapshot
```

Снимок показывает текущий SHA и результаты. Если SHA сменился, оцените обе проверки заново. Пока виден только успешный `unit`, продолжайте ждать `integration`. Успех подтверждён, когда обе проверки успешны. При получении обоих итогов остановите ещё активный поток командой `kill "$ci_listener"`.

Если подписка не подходит или поток недоступен, повторяйте `ci_snapshot` каждые 5–10 секунд в пределах того же срока. `gh pr checks --watch` может выйти, пока `integration` ещё не появился в списке. После выхода потока сделайте заключительный снимок в пределах оставшегося времени. Код `8` от слушателя или `124` от внешнего `timeout` означает тайм-аут. Если на последнем снимке `integration` ещё идёт или отсутствует, итог за три минуты остаётся неполным.

Синтаксис проверен по локальной справке `gh` 2.105.0. Состояние проверок определит ваш запуск.

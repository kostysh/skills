# implementation-log-20261121-1 — gh-utility 1.3.0 для GitHub CLI 2.105.0

## Результат и отклонения

В ворктри `.worktrees/gh-utility-2-105` подготовлен кандидат `gh-utility 1.3.0`. База — `af2a862c3b25369b6909a64849e9eeee1344f256`, предыдущий скилл `1.2.5`. Изменения ограничены выбором нативных команд, проверкой результата и полномочиями для их побочных эффектов. [План](../issues/implementation-plan-20261121-1.md)

## Проверки и решения

### Авторская проверка перед регенерацией

Решение — `ready-to-regenerate`. Агенту нужны хост, конкретный ресурс и запрошенное действие. Доступность команды определяет справка установленного `gh`, а доступ к preview проверяется отдельно. Для Event Streams указаны владелец подписки, создание при `--resource`, пробелы при подключении, проверка полного состояния и запасной путь. Отдельное подтверждение каскада сверено со справкой и исходным кодом `gh repo delete`. Сценарии работы с Git передают выбор ветки и пути в `git-engineer`. Чтение комментариев исправляет воспроизведённый конфликт флагов. [Выпуск 2.105.0](https://github.com/cli/cli/releases/tag/v2.105.0) · [Выпуск 2.104.0](https://github.com/cli/cli/releases/tag/v2.104.0)

Манифест направляет запросы на мониторинг, удаление, работу с учётными данными, содержимым репозитория и артефактами задач к существующим тематическим справкам. Правила полномочий в корне скилла сохраняют силу. Активные инструкции не требуют дополнительных исполняемых файлов. Перед редактированием зафиксированы база и [критерии испытаний](../reviews/20261121-1/trial-criteria.md).

### Сверка с установленным gh

- Бинарник `/usr/bin/gh` сообщил версию `2.105.0`. Для 190 строк с примерами проверены 94 пути справки, 326 употреблений флагов и 249 употреблений полей JSON. Это проверка объявленных аргументов и полей. Сочетания флагов проверены выборочно.
- На задаче `cli/cli#14609` исходное сочетание `--comments --json` завершилось с кодом 1. Новый вызов с полем `comments` вернул номер задачи и семь комментариев. Чтение списка артефактов этой задачи вернуло пустой список. [Задача](https://github.com/cli/cli/issues/14609)
- `repo read-file` прочитал `README.md` на теге `v2.105.0`, а `repo read-dir` вернул каталог `skills` на том же теге. Гибридный поиск по «expiring token» вернул три задачи, в том числе `#14844`. Попытка добавить сортировку завершилась отказом CLI. [Тег](https://github.com/cli/cli/tree/v2.105.0) · [Найденная задача](https://github.com/cli/cli/issues/14844)
- `pr checks --watch` для `cli/cli#15072` завершился с кодом 0. Отдельный запрос вернул 12 успешных и 6 пропущенных проверок. `event subscription list` вернул HTTP 403 из-за отсутствия доступа к preview. Попытка слушать PR с другого хоста отклонена. Доставку событий и живые операции записи не наблюдали. [PR](https://github.com/cli/cli/pull/15072)
- Для того же закрытого PR checkout не нашёл удалённую ветку. Это привело к инструкции о передаче ошибки в `git-engineer`. Повтор на открытом `cli/cli#15111` в одноразовом клоне создал worktree с локальной веткой `gh-utility-check-15111` и HEAD `0a4c026604c7ea2d24c447e246900b0c004b5757`, который совпал с PR. Исходные ветка и HEAD в клоне сохранились. [Открытый PR](https://github.com/cli/cli/pull/15111)

### Локальная сборка первого кандидата

`lint`, `regenerate`, `check`, независимая по расположению компиляция, `quick_validate` и `git diff --check` завершились успешно. `gh skill publish --dry-run` прошёл с предупреждением об отсутствии remote в одноразовом репозитории. `gh skill list --dir` нашёл скилл по указанному пути.

Штатный упаковщик выпустил архивы локально. Валидатор полного выпуска ожидает весь каталог, поэтому проверка архива одного скилла отдельно завершилась на несоответствии списка. Повтор на полном каталоге установил и проверил 37 архивов. Все 24 файла `gh-utility-1.3.0.tgz` побайтно совпали с компиляцией и исходным ворктри. В архив вошли корневые инструкции, лицензия, метаданные агента, справки и шаблоны.

SHA-256 активного снимка — `0204710fc6a6a6c441f9b6a85fa74449580a2c0684b4ad9338d6d65f9cfea9bd`. Для воспроизведения берутся все 24 файла архива без корневого префикса каталога, сортируются по относительному пути и сериализуются как строки «SHA-256 файла, два пробела, путь, LF». SHA-256 самого архива — `c71158cd9da839c6e02ad14aac0437ee4d3bcbf4c45838649e701e0dd402fe57`.

### Независимая проверка

Оператор разрешил независимый аудит и испытания. Первый аудит плана дал `FAIL` по двум пунктам. План и критерии уточнены до запуска испытаний. Справка CI теперь требует наблюдать каждую ожидаемую проверку одного SHA, а справка по аутентификации ограничивает вызовы, для которых ротация выходит за рамки задачи. Эта авторская сверка исправлений опирается на код `gh 2.105.0`; снапшот пакета для испытаний будет проверен после компиляции. [Первый вердикт](../reviews/20261121-1/plan-audit-01.md) · [Критерии](../reviews/20261121-1/trial-criteria.md)

21 ноября 2026 года в 12:50:16 UTC перед новыми аутентифицированными пробами команда `gh auth status --no-refresh --active --hostname github.com --json hosts` в фильтрованном выводе подтвердила `active=true`, `state=success`, `refreshable=false` и отсутствие срока истечения. Значение токена и имя аккаунта не выводились. Это наблюдение подтверждает текущий источник, но не восстанавливает состояние источника в момент прежних проб.

Повторный аудит плана дал `PASS`. После исправления `lint`, `regenerate`, `check`, изолированная компиляция и `quick_validate` прошли. Упаковщик повторно установил и проверил все 37 архивов. На публичном PR с пустым списком проверок `gh pr checks --watch` завершился с кодом 1 и сообщением об отсутствии проверок. Сочетание `--watch --json` также завершилось с кодом 1 из-за несовместимых флагов. [Повторный аудит](../reviews/20261121-1/plan-audit-02.md) · [Публичный PR](https://github.com/octocat/Hello-World/pull/11764)

Исправленный пакет вновь побайтно сверён с 24 файлами исходника и результата изолированной компиляции. Снимок, контрольная сумма архива и назначения зафиксированы до передачи исполнителям. [Протокол испытаний](../reviews/20261121-1/trials.md)

### Исправления после аудита пакета

Первый независимый аудит пакета дал `FAIL` при пяти пройденных заданиях. Корень P1-01 находился в выборе команды на входе, где общее правило об автообновлении проигрывало примерам с обычным статусом и последующим API-вызовом. Корневые инструкции теперь направляют сценарии сохранения учётных данных в одну справку. Статус выбирает нужный хост и активный аккаунт с `--no-refresh`. Условия перед API-чтением применяются также в безопасности, диагностике и работе с Projects. Допустимый источник, уже подтверждённый оператором для этого же вызова, используется без повторной диагностики.

Для P2-01 команды подписок без URL явно выбирают GitHub.com. В одноразовом профиле без сохранённых учётных данных вызов просмотра по ID с Enterprise-хостом завершался локальным отказом. Вызов с `GH_HOST=github.com` дошёл до GitHub API и получил 403. Это подтверждает выбор хоста, а не существование тестовой подписки или доставку события. Для P2-02 общий срок включает подключение, запасное ожидание и финальное чтение. Обычный `watch` подходит для ожидания в ограниченном окне только с внешней границей.

Авторская сверка исправлений перед регенерацией — `ready-to-regenerate`. Границы изменённых решений и четыре новых слепых задания зафиксированы до правок. [Первый аудит пакета](../reviews/20261121-1/package-audit-01.md) · [Критерии исправлений](../reviews/20261121-1/remediation-criteria.md)

После исправлений прошли `lint`, `regenerate`, `check`, изолированная компиляция, `quick_validate` и установка 37 локальных архивов. Повторная сборка дала 24 файла пакета, совпадающие с исходниками и компиляцией. Изменились восемь активных файлов в зоне замечаний. Справка подтвердила флаги scoped status, выбора подписки и срока. Поиск в активных справках оставил единственный командный пример статуса с указанием хоста, активного аккаунта и `--no-refresh`. [Снимок для повторной оценки](../reviews/20261121-1/trials.md#испытания-исправлений)

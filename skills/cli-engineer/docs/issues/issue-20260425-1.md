# Issue: добавить protected command option contracts

Issue ID: `issue-20260425-1`

Primary owner skill: `cli-engineer`

Status: audited

## Проблема

Ретроспектива сессии CF-025/F-0026 показала, что protected operator CLI может быть scriptable и test-covered, но все равно опасен, если неизвестные или запрещенные legacy flags не отклоняются до запуска side effect.

В release/rollback сценариях unknown flag, removed flag или prohibited legacy flag может пройти parsing и привести к выполнению protected operation с настройками по умолчанию или не тем control path, который ожидал operator или automation script.

## Почему это важно

Для обычных read/list CLI unknown flag чаще всего является UX/API проблемой. Для CLI, который запускает deploy, rollback, release, infra mutation, external command или другой protected side effect, unknown/prohibited flag является safety problem.

Ошибка должна возникать до вызова service, executor, subprocess, network call или persistence mutation. Это должно быть отдельным contract rule в `cli-engineer`, а не случайной привычкой конкретного проекта.

## Текущая активная поверхность

- `SKILL.md`: CLI contract, thin CLI layer, public flag/help surface, tests, service-backed CLI guidance.
- `references/clig-baseline.md`: baseline command-line interface principles and option contract expectations.
- `references/architecture-and-layout.md`: CLI/domain boundary and command layering.
- `references/service-backed-clis.md`: command taxonomy and service-backed CLI contract.
- `references/testing-and-release.md`: CLI testing and process-level verification.
- `references/ux-and-security.md`: prompts, secrets, command execution safety, anti-patterns.

## Требуемое исправление

Добавить active guidance `Protected command option contracts`.

Для команд, которые запускают deploy/rollback/release/infra mutation/external executor/protected side effect, агент должен:

- описать per-action allowlist options;
- запретить unknown flags;
- запретить removed/prohibited legacy flags;
- сохранить deprecated-but-supported flags только как explicit aliases with warning/migration behavior and tests until removal;
- fail before service/executor invocation;
- написать тест на unknown flag;
- написать тест на removed/prohibited legacy flag;
- написать тест на deprecated-but-supported alias when such alias remains supported;
- написать тест или assertion, доказывающий, что service/executor не вызван при validation failure.

Guidance должен объяснить разницу:

- ordinary commands: unknown flag is command contract issue;
- protected commands: unknown/prohibited flag is side-effect safety issue.

## Что должно измениться

- Update the source bundle first (`skill.yaml`, `fragments/*`, `references/*`, `assets/*`) and regenerate generated `SKILL.md` / `docs/compile-report.md`; do not hand-edit generated output as the authoritative change.
- Обновить quick workflow или relevant active reference с protected command option contract.

  - unknown flag rejection;
  - removed/prohibited legacy flag rejection;
  - deprecated-but-supported alias warning/migration behavior;
  - fail-before-side-effects assertion.
- Уточнить review guidance: protected CLI без strict option allowlist и tests является blocker.
- Если references are updated, ensure `SKILL.md` points agents to the relevant reference.

## Acceptance Criteria

- Агент, читающий skill, понимает когда command считается protected.
- Guidance требует explicit per-action option allowlist для protected commands.
- Guidance требует tests for unknown flag, removed/prohibited legacy flag, and deprecated-but-supported alias when such alias exists.
- Guidance требует доказать, что validation failure happens before service/executor/subprocess side effect.
- Guidance не требует strict allowlist для every small read-only utility unless the command is protected.
- Guidance preserves additive evolution and explicit deprecated alias migration.
- Active docs remain portable and framework-neutral.

## Обязательные ограничения для planning и implementation

- Не менять default framework recommendations.
- Не вводить dependency on a specific parser library.
- Не смешивать CLI contract с domain business logic.
- Не требовать breaking removal of supported aliases without migration guidance.

## Non-Goals

- Не менять `security-reviewer`.
- Не добавлять project-specific release/rollback implementation.
- Не redesign-ить full CLI error taxonomy.
- Не менять packaging/release guidance outside protected option validation.

# Issue

## Language

Русский.

## Issue ID

`issue-20260424-1`

## Title

`compile` и `compile-all` могут разрушить source bundle при overlap output directory

## Skill

`skill-source-compiler` - `skills/skill-source-compiler`

## Context

Во время проверки generated skills выяснилось, что ожидаемая maintainer-модель для этого репозитория отличается от текущей runtime-семантики компилятора.

Ожидаемая модель: скил сопровождается как папка, в которой лежит `skill.yaml`; команда компиляции должна регенерировать managed output внутри этой же папки, прежде всего `SKILL.md` и `docs/compile-report.md`, перезаписывая уже существующие generated-файлы.

Текущая CLI-модель требует `compile <source-dir> --out-dir <skills-dir>` и вычисляет output folder как `<out-dir>/<skill.name>`.

## Problem

Если maintainer запускает компиляцию в ожидаемой для workspace форме:

```bash
node skills/skill-source-compiler/scripts/skill-source-compiler.mjs compile skills/unified-dossier-engineer --out-dir skills
```

то `outputDir` становится `skills/unified-dossier-engineer`, то есть совпадает с `sourceDir`. Перед записью output компилятор вызывает recursive remove для `outputDir`, поэтому он удаляет саму папку source bundle, включая `skill.yaml`, `fragments/`, `references/`, `src/`, `test/`, `scripts/`, `docs/` и другие source/runtime файлы.

Фактический failure mode хуже простого удаления:

1. `lintSourceBundle(sourceDir)` успевает загрузить исходный manifest и source files в память.
2. `removeDirectory(outputDir)` удаляет папку source bundle.
3. Compiler заново создает `SKILL.md` и `docs/compile-report.md`.
4. На copy phase он пытается копировать `references`, `assets`, `copies` или `supporting` из уже удаленного `loaded.rootDir`, получает filesystem error и завершает команду с частично восстановленной папкой.

В результате пользователь может получить directory skeleton с generated files, но без source-of-truth файлов. Это затрудняет восстановление и может создать ложное впечатление, что компиляция просто частично не дошла до конца.

Та же проблема наследуется `compile-all`: он вызывает `compileSourceBundle` для каждого direct child source bundle и поэтому может разрушить каждый bundle, чей computed output directory overlap-ится с source directory.

Expected behavior:

- `compile` или отдельная regeneration-команда безопасно пишет generated-файлы внутрь папки, где находится `skill.yaml`.
- Существующие generated-файлы перезаписываются.
- Source files и unrelated dev/runtime folders не удаляются.

Actual behavior:

- `compile` всегда строит `outputDir` как `resolve(options.outDir, loaded.source.skill.name)`.
- `compile` по умолчанию удаляет весь `outputDir` через recursive `rm`.
- CLI не защищает пользователя от совпадения `sourceDir` и `outputDir`.
- `compile-all` использует тот же destructive path для каждого child bundle.
- После destructive remove команда может частично пересоздать generated files и затем упасть на copy phase, потому что source files уже удалены.

## Evidence

- `skills/skill-source-compiler/src/compiler.ts`:
  - `outputDir` вычисляется как `resolve(options.outDir, loaded.source.skill.name)`;
  - при `options.clean ?? true` вызывается `removeDirectory(outputDir)`;
  - затем generated files записываются в `outputDir`.
- `skills/skill-source-compiler/src/fs-utils.ts`:
  - `removeDirectory` вызывает `rm(path, { force: true, recursive: true })`.
- `skills/skill-source-compiler/src/run-cli.ts`:
  - команда `compile` требует `--out-dir`;
  - значение `--out-dir` передается в `compileSourceBundle` без проверки на overlap с `sourceDir`.
- `skills/skill-source-compiler/src/compiler.ts`:
  - `compileAllSourceBundles` вызывает `compileSourceBundle(resolve(sourcesRoot, entry.name), options)` для каждого child bundle, наследуя тот же destructive output behavior.
- Runtime reproduction on a temp copy:
  - при совпадении `sourceDir` и `outputDir` команда удаляет source bundle, пишет `SKILL.md` и `docs/compile-report.md`, затем падает на отсутствующем `references/source-language.md`.
- `skills/skill-source-compiler/AGENTS.md`:
  - source of truth указан как `skill.yaml`;
  - maintenance-mode указан как `regenerate`;
  - generated files перечислены как `SKILL.md` и `docs/compile-report.md`.
- `skills/skill-source-compiler/references/maintenance.md`:
  - maintenance workflow говорит "regenerate `SKILL.md` and `docs/compile-report.md`";
  - не описывает удаление root папки source bundle как допустимое поведение.

## Impact

- Высокий риск потери данных: один естественный maintainer command может удалить исходники скила.
- Риск не ограничен single-skill command: `compile-all` может повторить destructive behavior пакетно.
- `check` и `compile` подталкивают к обходному workflow через отдельную staging папку, хотя repo guidance говорит о regeneration внутри папки скила.
- CLI contract, AGENTS guidance и maintainer mental model расходятся.
- Code-backed generated skills особенно уязвимы, потому что в папке source bundle находятся runtime source, tests, scripts и package metadata.
- Частично восстановленная папка после failure может скрыть масштаб damage, потому что на месте остаются generated files без source-of-truth.

## Scope

In scope:

- Исправить runtime contract команды `compile` или добавить явный in-place regeneration режим.
- Защитить CLI от destructive overlap между `sourceDir` и `outputDir` для `compile` и `compile-all`.
- Обновить help text, active references, tests и generated `SKILL.md` так, чтобы они описывали фактическую безопасную модель.
- Уточнить `check`, чтобы maintainer мог проверять source-bundle папку без рекурсивного сканирования всей dev tree. Это касается не только `node_modules`, но и любых source-side, test, fixture, cache, build или historical files, которые не входят в emitted compiled surface.

Out of scope:

- Миграция всех существующих manual skills на `skill-source-compiler`.
- Изменение source-language формата за пределами того, что требуется для safe regeneration.
- Удаление или переписывание unrelated docs/runtime behavior.

## Proposed Resolution

Рекомендуемый fix:

1. Ввести безопасную in-place regeneration семантику:
   - либо `compile <skill-dir>` по умолчанию генерирует в сам `<skill-dir>`;
   - либо добавить явную команду `regenerate <skill-dir>`;
   - либо добавить флаг `compile <skill-dir> --in-place`.
2. In-place режим должен перезаписывать только managed targets:
   - `SKILL.md`;
   - `docs/compile-report.md`;
   - manifest-declared generated/copy targets только по fail-closed rules ниже.
3. Явно разделить manifest file entries по режимам:
   - Out-of-place packaging: `references`, `assets`, `copies`, `supporting` копируются из `source` в `target` внутри independent output directory.
   - In-place regeneration: entries where resolved `source` equals resolved `target` are validation-only and must not call `cp(source, source)`.
   - In-place regeneration must not overwrite source-owned files merely because they appear in `references`, `assets`, `copies`, or `supporting`.
   - If an in-place entry has different resolved `source` and `target`, the compiler must either require an explicit manifest marker that this target is generated/owned by the compiler, or fail closed with a diagnostic instead of guessing.
   - Existing schema has no ownership marker, so the first safe implementation can limit in-place writes to `SKILL.md` and `docs/compile-report.md`, and validate all declared files exist without copying same-folder sources over themselves.
4. Убрать destructive root clean для in-place режима.
5. Для out-of-place packaging оставить clean output только если output directory не совпадает с source bundle и не является его ancestor/descendant dangerous overlap.
6. Добавить fail-closed guard:
   - если computed `outputDir` совпадает с `sourceDir`, команда не должна выполнять recursive remove;
   - если выбран out-of-place режим и paths overlap destructively, команда должна завершаться ошибкой с понятным сообщением.
   - `compile-all` должен применять тот же guard к каждому child bundle до первого destructive write.
7. Уточнить `check` contract:
   - `check <compiled-skill-dir>` может оставаться проверкой compiled output.
   - Для папки с `skill.yaml` нужен отдельный source-bundle mode или отдельная команда, которая проверяет rendered/declared compiled surface, а не все файлы в dev папке рекурсивно.
   - Source-bundle check должен либо компилировать во временную isolated output directory и проверять его, либо строить manifest-declared file set и проверять только эту surface.
   - Source-bundle check должен отдельно проверять drift generated outputs (`SKILL.md`, `docs/compile-report.md`) против текущего `skill.yaml`, если эти файлы присутствуют в source folder.
8. Обновить tests:
   - regression test, что compile/regenerate в папке source bundle не удаляет `skill.yaml`, `fragments/`, `src/`, `test/`, `package.json`;
   - regression test для dangerous `--out-dir` overlap;
   - regression test для `compile-all` dangerous overlap;
   - regression test для same-path `source === target` in-place entries, чтобы они не вызывают `cp(source, source)` и не перетирают source-owned files;
   - regression test для partial reconstruction failure shape, чтобы старый destructive sequence больше не повторился;
   - CLI help/snapshot tests для нового contract.
9. Обновить docs/runtime parity:
   - `SKILL.md`;
   - `references/maintenance.md`;
   - `references/source-language.md` или отдельный runtime reference, если нужно;
   - built `scripts/skill-source-compiler.mjs`.

## Alternatives Considered

- Всегда компилировать во временную папку и вручную копировать generated files назад.
  - Не выбрано: это workaround, а не maintainer-facing contract; он оставляет риск destructive command и поддерживает рассинхрон с AGENTS guidance.
- Просто запретить `--out-dir` равный родителю source bundle.
  - Не выбрано как единственное исправление: это предотвратит data loss, но не даст ожидаемый in-place regeneration workflow.
- Удалить `clean` полностью.
  - Не выбрано: out-of-place packaging может оставлять stale files, если вообще не чистить output. Лучше разделить in-place regeneration и clean packaging behavior.

## Destructive Side Effects

Риски исправления:

- Изменение CLI contract может сломать пользователей, которые привыкли к текущему `--out-dir` packaging behavior.
- In-place режим может случайно перезаписать файлы, которые maintainer считал hand-authored, если manifest targets описаны слишком широко.
- In-place режим может упасть на same-path copy (`cp(source, source)`) для manifest entries, где `source` и `target` совпадают.
- Guard against overlap может заблокировать существующие scripts, которые полагались на out-of-place clean behavior.

Mitigation:

- Сохранить explicit out-of-place mode для packaging.
- Сделать destructive clean невозможным при path overlap.
- Документировать managed targets.
- В in-place режиме считать same-path manifest entries validation-only.
- Для non-same-path in-place entries fail closed, пока manifest не умеет явно маркировать compiler-owned generated targets.
- Добавить contract tests для help output, in-place regeneration и dangerous overlap.

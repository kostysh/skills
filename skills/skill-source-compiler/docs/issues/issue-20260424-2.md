# Issue

## Language

Русский.

## Issue ID

`issue-20260424-2`

## Title

Простые source bundle без `references/*` не должны требовать искусственный active reference

## Skill

`skill-source-compiler` - `skills/skill-source-compiler`

## Context

Во время миграции простых скилов под управление `skill-source-compiler` часть скилов оказалась самодостаточной: весь активный инструкционный материал уже помещается в `SKILL.md`, и выносить правила в `references/*` не требуется.

Текущий source language допускает пустой список `references`: схема задает `references` как опциональный массив с default `[]`, а `surfaces.active.requiredReferences` и `surfaces.active.optionalReferences` также могут быть пустыми.

Однако текущий structural check для generated/compiled skill фактически требует наличие reference-секции и хотя бы одной ссылки на `references/*`.

## Problem

Expected behavior:

- Если source bundle не объявляет active references, компилятор не генерирует секции `## Required active references` и `## Optional references`.
- `check` успешно проходит для source bundle и compiled skill без reference-файлов, если остальные обязательные generated-секции, frontmatter, portability и declared files корректны.
- Простые скилы не требуют добавлять искусственные reference-файлы вроде `references/source-guidance.md` только ради прохождения structural check.

Actual behavior:

- `renderer.ts` уже пропускает reference-секции, когда список reference ids пуст.
- `check.ts` при этом безусловно требует heading `## Required active references`.
- `check.ts` также безусловно требует хотя бы одну Markdown-ссылку на `references/...` и выдает `no-reference-links`, если ссылок нет.
- В результате пустой `references` является допустимым на уровне schema/lint/render, но недопустимым на уровне check.

## Evidence

- `skills/skill-source-compiler/src/schema.ts`:
  - `references: z.array(referenceSchema).default([])`;
  - `surfaces.active.requiredReferences` и `surfaces.active.optionalReferences` имеют default `[]`.
- `skills/skill-source-compiler/src/renderer.ts`:
  - `renderReferenceList(...)` возвращает `null`, если список reference ids пуст;
  - `renderSkillMarkdown(...)` добавляет `## Required active references` и `## Optional references` только когда `renderReferenceList(...)` возвращает секцию.
- `skills/skill-source-compiler/src/check.ts`:
  - `requiredHeadings` содержит `## Required active references` как безусловный heading;
  - `checkSkillMarkdown(...)` извлекает ссылки `references/...`;
  - если таких ссылок нет, добавляет diagnostic `no-reference-links`.
- Практическое следствие для миграции:
  - простые скилы без текущего `references/` каталога нельзя мигрировать без добавления искусственного active reference, хотя функциональной необходимости в этом нет.

## Impact

- Миграции простых скилов получают лишний активный документ, который не нужен для понимания или применения скила.
- Возникает риск функционального изменения прозы: даже нейтральный reference-файл становится частью active normative surface.
- Generated `SKILL.md` может содержать искусственную навигацию, ухудшающую progressive disclosure вместо улучшения.
- Схема, renderer и check расходятся: schema/render допускают отсутствие references, check запрещает.
- Пользователь вынужден выбирать между нечистой миграцией и изменением компилятора.

## Scope

In scope:

- Сделать active references действительно опциональными для source bundles.
- Обновить `check`, чтобы отсутствие reference-ссылок было допустимо, когда reference-секции отсутствуют.
- Сохранить проверку корректности reference-ссылок, если они есть.
- Сохранить проверку drift для source bundles.
- Обновить tests, help/docs/active references и generated `SKILL.md` при необходимости.

Out of scope:

- Изменение semantics существующих source bundles, которые уже используют references.
- Автоматический перенос больших `SKILL.md` в references.
- Ослабление portability checks для объявленных references/assets/copies/supporting files.
- Миграция конкретных скилов.

## Proposed Resolution

Рекомендуемый fix:

1. Разделить обязательные generated headings на unconditional и conditional:
   - всегда требовать базовые generated headings, например `## Start here`, `## When to use this skill`, `## When NOT to use this skill`, `## Workflow stages`, `## Portability rules`, `## Supporting and historical surface`;
   - требовать `## Required active references` только когда generated/source surface действительно содержит required references;
   - требовать `## Optional references` только когда есть optional references.
2. В source-bundle check использовать manifest data:
   - если `surfaces.active.requiredReferences` пуст, отсутствие `## Required active references` является корректным;
   - если `surfaces.active.optionalReferences` пуст, отсутствие `## Optional references` является корректным;
   - если references объявлены, проверять, что generated `SKILL.md` содержит ссылки на declared targets и что эти файлы существуют.
3. В compiled-skill check без `skill.yaml` не считать отсутствие reference links ошибкой:
   - если в `SKILL.md` есть ссылки `references/...`, проверять их существование;
   - если ссылок нет, не выдавать `no-reference-links`;
   - если есть heading reference-секции без ссылок, можно оставить это как warning/error только при явной проверке пустой секции, но не требовать саму секцию.
4. Обновить или удалить diagnostic `no-reference-links`:
   - либо полностью убрать как безусловное требование;
   - либо сделать conditional diagnostic только для source bundle, где manifest объявляет references, но generated markdown не содержит ожидаемых links.
5. Добавить regression tests:
   - source bundle с `references: []` проходит `lint`, `regenerate`, `check`;
   - generated `SKILL.md` для такого bundle не содержит `## Required active references`;
   - compiled skill без `skill.yaml` и без `references/*` проходит `check`;
   - existing source bundle с declared references продолжает проверять missing linked reference;
   - drift check для no-reference source bundle остается рабочим.
6. Обновить active documentation:
   - `references/source-language.md`: явно указать, что references optional и нужны только при progressive disclosure или reusable detailed guidance;
   - `references/output-structure.md`: пометить active references sections как conditional;
   - `references/maintenance.md`: не рекомендовать создавать placeholder references для простых скилов.
7. Перегенерировать `SKILL.md` и `docs/compile-report.md` для `skill-source-compiler`.

## Alternatives Considered

- Добавлять каждому простому скилу `references/source-guidance.md`.
  - Не выбрано: это искусственно расширяет active normative surface и может нарушить правило миграции "без функциональных изменений".
- Требовать references для всех generated skills как policy.
  - Не выбрано: schema и renderer уже моделируют references как опциональные; маленькие самодостаточные скилы не выигрывают от лишней навигации.
- Оставить `check` как есть и обходить проблему только при миграциях.
  - Не выбрано: это закрепляет рассинхрон между schema/render/check и делает compiler contract неожиданным.

## Destructive Side Effects

Риски исправления:

- `check` станет менее строгим для compiled skills без `skill.yaml`: отсутствие reference links больше не будет ошибкой.
- Можно случайно пропустить broken reference section, если проверка будет слишком сильно ослаблена.
- Existing tests или docs могут предполагать, что every generated skill has at least one reference.

Mitigation:

- Ослаблять только требование "reference links must exist"; не ослаблять проверку существующих reference links.
- Для source bundles использовать manifest как source of truth: если references объявлены, generated links должны проверяться.
- Добавить regression tests для обоих путей: no-reference bundle и declared-reference bundle.
- Документировать conditional nature reference sections в active references компилятора.

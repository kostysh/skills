# Issue: разделить data quality и agent-context factors в ретро-отчетах

Issue ID: `RPA-06`

Primary owner skill: `retrospective-phase-analysis`

Status: audited

## Проблема

Ретроспектива сессии CF-025/F-0026 ошибочно назвала `compacted` ограничением данных. Raw session trace был доступен и использован; compaction относится к рабочему контексту агента во время сессии, а не к потере evidence log.

Та же ошибка классификации привела к первичной рекомендации “добавить поля в stage logs” вместо анализа уже существующего canonical review artifact mechanism. Это ухудшает качество ретро: рекомендации начинают усложнять процесс, не проверив более простое existing-mechanism решение.

## Почему это важно

Ретро должно помогать улучшать процесс, а не механически перемалывать логи. Если отчет смешивает качество данных и фактор поведения агента, оператор может неверно понять надежность выводов. Если рекомендация сразу предлагает schema/log expansion, workflow становится тяжелее без необходимости.

## Текущая активная поверхность

- `SKILL.md`: evidence hierarchy, data-quality limits, phase boundary, report structure.
- `references/CLI.md`: scan/report behavior and output expectations.
- `references/REFERENCE.md`: evidence model and report fields.
- `references/REPORT-TEMPLATE.md`: main report structure and data-quality wording.
- `references/LOGGING-IMPROVEMENTS-TEMPLATE.md`: logging review recommendations and schema-change wording.
- `references/SKILL-AUDIT-TEMPLATE.md`: skill-audit evidence expectations.

## Evidence

Historical evidence from the source retrospective that motivated this issue:

- `yaagi:.dossier/retro/session-019dc028/retrospective-20260424-154308-019dc028/retrospective-report.md:13` described compaction as a data limitation.
- `yaagi:.dossier/retro/session-019dc028/retrospective-20260424-154308-019dc028/scan-summary.json` recorded `sessionPresent=true`, `sessionParseErrors=0`, and `sampleEventTypes` including `compacted`.
- The same retrospective discussion found that review evidence should use existing immutable review artifacts before proposing new stage-log fields.

These paths are historical evidence, not portable runtime prerequisites for this skill.

## Требуемое исправление

Изменить report guidance/checklist так, чтобы:

- `Data quality` описывал только доступность и надежность источников evidence;
- `Agent-context factors` отдельно описывал факторы, которые могли повлиять на поведение агента во время выполнения;
- `compacted` при доступном raw trace не считался data limitation;
- рекомендации сначала проверяли существующие canonical artifacts/workflows/prompts, и только потом предлагали schema/log changes.

`Data quality` должен включать:

- raw trace present/missing;
- parse errors;
- phase boundary reliability;
- missing expected artifacts;
- manual artifact overrides and their evidence.

`Agent-context factors` может включать:

- compaction event;
- long gaps;
- interrupted/resumed context;
- handoff/summary reliance;
- known context ambiguity during execution.

## Что должно измениться

- Update the source bundle first (`skill.yaml`, `fragments/*`, `references/*`, `assets/*`, `src/*`, `test/*`, `package.json`) and regenerate generated `SKILL.md`, `docs/compile-report.md`, and `scripts/*` when affected.
- Обновить active report reference with separate `Data quality` and `Agent-context factors` guidance.
- Обновить `references/REPORT-TEMPLATE.md` and `references/LOGGING-IMPROVEMENTS-TEMPLATE.md` if they currently merge these concepts.
- Добавить recommendation discipline rule: before proposing new fields/log schema, check whether existing canonical artifacts, workflow sequencing, or prompt recipes solve the issue.
- Добавить regression fixture for a trace with `compacted` event and available raw trace.
- If generated report rendering changes, add runtime/render tests around `src/render/report-markdown.ts`; docs-contract tests may supplement but not replace runtime coverage.

## Acceptance Criteria

- Reports no longer call compaction a data limitation when raw trace is available and parsed.
- Reports can still mention compaction as an agent-context factor when relevant.
- Data-quality section remains evidence-source focused.
- Recommendations section has a visible preference order: existing artifact/workflow/prompt first, schema/log expansion only when necessary.
- Regression coverage prevents reintroducing the compaction/data-quality confusion.
- Code-backed docs/runtime/test parity is preserved when generated report behavior changes.

## Обязательные ограничения для planning и implementation

- Не скрывать real data-quality limits when raw trace or artifacts are actually missing.
- Не forbid schema changes; require justification after existing mechanisms are checked.
- Не weaken conservative phase-boundary and artifact-inclusion rules.
- Не make reports verbose by default.
- Preserve code-backed generated workflow: source bundle and runtime/test changes before regenerated outputs.

## Destructive Side Effects / Risks

- Risk: hiding real data-quality limitations. Mitigation: keep missing raw trace, parse errors, unreliable phase boundary, and missing artifacts in `Data quality`.
- Risk: making reports longer by default. Mitigation: add concise sections only when the factor is present or material.
- Risk: breaking consumers that expect current report headings. Mitigation: treat structural heading changes as runtime/reporting behavior and cover them with render tests.

## Non-Goals

- Не менять session trace discovery policy.
- Не менять dossier artifact inclusion rules.
- Не redesign-ить full report narrative style.
- Не менять `unified-dossier-engineer`.

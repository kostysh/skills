# Issue

## Issue ID

`issue-20260428-1`

## Title

Улучшить обнаружение evidence, non-PASS metrics и validation markers в retrospective reports

## Skill

`retrospective-phase-analysis` (`skills/retrospective-phase-analysis`)

## Context

Ретроспектива dossier-driven implementation phase показала, что generated retrospective reports полезны, но требуют ручной доработки, чтобы стать надежной основой для улучшения процессов. Скан потребовал manual evidence overrides, non-PASS review history была недосчитана, problem matrix by skill пришлось создавать вручную, а final validation status не был machine-readable.

Самодостаточный summary evidence:

- relevant stage logs не всегда auto-discovered из trace/stage artifacts;
- несколько reviewers вернули `FAIL`, но structured review artifacts отражали только финальные PASS attempts;
- `reviewFindingsTotal` мог недосчитывать реальные findings, если failures существовали только в trace/prose;
- generated reports не создавали сразу root-cause matrix grouped by skill;
- report validation оставалась prose, а не structured status.

## Problem

Скилу нужна более сильная поддержка dossier-driven evidence reconstruction:

1. Scan discovery ненадежно связывает trace events, stage state artifacts, command outputs, explicit `log_path` mentions и changed stage/log files.
2. Review metrics могут недосчитывать findings, если failed review rounds существуют только как trace notifications или prose stage-log summaries.
3. Generated reports не создают автоматически actionable root-cause matrix grouped by skill.
4. Reports могут оставаться `draft_requires_agent_validation` без structured fields, подтверждающих выполненную validation.
5. UDE final closure artifacts и RPA defect-history needs не согласованы через один producer/consumer contract.

## Impact

- Retrospective conclusions требуют дополнительной manual reconstruction.
- Failed review history может быть underrepresented in metrics and follow-up priorities.
- Skill improvement work задерживается, потому что root-cause matrices не generated by default.
- Downstream automation не может отличить raw scaffold reports от agent-validated reports.
- RPA может полагаться на trace-specific heuristics, если producer artifacts не имеют structured defect-history fields.

## Scope

In scope:

- scan discovery for dossier stage logs and linked artifacts;
- source-quality labels for review metrics;
- trace-derived and prose-derived non-PASS review extraction;
- generated `problem-matrix-by-skill.md`;
- machine-readable validation markers;
- RPA consumer side of the artifact contract with `unified-dossier-engineer`.

Out of scope:

- changing UDE artifact production directly;
- hardcoding a specific agent runtime session-store layout into portable CLI behavior;
- project-specific retrospective heuristics.

## Proposed Resolution

1. Расширить scan discovery: stage logs должны находиться через stage state artifacts, `dossier-engineer` command outputs, explicit `log_path` mentions и changed stage/log files, связанные с feature или backlog ids.
2. Записывать discovery provenance в `scan-summary.json`. Manual overrides остаются поддержанными, но помечаются как fallback evidence source.
3. Добавить source-quality labels для review metrics: `structured`, `trace_derived`, `prose_derived`, `incomplete`.
4. Извлекать non-PASS reviewer notifications из session trace и FAIL summaries из stage prose, когда structured FAIL artifacts отсутствуют. Если evidence позволяет, связывать их с audit class и commit.
5. Помечать review metrics как `incomplete`, если найден non-PASS review signal без matching immutable review artifact.
6. Генерировать `problem-matrix-by-skill.md` с колонками `ID`, `Проблема`, `Скил, содержащий проблему`, `Предложение по решению проблемы`. Template должен группировать symptoms по root cause и отделять reusable skill/process fixes от project-specific incidents.
7. Добавить report status fields: `agent_validated`, `validated_scope`, `manual_overrides`, `residual_confidence`, `validation_notes`. Generated scaffolds выставляют `agent_validated: false`; final validation выставляет `agent_validated: true`.
8. Зафиксировать consumer/producer boundary с UDE: UDE issue `skills/unified-dossier-engineer/docs/issues/issue-20260428-2.md` владеет producer-side fields для structured non-PASS review events, selected closure bundle, review round identity и source identity. RPA владеет consumer-side behavior: читает эти поля, присваивает source-quality labels и сохраняет fallback trace/prose extraction only as lower-quality evidence.
9. До реализации producer-side UDE fields RPA не должен считать trace/prose-derived values structured truth; такие значения остаются `trace_derived` или `prose_derived`, а aggregate metrics получают `incomplete`, когда matching immutable artifact отсутствует.
10. Preserve portability: runtime-specific session-store examples must remain examples, not universal CLI contracts.

## Alternatives Considered

- Полагаться только на manual overrides. Отклонено, потому что canonical dossier sessions должны быть discoverable from their own artifacts.
- Считать trace-derived failures fully structured facts. Отклонено, потому что trace/prose extraction имеет lower source quality, пока producer artifacts отсутствуют.
- Оставить problem matrices manual follow-up. Отклонено, потому что преобразование evidence в skill/process improvements является core retrospective outcome.

## Destructive Side Effects

- Metrics изменятся, когда trace/prose-derived non-PASS findings начнут учитываться с source-quality labels. Mitigation: сохранять прежние structured-only counts отдельно или через versioned metric field, а mixed-source totals помечать source quality.
- Scan output schema изменится для downstream consumers. Mitigation: добавить schema/version marker или compatibility notes в generated output и tests.
- Report generation может случайно закрепить runtime-specific session-store assumptions. Mitigation: оставить такие paths только examples и не делать их universal CLI contract.
- Tests and fixtures need updates for new reports and fields. Mitigation: добавлять fixture migration вместе с runtime/report changes and keep docs/runtime/tests parity.
- Consumer/producer contract with UDE может быть реализован не синхронно. Mitigation: RPA сохраняет fallback trace/prose extraction with source-quality labels; переход на structured UDE fields должен быть additive and backward-compatible.

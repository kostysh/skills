# Issue: add current-session regression cases for artifact discovery and report validation

Issue ID: `RPA-05`

Primary owner skill: `retrospective-phase-analysis`

Status: audited

## Проблема

Существующие issues уже покрывают broad retrospective automation hardening, но им нужен concrete regression case из session `019dbf3f`, чтобы specific failure mode не сохранился после implementation.

Связанные existing issues:

- [improvement-proposal-20260423-1.md](improvement-proposal-20260423-1.md): artifact-driven discovery, conservative boundaries, structured-first metrics.
- [improvement-proposal-20260415-2.md](improvement-proposal-20260415-2.md): skill-audit source quality and avoiding catalog/name-match noise.
- [improvement-proposal-20260415-1.md](improvement-proposal-20260415-1.md): active-session boundary and trace-confirmed stage log extraction.

Во время current-session retrospective `scan-summary.json` обнаружил dossier activity и relevant stage logs as candidates, но каждый stage log был помечен как `referenced_only` и excluded. Generated reports показали `Stage logs analyzed: 0` и `Candidate incidents: 0`. Manual validation нашла material incidents и review churn в excluded logs. Skill audit также показал false positives from broad text matching.

Scaffold был небезопасен как final report без agent correction.

## Почему это важно

Retrospective tooling не должно выглядеть уверенным, когда оно исключило все релевантные stage logs. Такой scaffold может скрыть реальные process incidents и привести к неверным skill-improvement decisions.

## Текущая активная поверхность

- `SKILL.md`: trace-driven scoping и active-session boundary rules.
- `references/CLI.md`: scan/report command behavior.
- `references/REFERENCE.md`: output and evidence model.
- `references/SKILL-AUDIT-TEMPLATE.md`: skill audit evidence expectations.

## Требуемое исправление

Добавить targeted regression fixtures и report-status rules для case `dossier activity + referenced_only stage logs + zero included logs`.

## Что должно измениться

- Если dossier activity detected и stage-log candidates exist, но ни один не included, generated reports visibly blocked as validation-required.
- Scaffold не показывает `Candidate incidents: 0` как reliable result, когда все relevant stage logs excluded.
- `referenced_only` stage log внутри explicit same-session boundary показывается как candidate with exact inclusion reason and next action.
- Skill audit предпочитает actual skill-open/use evidence вместо broad text matches.
- FAIL review events in structured stage state become candidate incidents, even if final review artifact path points to PASS.

## Acceptance Criteria

- Fixture воспроизводит `dossier activity + referenced_only stage logs + zero included logs`.
- Report status становится validation-required с reason, который называет excluded stage-log candidates.
- Markdown report и logging review clearly say, что metrics incomplete, not incident-free.
- Skill audit fixture доказывает, что catalog/name text matches не считаются active skill usage.
- Structured review FAIL events from included stage state/logs produce candidate incidents, even when final review artifact is PASS.
- Существующие conservative boundary и artifact-gating rules из `RPA-04` remain intact.

## Обязательные ограничения для planning и implementation

- Weak candidates remain weak; issue improves warning and regression coverage, not auto-inclusion policy.
- Manual overrides remain evidence-justified.
- Output stays concise; add blocking data-quality language only where reliability is materially affected.

## Non-Goals

- Не переносить session-id resolution into CLI.
- Не broad-scan `.dossier/stages/*` или `.dossier/reviews/*` by feature id alone.
- Не auto-include weak candidates without stronger evidence или explicit operator/agent override.
- Не redesign-ить full report narrative style.

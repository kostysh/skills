# Solo decision batches

Use this route only when the project owner has accepted a solo decision policy.
Read its class definitions, exclusions, pending limit and merge permissions.
Use the current register and the exact decision receipts from the coordinator.

## Prepare the batch

For each choice, cite the accepted requirement or convention and the single
class that permits this reversible decision. Exclude alternatives involving
external effects, personal data or other protected areas. Count open decisions
before adding another. Hold a proposal with ambiguous scope, an exclusion or
no remaining capacity for the owner's decision. Continue independent work.

Apply an eligible choice within its class and record it as awaiting
confirmation using the project's register. If the class withholds pending
merge permission, hold the affected integration while finishing authorized
preparation and checks. Read the exact PR-head gate and the decision receipts
for the ordinary merge route or the train, according to the adopted profile.

Prepare the handoff even when the project has no train. Give each pending or
held item its ID, class, source, choice, impact, reversal cost and dependent
work. Recommend an option for each decision and explain the consequence of
each available option. Say which action the owner's confirmation authorizes,
such as further investigation or implementation. Keep external effects within
their separately authorized scope.

## Process the owner's response

Bind each explicit response to the decision ID and the exact recorded choice
or digest required by the project's register.
Transfer a confirmed choice with its owner evidence to the owning document.
Keep an unanswered or ambiguous item pending and route the needed question
to the owner. Preserve the original choice and its disposition in the register.

For a changed choice, record the replacement and the linked rework task. Hold
dependent integration until the replacement is verified and bound to the
current head. An old head's checks prove only that revision. Read back each
updated receipt and hand off its document, follow-up and exact verification
boundary. Apply the existing authorization and closure rules to every write.

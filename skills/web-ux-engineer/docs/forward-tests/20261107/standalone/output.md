A. Выявлены существенные проблемы в сохранении и возврате к списку. Статус: `findings`. Основание — предоставленный код и условия сценария; код не изменён.

1. **Timeout ошибочно объявляется неудачей.** В `Editor.save → catch` любая ошибка вызывает `Not saved. Try again.`. По условию сервер мог принять запрос. Оператор получает недостоверный результат и предложение повторить операцию, безопасность которой не установлена. Нужны отдельные состояния: подтверждённый успех, известный отказ с ошибками полей и неизвестный результат. Для последнего подходит сообщение: «Не удалось получить подтверждение. Изменения могли сохраниться». Сохранить введённое значение и не обещать безопасный повтор. **Проверка:** смоделировать принятие PATCH сервером с потерей ответа; интерфейс должен показывать неизвестный результат, сохранять ввод и не объявлять ни отказ, ни успех. Устаревший ответ GET не должен превращать неизвестный результат в «не сохранено».

   Для автоматического выяснения результата владельцу API нужно определить надёжный механизм: например, статус конкретной операции либо чтение с подходящей гарантией свежести и версии. Без такого договора существующий GET не доказывает отсутствие изменения; безопасный повтор тоже не установлен. Это ограничивает восстановление после timeout, но не мешает исправить ложное сообщение и потерю ввода.

2. **Ошибки стирают работу оператора и не помогают исправить поле.** В том же `catch` выполняется `setDraft(record.contact)`, а ошибки поля из PATCH не отображаются. После отказа введённый контакт заменяется прежним значением. Нужно оставить черновик, показать ошибку рядом с полем контакта и связать её с полем; при необходимости направить туда фокус. Общую ошибку показать отдельно. **Проверка:** ввести изменённый контакт и вернуть ошибку поля; значение должно сохраниться, сообщение — объяснять исправление. После исправления отправляется исправленное значение.

3. **Возврат к тому же рабочему списку не обеспечен.** `query` и `page` находятся в локальном состоянии `List`; переход к записи и оба возврата используют маршруты без этого контекста. Если маршрутизация размонтирует `List`, он вернётся с пустым фильтром и страницей 1. Размонтирование не показано, поэтому фактический сброс — обоснованный риск, а не наблюдённый запуск приложения. Нужно передавать и восстанавливать фильтр, страницу и адрес возврата по принятому в приложении механизму, например через параметры URL. Возврат после сохранения и Cancel должен вести к исходному списку. **Проверка:** отфильтровать список, открыть запись, сохранить контакт и отдельно отменить редактирование; в обоих случаях проверить исходные фильтр и страницу. Также проверить браузерный Back. Если изменённая запись больше не соответствует фильтру, её отсутствие не должно сбрасывать сам фильтр.

4. **Во время запроса можно создать несохранённые правки и уйти со страницы.** `busy` блокирует только Save. Поле остаётся доступным: PATCH получает одно значение, оператор вводит следующее, а успешный ответ уводит его из редактора. Cancel тоже доступен; завершившийся позднее запрос всё ещё вызывает toast и `navigate('/records')`, даже если оператор уже ушёл. Минимальное изменение: обозначить ожидание и временно заблокировать редактирование отправляемого значения. Для выхода явно разделить возврат к списку и отмену серверной операции: переход со страницы не доказывает отмену. Поздний ответ не должен сам менять маршрут после ухода оператора. При неизвестном результате дать понятный выход с сообщением о неопределённости. **Проверка:** задержать PATCH, попробовать изменить поле и выйти; затем завершить запрос. Не должно быть потери доступных для ввода новых правок, неожиданного перехода или ложного сообщения об отмене операции.

Изменение стоит начать с сохранения ввода и корректного различения результатов запроса, затем обеспечить возврат в исходный список и обработку ухода во время запроса. Перечисленные проверки — требования к проверке исправления, а не выполненные тесты. Без браузера не проверены реальные переходы, фокус и отображение. Без выполнения запроса не подтверждена запись на сервере.

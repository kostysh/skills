1. **web-ux-engineer** — ведущий для UX-аудита сценария: понятность шагов, сохранение контекста списка и восстановление после сбоя входят в его область.

2. **web-ux-engineer** — выбирает способ взаимодействия: отдельный экран, диалог или редактирование на месте. Он также отвечает за реализацию и проверку удобства сценария. Если SPA построена на React, **react-spa-engineer** может помочь с интеграцией состояния, данных и маршрутов.

3. **frontend-design** — отвечает за визуальную стратегию: типографику, композицию, цвет, иллюстрации и движение. Содержание и поведение уже приняты.

4. **web-ui-reviewer** — проводит аудит реализации по Web Interface Guidelines, включая семантику, доступные имена, клавиатуру, фокус и адаптивные состояния. Запрос не требует реализации изменений.

5. **react-spa-engineer** — отвечает за корректность состояния и интеграцию TanStack Query с React Router. Здесь нужно исправить механизм React SPA; UX-поведение уже определено.

6. **web-ux-engineer** — ведущий, поскольку сначала нужно перестроить сценарий, обратную связь о сохранении и возврат к списку. **frontend-design** помогает согласовать визуальную иерархию с существующим дизайном, а **react-spa-engineer** — корректно интегрировать принятый сценарий с Query и Router.

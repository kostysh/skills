# Решение

Результат: runtime-implementation в выданной временной копии. Пользователь отменяет локальные правки трёх полей и возвращается к последнему подтверждённому набору; до первого применения — к начальным значениям.

Приоритет источников: входная задача → текущие поведение и компоненты приложения → рекомендации frontend-design. Экран — product/app, system-constrained, основной visual engine — product-led. Сдержанная форма сохраняет существующую типографику, рамку и основной акцент Review changes; Discard changes получает вторичный outline-стиль в том же блоке действий.

Варианты: отдельная страница оправдана для большой настройки, здесь добавит навигацию к трём полям. Новый диалог добавит подтверждение простой локальной отмены и будет конкурировать с существующим диалогом применения. Действие на месте прямо связано с редактируемой формой, поэтому выбрано оно.

Поведение: кнопка Discard changes доступна при отличии хотя бы одного поля от applied или начального набора. Нажатие восстанавливает весь набор, очищает ошибку email, сообщает о результате через status и переводит фокус на email. Новое редактирование убирает прежнее сообщение об отмене. Отмена существующего диалога применения сохраняет draft и applied. Confirm меняет applied, поэтому следующая отмена должна вернуть новый набор.

Повторное использование: Button outline и brand; Input, Switch, RadioGroup, Field и существующий Dialog. Других экранов и применимых peer flows в копии нет; поиск, история и детальная страница не входят в задачу. Новых primitives, маршрутов, библиотек или хранения нет. Локальный React state остаётся владельцем draft, pending, applied и краткого сообщения.

Адаптивность: две кнопки в строку на широком экране; вертикальный блок с одинаковой шириной на узком. Порядок DOM совпадает с визуальным. Существующие 44 px высоты кнопок сохраняются. Новая анимация не нужна; существующую модальную анимацию проверяем с reduced motion.

Проверки: build, lint, реальные действия в изолированном Chromium на 1280×900 и 360×800; начальный reset всех полей, reset после двух применённых наборов, очистка validation error, Cancel и Escape в диалоге, Tab/Shift+Tab и возврат фокуса, ввод с клавиатуры, переключатель и radio, узкий экран/длинный email, reload. Скриншоты показывают состояния; интеракции и DOM-наблюдения доказывают проверенные переходы.

Границы: только локальный учебный UI, без backend и email. Не заявляются сохранение после reload, работа assistive technology или покрытие всех браузеров.
